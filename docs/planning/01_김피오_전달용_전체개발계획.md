# 김피오님 전달용: 《동그란 사이》 전체 개발 계획

작성: 김도현 / 2026-10-12 / v0.1 / 검토 제안. 원본 패키지 0.2를 기준으로 하며 납기·비용·제품 승인을 뜻하지 않는다.

## 1. 완성할 경험과 범위

직접 얼굴을 만든 폰이 생활과 공동 사건을 겪고, 선택이 관계·기억·다음 행동을 바꾸는 경험을 완성한다. 화면, 사건 규칙, 저장, 복구가 한 흐름으로 동작해야 한다.

| 단계 | 결과 | 완료 판단 |
| --- | --- | --- |
| A 관계 시제품 | 얼굴 편집→자기 폰 3명→개인 월드→공방 선택→8축·기억 변화→달라진 행동→복원 | DEV-01~08 및 관련 디자인/관계 검증, 실제 체험 |
| B 소셜 알파 | 계정·영속 저장→친구 초대/방문→광장→사용자 간 공방→지속 관계→동의/차단/신고/재접속 | DEV-09~18, 2계정 이상 종단간 검증, 운영 게이트 |
| C 확장 후보 | 추가 목적 맵·파츠 공유·집단 관계 | 추가 요구별 견적·인수 조건 결정 |

주의: 목적별 맵은 사용자 확정 요구다. 공방 한 곳으로 U-05 전체 완료를 선언하지 않는다. B의 첫 목적 맵을 공방으로 제한하는 것과 여러 목적 맵의 최종 완료는 다르다. B 안에 두 번째 목적 맵을 포함할지, 별도 완료 단계로 둘지 PO 결정이 필요하다. ‘공동 작업/식사’ 같은 맵 후보는 제안이며 선택된 내용이 아니다.

전투·경매·유료 재화 거래·음성/자유 채팅·생성형 대사·자유 맵 제작은 A/B 범위에 넣지 않는다. 로맨스는 연령/허용 정책이 정해질 때까지 데이터 확장 가능성만 예약하고 콘텐츠 구현을 보류한다.

규모는 비교용이며 사람·주 단위 확정 견적이 아니다. 실제 일정은 기준 기기, 디자인 납품 가능일, 엔진 실험, 인력, A 체험 결과, B 동시접속/운영 비용을 확인한 뒤 갱신한다. 최초 출시일까지 고정 주차를 약속하지 않는다.

개발 진행의 긴 경로는 G0→G1→G3→G4→G5→G6→G7이다. G2의 화면/자산 검토는 G1과 독립적으로 진행할 수 있다. 이는 작업 의존성의 분리이며 별도 에이전트나 인력을 자동 배정한다는 뜻이 아니다.

## 3. 기술과 서버 운영 방향

개발 검토 기본안은 PC 브라우저 우선, TypeScript+React UI+Vite 빌드, Phaser 월드 렌더러 후보다. G0에서 파츠 합성·입력·UI 중첩·성능 실험으로 엔진을 선택하며 복수 엔진을 혼용하지 않는다. 모바일 지원은 포인터 입력·반응형 구조를 예약하되 지원 완료로 선언하지 않는다.

Vite는 React/TypeScript 템플릿을 제공하므로 시작 기반으로 검토한다. [공식 안내](https://vite.dev/guide/). Phaser는 웹용 2D 게임 프레임워크 후보이며 선택은 실험 후 기록한다. [공식 소개](https://docs.phaser.io/phaser/getting-started/what-is-phaser).

Supabase는 사용자가 선택한 프로젝트를 사용한다. A는 단일 사용자 로컬 권위자로 관계 규칙을 검증할 수 있지만 외부 공개/공유 데이터의 판정을 맡기지 않는다. B는 인증된 서버 명령 처리와 원자적 DB 확정을 필수로 한다. 같은 순수 로직/계약을 재사용하고 저장 어댑터를 교체한다.

Edge Function은 명령 API 후보이며 상시 시뮬레이션 서버로 가정하지 않는다. [공식 안내](https://supabase.com/docs/guides/functions). DB에 여러 HTTP 쓰기를 보내는 것만으로 원자성을 보장하지 않는다. G5에서 트랜잭션 실행 경로를 실험해 확정한다. 공방/광장에 상시 권위 서버가 필요한지는 G6 부하 실험으로 판단하고 필요하면 비용 비교안을 낸다. Realtime은 판정 근거가 아닌 전달 계층이다.

호스팅은 미결이다. 정적 배포와 비밀 처리 서버를 구분하며 GitHub Pages 등 후보의 보안 헤더·직접 링크·하위 경로·로그 정책을 검토한다. 공개 배포는 현 계획 작성과 별개다.

## 5. 협업과 디자인 수령

김도현은 데이터/명령/상태 fixture와 런타임 제한을 제공하고, 김디자인은 화면·자산·피드백을 제공한다. 먼저 WP-01~03(SCR-01/04/06/07)을 검토하고 월드·생활을 연결한다. B 화면은 G5 계약부터 상세화한다. 디자인 파일이 도착하면 파일 목록/버전→화면·상태 비교→자산 검사→실제 크기 검토→통합 순서로 처리한다.

규칙 변경은 CR-ID로 DEC-01~12·U-ID·SCR-ID·테스트·저장 영향까지 기록한다. 관계 의미는 정연우 자문 검토, 제품 범위는 PO 판단을 받는다. 현재 문서는 실제 새 협업 회신 없이 작성한 전달용 계획이다.

## 7. 납품과 완료 보고

소스/실행 빌드/설치 안내, 데이터·명령 스키마, 자산 manifest, 사건·규칙 버전, 테스트 결과, 마이그레이션/복구/운영 문서, 알려진 문제를 함께 납품한다. 게임 복사 위치는 C:\code\game이며 원본 저장소는 보존한다. 복사는 승인된 범위 안에서 수행하고 시크릿·의존성 캐시를 제외한다.

각 게이트 보고: 플레이 가능한 흐름 → 변경 이유 → 실제 검사 증거 → 미완료/결정 항목. A 완료, B 완료, 확정 요구 전체 완료, 공개 출시를 각각 구분한다.
