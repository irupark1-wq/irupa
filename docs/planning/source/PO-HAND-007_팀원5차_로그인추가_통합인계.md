## 1. 다음 버전 범위와 우선순위

구글/이메일 로그인은 최신 사용자 요구로 추가한다. PO-AUTH-001에 따라 B-ACCOUNT를 다음 개발로 앞당긴다. 데이터 보존/계정 격리·인증/저장의 구분을 먼저 구현하고 실제 친구 공존은 별도다. 기존 두 번째 방과 관계 기반 보완도 유지하되 단독개발자의 작업량을 고려해 실제 제작 순서·의존성을 김도현이 회신한다. 전체를 동시에 완료한다고 약속하지 않는다.

로그인 제작의 제품 허가는 이번 요청으로 확보됐다. 운영 provider 설정/공유프로젝트 영향/접근·비용이 필요한 것은 구체목록으로 올린다. 김PO가 로그인 도입 여부를 반복 승인하는 절차는 추가하지 않는다.

## 2. 관계 회신 수용과 실제 갈등 결정

정연우 v1.4의 사실→인지→확인사항→실제대립 구분 및 원인/영향에 맞는 종료조건을 수용한다. 외주6의 Q06 방향은 같은 의미이며 기존 단순누락·미회신벌점0을 유지한다.

**같은 소유자 로컬 폰 사이의 국소 공로기준 분쟁을 다음 시제품 갈등 후보로 채택한다.** 실제 두 폰이 공로표시 기준에 반대입장을 표명한 별도action, 인지·작업/게시참조·한정된impact·scope가 필요하다. 최초 severity250을 QA시험값으로 채택한다. 이는 기준불일치를 랜덤으로 만들거나 ‘C가 B기여사실을 알면서 거짓말함’을 동일사건으로 처리하는 허가가 아니다.

450의 지속/실질피해 분쟁과700의 입증고의독점은 이번 신규생활범위에서 보류한다. 최초250에서자동시간경과/같은source재전송으로승격하지 않는다. 다른활성갈등을함께닫거나태그/친밀을자동부여하지 않는다. 신규EventDefinition/원천/수락키와 실제 후보도달조건은 김시스템·김도현이 작성해 정연우의 정합검수를 받는다. 이 계약을 만족하지 못하면 해당분기 blocked를유지한다.

해결은 그분쟁의resolution_condition_ref에따른 실제원인/영향해소·당사자별인지·필요수용으로판정한다. 정정이유일원인을해결했다면해결가능하며무조건EVT12를추가요구하지않는다. 반대로게시만고쳐도항상해결은아니다. EVT09정정효과와EVT12별도복구효과는동일증거이중사용금지. 최초분쟁에는새감정감점/확률을임의추가하지않는다.

가벼운위임의 사실상태offered/accepted/declined/fulfilled_pending_ack/confirmed/overdue/cancelled 의미를 수용한다. 생활구현과EVT06/07 기여·의무부담은아직확정되지않았으므로무검증큰보상을넣지않는다. 로그인범위가늘어난이번버전에위임전체를필수완성조건으로추가하지않는다.

## 3. 미수령 반복 해소

정연우v1.4와외주6은DEV24/실코드/실측원본미수령을명시한다. 해당원본은이미김PO가읽었고이전패키지에있었다. 이번에도DEV24ZIP을그대로첨부하여정연우/김시스템 검수입력으로전달한다. 이미수신한자료를김도현에게새로만들어달라고요청하지않는다. 현commit과달라졌다면차이만요청한다.

정연우는코드/dialogue.js의실키 credit_ask/credit_ask_accept/credit_ask_pending/credit_fixed/credit_ack와speechTurns호출을각상황에매핑한다. DLG05~08은기획QA ID이며실코드키라고추정하지않는다. 추가호출store/life문맥이필요하면정확한누락부분만김PO에요청한다.

DEV24실측은16run각2000tick, B/default의정정1은4run합계다. Q06실제Conflict는차단상태였으며외주가독립측정한값이아니다. 이미제출된경로의재작성을요구하지않고신규250분쟁도달성과새실행출력을요청한다.
