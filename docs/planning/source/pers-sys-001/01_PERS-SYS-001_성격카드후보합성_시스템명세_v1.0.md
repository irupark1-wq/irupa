## 0. 선행 결정과 비결정 구분

**김PO 확정:** 첫 4장 `다정한 / 욱하는 / 고집 센 / 독립적인`; 0~3장(권장 2), 15세트, 선택 순서와 무관, 중복 불가, 미지원 카드 사용 불가, 기존 3축·관계 8축·인지·기억·거절·반복 상한 유지. 선택 카드가 직접 관계 delta·갈등 severity·고의·실제 완료·동의를 만들면 안 된다. 기존 폰에 자동 카드 부여 금지. 과거 원장 재계산에 현재 카드 소급 금지. 12개 `PERS-C01~12` ID 유지. `PO-HAND-015`가 로그인·두 방보다 **다음 플레이 가능 개발 묶음의 카드 우선**을 새로 확정했다. 이미 구현된 로그인·두 방·저장 기능은 유지.

**미결 및 제안:** 행동 후보별 추가 점수, 합성 상한, 설명 수용 구현 경로, 후속 성격 반응 점수, 카드 규칙 버전·저장 필드의 정확한 기술 형식. 아래 숫자는 모두 **실험 제안치**이지 출시 값·기존 소스 값이 아니다. 실제 갈등 250의 활성화는 이 문서에서 승인하지 않는다.

## 1. 기존 3축과 카드의 역할 분리

| 현행 내부 축 | 역할(기존 추출 코드 기준) | 카드와 겹치는 지점 | 처리 계약 |
|---|---|---|---|
| `fairness_sensitivity` | 작업·도움·복구 후보와 EVT-09/10의 `reciprocity` 기여 계수 | `고집 센`, `욱하는`, `다정한`의 확인/도움 | **기존 축 점수·이벤트 효과는 유지**. 카드는 유효 후보 선호에만 소폭 잔차 가중; 공정성 수치로 사실 포함/제외 입장 고정 금지 |
| `closeness_orientation` | 만남·이야기 후보 및 일부 수락 조건 | `다정한`, `독립적인`의 접촉/거리 | 카드가 친밀 성향 값을 몰래 바꾸지 않는다. 독립적이어도 관계 축·애정 자체의 감점 없음 |
| `risk_aversion` | 휴식·만남·복구 후보에 영향 | `독립적인`의 휴식, `고집 센`의 재확인 | 카드 효과는 후단에만 적용, 위험 회피 축 재추첨 없음 |

기존 로컬 `prototype/life.js`에서는 `rest/work/social/meet/assist/repair` 후보가 있고 `reaction`은 상대의 상태·기질·관계로 수락 여부를 검사한다. 이전 시제품의 `work` 합류 분기에는 반응 검사에 initiator 기질이 전달되는 것으로 보여, **현 최신판에 같은 문제가 남았는지 김도현 확인 필요**. 구형 코드의 `trust<220`, `tired>=65` 같은 문턱을 최신 고정 규칙으로 가정하지 않는다.

## 2. 후보 생성 → 적격성 → 가중 → 선택 → 반응 → 확정

1. **권위 사실/인지**: source/action ID·실제 기록·observer가 아는 사실·해결 여부와 소유 권한을 확인한다. 이벤트를 지어내지 않는다.
2. **하드 적격성**: 같은 방·경로·남은 시간·피로·현재 활동·상대 유효·동의/권한·기존 쿨다운/반복 계약을 검사한다. 카드가 부적격 후보를 되살리면 실패.
3. **기본 점수** `base_score`: 기존 기질 3축·욕구·관계 방향·목표·기억·환경·기존 재현 가능한 변동을 포함한 최신 빌드의 값. 카드 없는 폰은 기존 후보/점수/선택과 **동일 결과**여야 한다.
4. **성격 선호 보정** `card_delta`: 아래 표에서 상황 전제까지 만족한 유효 후보에만 적용. 반례를 설명할 수 있도록 후보별 각 카드 기여를 비공개 추적 로그에 기록.
5. **선택** `final_score = base_score + card_delta`. 동점은 먼저 원래 후보 선택 순서/타이브레이크를 유지한다. 신규 동일점수 후보 사이에는 정규화된 후보 키(`kind|target_id|place_id|source_id`)의 정렬 결과로 결정한다. 현재 seed 난수 소비량을 함부로 바꾸지 않는다. 구형 코드의 `kind` 문자열순 보정은 최신판 확인 후 최소 영향 방식으로 처리한다.
6. **상대 독립 반응**: 대답하는 폰 자신의 권한·피로·목표·관계(상대→요청자 방향)·카드·인지 상태로 판정. 요청자 카드만 보고 수락을 강제하거나 상대 기질을 덮어쓰지 않는다. 초기에 기존 수락/거절 경계를 유지하고, 추가 반응 점수는 별도 실험 플래그로 검증.
7. **실행/원장**: 실제 수락·완료 commit이 난 때에만 승인된 사건을 기록. 후보 boost·제안·거절·기술 실패·단순 휴식은 관계 source 아님. Day/반복 quota/중립·미인지·checkpoint 계약 보존.

**기회 주의:** 만남의 `light_social` 효과 상한 도달은 **대화 시도 자체의 금지 조건이 아님**. 효과 자격과 행동 적격성을 혼동하지 않는다. 중립 완료도 가능하다.

## 3. 후보별 카드 보정표 (전부 시험 제안치)

단위는 기존 후보 **점수 단위**이며 저장 관계 delta가 아니다. `0`은 변경 없음, `—`는 아직 정식 행동/근거가 없는 디자인 전용 후보를 뜻한다. 조건 불충족 시 모든 카드 기여는 **0 이전에 후보 자체가 부적격**일 수 있다.

| 유효 후보 / 조건 | 다정한 `warm` | 욱하는 `quick` | 고집 센 `firm` | 독립적인 `independent` | 구현 판단 |
|---|---:|---:|---:|---:|---|
| `rest`(자기 휴식) | 0 | 0 | 0 | **+12** | 기존 휴식 후보 이용 |
| `work`(자기 작업) | 0 | 0 | 0 | **+8** | 기존 작업 후보 이용, 반드시 혼자만 하라는 뜻 아님 |
| `social`(이야기 자리) | +4 | 0 | 0 | -5 | 기존 후보 이용. 혼자 있기 선호는 접촉 금지가 아님 |
| `meet`(대화 제안) | +6 | 0 | 0 | -8 | 기존 후보 이용, 대상 동의 우선 |
| `assist`(도움 제안) | **+11** | 0 | 0 | **+3**¹ | 작업·대상·여력·수락 자격 필수 |
| `repair`(승인된 특정 쟁점 보완) | +4 | 0 | +2 | 0 | 열린 실제 쟁점+정당한 접근·수락 필요 |
| `credit_ask`(인지한 공로 누락 확인) | +3 | **+12** | +3 | 0 | 저장된 누락·직접 인지/출처가 있을 때만 |
| `credit_review`(증거 재검토) | +2 | +8 | **+10** | 0 | **신규 행동 정의/지원 확인 필요** |
| `credit_state_standard`(자기 기준 설명) | 0 | +3 | **+11** | 0 | **신규 행동 정의/지원 확인 필요** |
| `credit_accept_explanation`(근거 있는 설명 수용) | +4 | +3 | +2 | 0 | **신규 행동 정의/지원 확인 필요**. 고집으로 불가능 처리 금지 |
| `express_discomfort`(알고 있는 불편 표현) | +2 | **+10** | +2 | 0 | **신규 행동 정의/지원 확인 필요**. 곧장 갈등 생성 금지 |

¹ `assist`의 독립적인 +3은 **상대가 요청했거나 공동 목표에 동의했고 여력이 충분한 경우만**. 다른 경우 0이며, 기존 수락 조건은 그대로 유지. `credit_ask_accept/pending/fixed/ack`는 DEV-25 6절의 **대사 코드 키**이지 독립 행동 후보라는 증거가 아니다. DEV-25 `credit_standard_stated/contested`도 §5의 **비활성 갈등 설계 초안**이므로 구현 완료로 표시하지 않는다.

**책임 분리:** `credit_ask` 발화 전에 당사자가 실제 누락을 알고 있어야 한다. 다정한 폰도 피로하면 도움 거절 가능; 욱하는 폰도 실제 근거 없이 항의 불가; 고집 센 폰도 검증된 증거에 수정 가능; 독립적인 폰도 도움 수락 가능.

## 4. 0~3장 합성 알고리즘 (실험 제안)

- 카드 ID는 안정된 상수 `warm`, `quick`, `firm`, `independent`; 선택 목록은 저장 전 **ID 정렬·중복 제거가 아니라 중복 시 거절**한다.
- 유효 후보에 각 카드가 내는 부호 있는 점수 `w_i`를 구한다(위 조건별 적용). 0도 가능.
- `|w_i|` 내림차순, 동률은 card ID 오름차순으로 **선택 순서와 무관하게** 정렬한다. 0은 빼도 결과 동일.
- `raw = w_1 + (w_2 / 2) + (w_3 / 4)`. `card_delta = clamp(round_half_away_from_zero(raw), -14, +14)`.
- 카드 0장일 때는 `card_delta=0`, 기존 선택 코드를 최대한 동일하게 실행(결정론 회귀). 소수점 반올림은 카드 delta에만 마지막 1회 적용. 음수도 절댓값 기준 반올림.
- 3장이라고 승률/재화를 올리지 않는다. 더 많은 카드는 다른 선호를 섞으며, 같은 후보 영향은 한계 수익이 줄고 반대 부호는 상쇄한다. 이 규칙 자체가 3장 비우월성을 **보장하는 증명은 아님**—장별 선택률/반례로 검증해야 한다.

**계산 예시:** `warm+independent` 만남 후보의 카드 기여는 `-8 + 6/2 = -5`; `warm+independent` 도움 후보는 적법한 공동목표 조건에서 `11 + 3/2 = +13`; `warm+quick+firm` 공로확인 후보는 `12 + 3/2 + 3/4 = 14.25 → 14`(상한). 4장 불가.

**추천 실험 방법:** 같은 세계/폰/관계/행동 자격/seed로 `card_ids=[]`와 `[해당 카드]`를 교차 비교. 단독 선택의 유효 후보 최소 1개가 실제로 차별화되고, 거절/피로/위치 경계가 유지되는지 본다. 숫자 14 상한, 개별 보정치는 김도현 시뮬레이션과 김플레이 생활 관찰로 수정 가능하며 수정 시 `rule_version` 증가/결정 로그가 필요.

## 5. 독립 반응 모델 (최소 버전 + 확장 제안)

**최소 구현:** 기존 대상 폰의 권한·상태·동의·피로·행동 가능성 및 `target→actor` 관계 평가를 재사용한다. 예: 도와주려는 폰이 다정해도 상대가 바쁘거나 거절하면 사건 없음. 요청자가 독립적이어도 대상이 수락할 수 있다. 대상 카드의 수락 선호까지 바꾸려면 동일한 데이터 소유자·행동 타입·상대 지각을 기준으로 한 별도 `response_candidate` 설계/시험 후 추가한다.

**확장안(미승인):** 대상의 반응 후보 `[accept, decline, defer]`를 생성하고 하드 게이트 다음에 선호 점수를 적용. `warm`은 수락 가능한 한정 도움에 약한 가중, `independent`는 자기 휴식 선택에 약한 가중, `quick`은 근거가 확인된 질문 우선, `firm`은 기준 설명/새 증거 재확인. **상대의 명시적 거절·미인지·강제 수락 금지**는 불변. 거절과 기술 실패가 악의·배신·애정 감점의 근거가 되지 않음. 임계치·수치는 미확정이므로 이번 제출의 표를 자동 적용하지 않는다.

## 6. 6개 두 장 조합과 대표 장면 계약

| 조합 | 기대 차이 / 실제 후보 연결 | 금지·반례 |
|---|---|---|
| 다정한+욱하는 | 도움 `assist`와 근거 있는 `credit_ask`가 상황별 후보가 됨 | 도움 성공 직후 자동 싸움, 인지하지 못한 기록에 항의 |
| 다정한+고집 센 | `assist` 제안 + 증거 확인/기준 설명 가능 | 친절하다고 자기 기준 무조건 포기 |
| 다정한+독립적인 | `rest/work`를 유지하면서 필요·동의 조건에서 `assist` 가능 | 혼자 시간=낮은 애정/신뢰 |
| 욱하는+고집 센 | 근거가 있을 때 `credit_ask`·`credit_review`·`credit_state_standard` 우선 | 카드만으로 conflict250/고의 부여 |
| 욱하는+독립적인 | 사실 질문 후 `rest` 또는 자기 활동으로 복귀 | 불편 표현=관계 단절 |
| 고집 센+독립적인 | 자기 작업·기준 확인과 합의된 협력 공존 | 모든 공동 작업 거절, 증거 무시 |

대표 검수 6장면(`PO-PERS-002` 4절)에서 **기본 점수/카드 delta/유효 후보/선택/대상 반응/실제 완료**를 따로 기록해야 한다. 예를 들어 `고집 센`의 '근거에 따른 수정'은 현재 '정정' 대사만으로 통과가 아니며 유효한 evidence revision과 설명 수용 action이 있어야 한다. `회복 후 거리`는 해결 상태와 친밀 선호를 별개로 추적한다.

## 7. 카드 수정·저장·과거 재생 계약 (안)

```json
{
  "personality_profile": {
    "schema_version": "personality-cards-v1-proposed",
    "rule_version": "pers-score-v1-proposed",
    "card_ids": ["firm", "independent"],
    "effective_from_order": 321,
    "legacy_axis_values": {
      "fairness_sensitivity": "medium",
      "closeness_orientation": "medium",
      "risk_aversion": "medium"
    }
  }
}
```

- 저장 payload의 실제 필드 이름·next order 채번·현재 `save_format` 버전은 **김도현이 최신 스키마에 대조하여 결정**. 위 JSON은 서버/클라이언트 API 확정형이 아님.
- 카드 추가/해제·3축 동시 편집은 한 commit. 실패는 이전 카드/3축/활동 상태로 rollback. 중복 카드·4장·미지원 ID·미지원 rule_version 거절. 지원 카드 4종 외 ID는 일반 유저 선택 불가.
- 과거 사건은 당시 profile snapshot, rule/trait revision·인지·순번으로 replay. 새로운 카드 적용은 `effective_from_order` 이후 새 결정에만 적용; 이벤트 시각 이전 재평가/소급 관계 기여 금지.
- 옛 저장은 `card_ids=[]`로 간주하면서 pawn ID/기존3축/원장/기억/갈등/동의/기존 생활을 그대로 둔다. 폰 카드 자동 배정·내부3축 재추첨 금지. 새로운 저장 형식을 구버전 클라이언트가 덮어쓰지 않도록 버전 거절/원본 백업/업데이트·rollback 계획 유지.
- 카드가 일반 공개 DTO·대사에서 내부 가중치, 상대 비공개 기억, 역방향 점수/성격 추론을 누출해서는 안 된다. 개발 trace는 접근통제된 진단용.
- 카드 설정이 바뀌어도 이미 이동/수락·행동 중인 intent는 옛 버전 snapshot으로 완료할지 취소할지 개발 정책이 필요하다. **권고:** 시작된 intent는 snapshot 고정, 새 후보 선택부터 새 카드 적용(권한/안전 변경은 항상 우선). 새 후보에만 effect 적용.

## 9. 역할별 김PO 경유 인계 요청

**김도현**: ① 최신 후보 kind와 점수 함수/동률·seed 소비 순서, ② 지원 행동/그룹·대화 종류/목격 근거와 카드 저장 확장 가능 지점, ③ 기존 3축에 이미 포함된 편향의 중복 보정, ④ 부적격 후보 필터/상대 독립 반응(요청자 기질 누수 포함), ⑤ 기존3축·이벤트 재생/계정·두방/동시 저장/실패 rollback, ⑥ 실제 PERS-C01~12 증거와 개발 작업량 회신. 기존 카드 없는 폰 동작의 회귀 차이도 제출.

**정연우**: 수치 제안이 관계 의미를 왜곡하지 않는지(다정=순종 등), 실제 누락 인지/설명 수용·쟁점 유지/해결 후 거리 분기, 두 장 6조합의 예외를 검토. `fairness_sensitivity`를 포함 입장과 일대일 고정하지 않음. 신규 delta/severity는 이 문서가 요구하지 않음.

**김플레이**: 위 후보 kind/조건/금지 조건과 장면 6개를 `PERS-PLAY-001`에 연결. 기존 `credit_ask` 등 상황 말풍선은 **실제 commit 뒤에만**; 카드 설명 대사가 사실·인지 상태를 대신하지 않도록 주의. 미구현 수리/재료 전달은 사용하지 않음. 저에너지/거절/경로없음 후 대체 활동 UX 제공.

**김디자인**: 0/3·1/3·2/3·3/3·해제/취소/저장실패·기존폰 수정/미지원 카드 잠금 상태를 보여줌. 행동 차이를 드러내는 짧은 실생활 장면/읽기 좋은 말풍선 우선; 좋음/나쁨 캐릭터 등급, 관계 총점·감정 자동 표시 금지. 신규 자산 사양은 김도현 실제 렌더 요구를 김PO가 취합한 뒤 확정.

**김PO 결정 요청 (승인되지 않은 것만):** A) 후보 점수표·상한·합성 수식 시험 승인, B) 신규 `credit_review/state_standard/accept_explanation/express_discomfort`의 최소 지원 범위(현 코드 지원 현황 확인 후), C) 대상 반응 추가 점수의 다음 차수 분리 여부, D) 기존3축 중복 보정 기준. 새 갈등250 활성화는 PERS 과제로 자동 승인하지 않음.

## 10. 인수 완료 기준(제안)

- 첫4카드 각1개 이상의 유효 후보/반응 우선순위 변화 + 실제 대표 행동 증거.
- 선택/해제/저장/복원 전 과정의 기본 폰/기존 데이터 불변 및 재현성.
- 거절·인지·권한·증거·반복 상한·상대 독립 수락은 우회되지 않음.
- 자동시험 + 실제 플레이 장면(연속 화면/영상), 실제 vs 기대·실행 버전 구분.
- 미지원 후보 때문에 장면이 막히면 막혔다고 명시하고 대사만 교체해 합격시키지 않음.
