## 3. SB-0003 실행 전 보완

### URL·Google

실제 callback경로와앱복귀경로를김도현이먼저확정한다. production redirect는필요한정확한주소만등록하고 https://neinom.com/** 전체와일괄localhost/**를기본승인값으로사용하지않는다. 로컬시험은분리한정확한경로를등록한다. Google승인도메인/동의화면·사이트지원정보/게시상태는계정소유자가공식화면에서확인한다. ‘심사보통불필요’를실제승인완료로기록하지않는다.

### 메일·DNS

SMTP는실사용주소발송에필요하다. Supabase기본메일의팀원/시간당2통제한은 [공식 SMTP문서](https://supabase.com/docs/guides/auth/auth-smtp)에따라시험용한계로기록한다.

Resend도메인검증화면의정확한type/name/value/TTL을목록으로받아기존레코드와대조한다. 같은host에SPF TXT를중복추가하지않고 기존정책과발송범위를검토한다. DKIM과지정발송/return-path서브도메인레코드만필요대로추가하고neinom.com루트메일수신MX/웹A/CNAME을건드리지않는다. 기존DMARC정책을임의교체하지않으며필요시낮은영향의제안을올린다. 아직레코드값이없으므로본결정은실제DNS수정완료보고가아니다.

공용프로젝트/기존사용영향이없다는것은개발자보고다. 실제프로젝트/조직범위·발송/수신자·DNS대상을확인하고설정변경기록을남긴다. Googlesecret/SMTPkey는소유자가대시보드에입력하며문서/채팅/개발자에게전달하지않는다.

### 비밀번호·계정연결

최소10자/문자규칙은시험설정후보이며길이·문자만으로보안완료라고하지않는다. 공급자기능·rate limit·재설정·일반오류·필요시CAPTCHA를대조한다. Google로먼저가입한사용자가동일이메일로이메일신규가입하는흐름과, 로그인계정에비밀번호수단을추가하는흐름은다르다. 공식정책에맞춰기존Google로그인→검증된비밀번호추가/재설정경로를정의하고일반가입메일이항상오는것처럼안내하지않는다.
