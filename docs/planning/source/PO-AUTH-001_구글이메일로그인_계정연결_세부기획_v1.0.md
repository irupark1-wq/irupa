# PO-AUTH-001 — 구글·이메일 로그인 및 기존 월드 계정 연결

- 김PO → 김도현 / 참조 김디자인·김시스템
- 작성일: 2026-10-13 / v1.0
- 사용자 확정 요구: 다음 개발에 구글 및 이메일 로그인 추가.
- 관련: PO-PLAN-001/002, PO-DEC-001, PO-ROOM-001, PO-HAND-007
- 상태: 제품 세부기획. 실제 인증 설정·메일 발송·DB 변경·배포·검증 완료가 아니다.

## 1. 범위와 순서 변경

기존 A3 뒤 B-ACCOUNT 계획을 다음 버전 작업으로 앞당긴다. 구글 로그인, 이메일 가입/로그인, 이메일 확인, 비밀번호 재설정, 로그아웃, 계정 구분 및 기존 로컬 월드의 안전한 계정 저장을 묶는다. 실제 친구 방문은 이후 B1이며 로그인 구현만으로 온라인 방문 완료를 선언하지 않는다.

기존 개발 데이터·공유 서비스와 충돌하지 않는 구현안을 김도현이 제시한다. 인증 기술은 검증된 기존 인증 서비스의 지원 기능을 우선하고 게임이 비밀번호 관리 체계를 새로 만들지 않는다. 이번 사용자 요청은 이 기능 제작의 제품 승인이며 같은 기능 도입 여부를 다시 묻지 않는다. 실제 운영 설정에 필요한 자격·권한·비용·공유서비스 영향은 구체적으로 보고하고 필요한 접근만 요청한다.

## 2. 로그인 방식 결정

- 구글: ‘Google로 계속하기’ 버튼. 구글 인증 취소는 정상 취소이며 로컬 자료와 게임 관계에 영향 없음.
- 이메일: **이메일+비밀번호**를 첫 방식으로 채택한다. 가입·이메일 확인·로그인·비밀번호 재설정을 지원한다. 인증 서비스가 이 방식보다 일회용 코드만 지원한다면 변경 이유/UX/기존계정 영향을 먼저 제안한다. 두 방식을 임의로 혼용하지 않는다.
- 계정 없이 시작/계속하기 유지. 로컬 플레이에는 폰 생성 전 로그인 강제를 추가하지 않는다. 계정 저장·기기 간 복구와 실제 소셜은 로그인 필요로 표시한다.
- 게임 표시 이름과 구글/이메일 정보는 별도. 구글 실명·프로필 사진·이메일을 폰 이름이나 공개 사용자 정보로 자동 반영하지 않는다.

이메일 비밀번호는 인증 제공자의 검증된 저장/재설정 기능을 사용하고 게임 저장 JSON·로그·기획 fixture에 넣지 않는다. 인증 서비스 정책에 맞는 길이/유출 비밀번호 차단·시도 제한을 개발자가 제안한다. 단순 복잡성 규칙만으로 안전하다고 판정하지 않는다.

## 3. 첫 사용과 기존 사용자 흐름

1. 시작/설정에서 로그인 선택. 로컬 저장임을 분명히 표시한다.
2. 외부 구글 로그인 또는 이메일 가입/확인·로그인을 수행한다. 인증 과정 중 월드 시뮬레이션은 정지하고 초안을 보존한다.
3. 로그인 성공 시 계정 상태를 표시한다. **로그인 성공만으로 월드 저장 성공을 표시하지 않는다.**
4. 현재 로컬 월드가 있으면 ‘이 계정에 현재 월드 저장’ 화면에서 월드/폰 수·마지막 저장·대상 계정을 확인한다. 로컬 백업을 먼저 보존한다.
5. 서버 저장 성공과 소유 연결 검증 후 ‘계정에 저장됐어요’를 표시한다. 실패하면 로컬 원본 유지·재시도/취소. 기본 생활은 로컬 체험으로 계속할 수 있다.
6. 다른 기기에서 같은 계정으로 로그인하면 계정 저장 월드를 조회·선택하여 정지 상태로 복구한다. 오프라인 생활 소급 없음.

다음 버전의 최소 계정 저장은 **명시적인 스냅샷 저장/불러오기**다. 상시 실시간 동기화·오프라인 충돌 자동 합치기를 완료 범위에 넣지 않는다. 자동 클라우드 저장은 후속 제안으로 분리한다. 로그인만 납품하고 계정 저장은 미완료인 경우 두 상태를 따로 보고한다.

## 4. 로컬 월드 연결과 소유권

- 내부 account_id는 인증 주체와 연결한 안정 ID다. 이메일 문자열이나 표시 이름을 소유권 키로 사용하지 않는다. 구글 계정 식별은 검증된 provider subject를 사용한다.
- 서버는 로그인한 주체가 자기 계정 namespace에 저장할 권한을 검증한다. 로컬 JSON의 owner_id·관계 점수·권한 주장을 온라인 참여 권한으로 신뢰하지 않는다.
- 기존 로컬 월드는 해당 로그인 계정의 **개인 월드로 가져오기**다. 다른 사람의 온라인 월드/폰 소유권을 덮어쓸 수 없다. 새 서버 식별 매핑이 필요하면 폰 간 관계·기억·action/source 참조를 함께 일관되게 보존한다.
- 가져오기 키는 account+로컬 world 참조+스냅샷 fingerprint/버전 등을 사용한 안정 멱등 계약으로 제안한다. 같은 업로드 재전송에 폰/월드 복제 없음.
- 기존 계정 월드가 있으면 로컬 월드로 자동 덮어쓰지 않는다. ‘계정 월드 불러오기’ 또는 ‘로컬 월드를 별도 월드로 저장’을 제공한다. 월드 간 관계/폰을 자동 병합하지 않는다.
- 서로 다른 기기의 계정 저장은 expected_version과 서버 revision으로 충돌을 감지한다. 최신 계정 상태 확인·로컬 사본 보존·명시 선택으로 해결하며 마지막 요청이 조용히 승리하지 않는다.
- 월드 손상/지원하지 않는 schema/version은 안전 거절하고 원본을 유지한다. 부분 성공으로 얼굴만 옮기고 관계/기억을 잃지 않는다.

## 5. 구글·이메일의 같은 사용자 연결

같은 이메일이라는 이유만으로 두 별도 계정을 자동 병합하지 않는다. 이미 로그인한 계정에서 ‘다른 로그인 방법 연결’을 제공하려면 기존 계정 재확인과 새 수단 인증, 중복 subject 검증이 필요하다. 인증 제공자가 검증된 연결 정책을 지원하면 근거와 충돌 처리를 확인한다.

다음 버전에는 방법 연결 기능까지 구현 가능한지 견적을 받는다. 미구현이면 자동 병합 대신 기존 로그인 방식으로 계속하도록 안내하고 `link_pending`으로 명시한다. 로그인 방식 추가와 게임 월드 가져오기는 별도 명령이다. Google 계정 변경/중복 이메일로 다른 계정의 월드에 접근하면 안 된다.

## 6. 상태·실패·로그아웃

| 상태 | 표시와 처리 |
|---|---|
| 게스트 | ‘이 기기에 저장 중’ 및 계정 저장 안내 |
| 인증 진행 | 중복 요청 차단·취소/뒤로가기·현재 초안 보존 |
| 이메일 확인 대기 | ‘이메일을 확인해 주세요’·재발송 제한·주소 수정/취소 |
| 로그인 성공 | 계정 표시, 월드 저장 상태는 별도 |
| 인증 실패 | 입력/연결 확인을 안내. 계정 존재 여부나 다른 사용자의 정보를 노출하지 않는 공통 실패 응답 |
| 계정 저장 중/실패/충돌 | 정지 및 로컬 사본 유지·멱등 재시도·최신 상태 확인 |
| 세션 만료 | 계정 저장/온라인 권한 작업 정지·로컬 초안 보존·재로그인 |
| 로그아웃/계정 전환 | 시뮬레이션 정지·계정 캐시 분리. A의 서버 월드가 B 계정 화면에 나타나거나 B로 저장되지 않음 |

로그아웃으로 원격 자료를 삭제하지 않는다. 로그아웃 화면은 저장 여부를 안내하고, 기기에 개인 사본을 남기는 동작은 명시 선택으로 제공한다. 기본 새 게스트 영역은 로그인 계정 캐시와 분리한다. 다른 사람이 같은 기기를 쓰는 경우에도 자동 노출하지 않는다.

계정 삭제는 로그인/로그아웃과 분리한다. 실제 삭제 버튼은 재인증·범위 안내·서버 소유자료 삭제 계약이 갖춰진 경우만 활성화한다. 정확한 보존/삭제 정책은 B-ACCOUNT 후속 명세와 운영 제약을 대조한다. 지원하지 않는 복구·삭제를 가능한 것처럼 표시하지 않는다.

## 7. 개발·디자인 인계

김도현은 인증 공급자/현재 프로젝트 격리, Google client/redirect 설정, 이메일 확인/재설정 발송, 세션 검증, 계정 namespace·권한, import/충돌/백업·복구의 구현안과 필요한 실제 설정 목록·영향·작업량을 제출한다. 토큰/비밀번호/secret은 문서·코드저장소·공개 로그로 제출하지 않는다.

김디자인은 로그인 선택·이메일 가입/확인·실패·취소·계정저장/import 선택·충돌·복구·로그아웃 상태를 기존 톤으로 제작한다. Google 버튼은 공식 표시 가이드를 확인한다. 인증 상태와 저장 상태를 별도 줄로 표현한다. 기술 선택을 사용자가 이해해야 로그인할 수 있는 흐름을 만들지 않는다.

## 8. 수용 시험

AUTH01 Google 성공/취소/실패와 redirect 복귀, AUTH02 이메일 가입/확인/로그인, AUTH03 재설정 만료/재사용/시도제한, AUTH04 세션만료/재로그인, AUTH05 로컬 가져오기와 원폰/관계/기억 유지, AUTH06 동일 업로드·다른command 중복0, AUTH07 기존계정 월드 충돌·별도저장, AUTH08 다른기기 복구 및 paused/소급0, AUTH09 다른계정/기기 소유조회·변경 거절, AUTH10 로그아웃/계정전환 캐시분리, AUTH11 토큰/비공개정보 응답·로그 누출0, AUTH12 이메일동일/Google수단연결의 자동병합방지.

각 ID는 지원환경·초기상태·명령·기대/실제·코드/정책버전·pass/fail/partial/blocked/not_run과 로컬/시험서버/운영 범위를 제출한다. 메일 발송/Google 실제 인증이 없는 mock 시험을 운영 로그인 통과로 올리지 않는다.

## 참고 근거

구글 subject 식별과 검증된 인증 흐름은 [Google OpenID Connect 문서](https://developers.google.com/identity/openid-connect/openid-connect)를 참조한다. 공통 실패 응답과 재설정 처리는 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html), [Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)를 기술 검토 근거로 사용한다. 본 문서의 계정저장/월드충돌정책은 김PO의 제품 결정이다.
