## 1. 로그인/시작 화면

PO-START-001을 이번에 추가한다. 준비 화면→로그인/게스트 선택→필요한 월드 선택/연결→paused 진입으로 구성한다. 기존 로컬이 있으면 이어하기 우선, 인증 callback은 일반 랜딩보다 먼저 처리한다. Google/이메일 로그인·계정 저장 정책은 PO-AUTH001 및 PO-DEC006을 유지한다. 로그인 성공과 현재 월드의 저장 위치를 별도로 표시한다.

DES12의 상태표를 수용한다. 계정 사본 생성과 현재 활성 월드의 서버 저장을 구분한다. ‘로컬 복구 사본 유지’ 문구는 실제 사본이 보존된 경우에만 사용한다. 사유 미확인 거절의 declined.png는 기존 의미 규칙에 따라 텍스트/중립 표시로 수정한다. 공개된 ‘혼자 있고 싶음’에만 해당 그림을 사용한다. reading/recording은 유지하고 스타일 통일 재제작을 우선 작업으로 추가하지 않는다.

## 2. 국소 분쟁 정책 변경: 정연우 v1.5 우선 적용

### CR-DEV25-CREDIT-01: 고정 성격→입장 매핑 수정 수용

공정성 high=항상 포함, low=항상 제외, medium=항상 승복 매핑은 채택하지 않는다. 민감도는 확인/근거 요청/문제 주목 후보에 영향을 주고, 포함/제외/미정 입장은 실제 규칙 이해·역할·정보·기억에서 형성한다. 이는 새 영구 성격축이 아니다.

QA에서는 C=제외/B=포함을 명시 입력으로 고정할 수 있다. 같은 성격의 반대 입장 및 다른 성격의 같은 입장 반례를 포함한다. 자연 생활에서 입장이 만들어지는 근거·가중치·분포는 김시스템/김도현이 작은안을 제안한다. 임의 랜덤으로 관찰 사실이나 기준을 바꾸지 않는다. 생성 모델이 없으면 통제 QA 통과와 실제 생활 도달 미완료를 구분한다.

### CR-DEV25-CREDIT-02: 25% 조건과 갈등250

25% 미만은 **이 시제품 공로 조항의 모호성을 시험하는 조건**으로 채택한다. 시간 기여 비율을 공로 가치나 도덕성으로 표시하지 않는다. 실제 조항이 확정된 단일 해석이면 분쟁 조건으로 쓰지 않는다.

정수 작업진행 tick>0, 실제 helper overlap tick>0 및 분모이하를 보존한다. 판정은 4×overlap<work로 한다. 표시용 permille 반올림이 판정을 바꾸지 않도록 한다. 이동/휴식/정지/오프라인은 분모·분자에서 제외하고 나눠 도운 구간은 중복 없이 합산한다. 24/25/26%와 249/250 경계, 결측/0분모/0기여를 검증한다.

실제 도움 인정·양쪽 독립 주장·상대 주장 인지·같은 record/rule version·미해결 표시 쟁점·한정된 영향이 모두 있어야 B→C 갈등250 후보다. 250은 개별 Conflict severity 시험값이며 감정4축 -250이나 파생값 덮어쓰기가 아니다. 다른 갈등과 병존 산식을 검증한다. 시간 경과/같은근거로450/700 자동 승격 없음.

### CR-DEV25-CREDIT-03: 해결과 정정자 귀속 분리 수용

정정 게시→B의 수정본 인지→B의 정정자 인지→특정 분쟁 종료→EVT09 효과는 독립 조건이다. 기록 issue는 수정본 인지만으로 닫힐 수 있다. B가 실제 정정자C를 모르면 EVT09 B→C는0이다.

국소 분쟁이 이름 표시 하나에만 관한 것이고 B가 실제 수정본을 받아들이면 그 분쟁은 해결 가능하다. **정정자 미인지라는 이유만으로 이 분쟁을 무조건 계속 열어두지 않는다.** 김시스템 C250-07의 ‘Conflict 확인 대기’ 고정 기대는 이 기준에 맞춰 개정한다. 더 넓은 기준 갈등이 남으면 별도 쟁점/증거/범위로 표시한다. 실제 인지/수용 없이 자동 종료하지 않는다.

합의 경로는 양쪽의 적용 방식·scope·명시 수용·필요 인지를 가진 별도 action이다. 수정 없이 제외 합의로 닫으면 게시의 누락 이력은 남고 EVT09/12는0이다. 합의·정정만으로 친밀/화해 태그를 자동 생성하지 않는다. EVT12는 별도 계획/이행/필요 수용 증거가 있어야 한다.

## 3. 대사와 QA 수정

credit_ask_pending의 진짜 거절과 기한 없는 연기는 구분한다. 연기는 deferred_without_due 의미로 표시하며 자동 약속/기한/EVT07 생성 없음. 거절에는 ‘지금은 확인하기 어려워.’ 등 현재 상태 문구를 사용한다. ‘작업 기록 확인 좀.’은 ‘기록, 확인해 줄래?’ 등 짧은 청유형으로 보완한다.

C의 기준 발화는 ‘기준상 안 적어’라는 객관 판결 대신 ‘난 짧게 도운 건 빼는 줄 알았어.’ 같은 자기 해석임을 밝히는 대사로 제안한다. 실제 fact 인정과 rule/stance source가 필요하다. 말풍선 길이상 둘로 나눌 때도 하나의 주장 action과 연결하고 일부 발화만으로 상대가 모두 인지했다고 가정하지 않는다.

김시스템 C250-13의 fixed high/low/medium 기대는 신규 매핑에 맞춰 수정한다. 다른 QA ID도 정연우18건과 비교하여 충돌을 표시한다. 16건과18건은 별도 집합이며 개수만 합쳐 기존 pass로 처리하지 않는다.

## 4. 저장·증거 필수 조건

열린 Conflict가 요구하는 도움/기록/주장/상대 인지/ratio·stance snapshot·resolution ref는 확인 issue가 닫힌 후에도 pin 또는 충분한 불변 증거로 보존한다. ledger300→150 접기·credit60 trim 후에도 그 분쟁을 재현/해결할 수 있어야 한다. 동일record/B/C/topic의 stable ID·중복/동시성·정정 경합·원자 rollback을 검증한다. 자료가 없으면 다른근거를 대입하지 않고 blocked_missing_evidence로 처리한다.

이미 제공된 DEV24 실측/DEV25 로그를 매번 다시 생성하라고 요청하지 않는다. 담당자의 미수령 문제는 원본 패키지를 직접 첨부해 해소한다. 이번에도 DEV25 원본 및 기존 인계를 포함한다. 해당 원문/코드/호출 계약이 더 필요한 경우 정확한 누락 파일만 요청한다.
