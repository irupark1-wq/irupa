## 1. 제품 방향과 적용 범위

다음 테스트 버전에 아래 세 개선을 포함한다. 사용자의 체감 문제는 접수했으나 실제 소스상의 원인과 이벤트 빈도를 이번 문서에서 확인한 것은 아니다. 김도현은 현 실행본을 재현해 원인을 대조하고 기존 A2 작업에 묶어 우선순위를 제시한다.

1. 성격·관계·기억에 따른 자율 행동/상대 반응의 차이와 생활에서 발생하는 불화.
2. 폰 위 말풍선으로 지금 나누는 대화 표현.
3. 관계창을 방향·복합 상태·최근 사건·변화 이유 중심으로 개선.

대화 선택지를 누르는 진행으로 되돌리지 않는다. 인위적으로 모든 폰을 불친절하게 만들거나 일정 시간이 지나면 무조건 싸우게 만들지 않는다. 실제 갈등 발생을 생활 사건으로 구현하고 다양한 정서 반응을 관찰할 수 있게 한다. 원형 폰/2D/기존 동의·인지 계약은 유지한다.

## 2. 성격·관계의 행동 차이

### 요구되는 차이

- 친밀 지향: 접근 빈도·혼자 활동 선호·대화 길이 경향 등에 영향을 주되 상대의 수락을 강제하지 않는다.
- 공정성 민감도: 실제 기여/공로 불일치에 대한 반응·확인 행동에 영향을 주되 낮은 값이 악의/공로 독점의 증거가 되지 않는다.
- 위험 회피: 낯선 활동·위임·갈등 대면 방식의 신중함에 영향을 주되 항상 친절하거나 항상 회피하는 고정 대본으로 만들지 않는다.
- 애정/신뢰/존중/갈등 및 기억: 접근·협력·중요한 맡김·회피·문제 확인·회복 반응의 차이에 사용한다. 하나의 ‘좋음/나쁨’ 조건으로 합치지 않는다.

최소 비교: 좋아하지만 못 믿음, 싫지만 존중해 협력함, 갈등 중 필요한 협력, 서운해 확인함, 해결 뒤에도 거리두기. 무뚝뚝한 말투와 낮은 애정은 같은 개념이 아니다. 말투·행동 경향이 다르다고 기존 3축에 새 성격축을 자동 추가하지 않는다. 필요한 추가 특성은 외주가 기존 축으로 가능한 표현과 확장안의 비용을 비교해 제안한다.

### 갈등의 실제 발생

첫 구현은 기존 합의의 같은 소유자 폰 공동작업 공로 기록 불일치를 실제 생활에서 발생·인지·반응·정정·복구할 수 있게 한다. 기존 갈등 fixture만 가져와 보여주는 것으로 완료하지 않는다. 생활 목표 충돌·공간 사용 방식의 불일치는 후속 후보이며 가구 점유/길막/단순 거절만으로 신뢰 하락을 자동 추가하지 않는다.

발생 사실, 원인 확인 여부, 폰의 해석을 구분한다. 새로운 부정 기여가 필요하면 사건 정의·입력·observer·scope·수치 가설·중복 처리·회복 조건을 명시해 검수한다. 정연우가 검수하지 않은 ‘고의 배신’ 분기를 임의 생성하지 않는다. 기능 거절·차단·참여 철회·접속 실패는 벌점0 유지.

### 개발 원인 점검

김도현은 초기 상태가 모두 같은지, 후보가 친밀 행동에 쏠리는지, 관계/기억이 실제 후보와 반응에 연결되는지, 갈등 생성 조건과 증거가 실제 생활에서 도달 가능한지 확인한다. 후보→제안→수락/거절→완료→인지→관계 변화의 각 단계에서 막힌 이유를 개발 로그로 비교한다. 콘텐츠 미구현과 밸런스 빈도 문제를 구분한다.

새 월드·같은 seed/공간에서 성격 또는 관계만 바꾼 비교와, 일반 자율 생활에서의 실제 발생 기록을 함께 제출한다. 재미와 관계 다양성을 단순 싸움 횟수로 판정하지 않는다. 갈등 빈도/회복 가능성/쏠림은 외주 제안과 관찰 후 시험값을 정한다.

## 3. 폰 위 대화 말풍선

### 동작

실제 대화/상호작용의 발화 시점에 해당 폰 위에 짧은 말풍선을 표시한다. 말풍선 텍스트는 대사 데이터와 실제 상황·인지 상태·화자/청자의 관계에 연결한다. 인사·잡담·도움 제안/수락/거절·서운함 확인·정정·회복/거리두기의 대사를 구분한다. 친절한 인사 하나만 무작위 반복하지 않는다.

제안 대사는 수락 이전에도 가능하지만 그 자체로 완료/점수 변화를 표시하지 않는다. 대사 발화와 사건 완료를 구분한다. 혼잣말을 사용할 경우 대화 상대가 있는 것처럼 연출하지 않는다. 방문 폰의 허용된 공개 발화만 표시하고 내부 속마음·성격 수치·역방향 점수·미인지 사실은 대사로 누출하지 않는다.

### 표시와 복구

- 폰 이동을 따라가되 화면 밖 잘림·가구 가림·여러 폰 동시 발화의 겹침을 처리한다.
- 짧은 대사 중심으로 표시하며 글자량·표시시간·대기열·동시개수는 실제 폰 크기/화면으로 디자인과 개발이 제안한다. 임의 픽셀값을 확정하지 않는다.
- 읽는 동안 일시정지 가능, 숨김/표시 설정 제공. 최근 공개 대화는 일지에서 다시 확인할 수 있게 한다.
- 생활 속도 ×4에서도 말풍선이 지나치게 빨라지거나 쌓이지 않게 표시 시간을 논리 시뮬레이션과 분리해 검토한다. 일시정지/재개 시 동일 대사를 중복 발화하지 않는다.
- 저장 확정 전 완료 결과를 대사로 성공 처리하지 않는다. 재실행/지식 replay로 과거 말풍선을 새 대화처럼 재연출하지 않는다.

말풍선 예시는 기획 표현 후보다: ‘지금은 혼자 쉬고 싶어.’ / ‘이 일은 네가 잘하니까 같이 해보자.’ / ‘기록에 내 이름이 없네. 확인해 줄래?’ / ‘기록은 고쳤어.’ / ‘문제는 정리됐지만 오늘은 따로 있고 싶어.’ 실제 공개 근거·발화자·상태와 맞는 경우에만 사용한다.

## 4. 관계창 개선

첫 화면은 관계 숫자8개를 동등하게 나열하기보다 ‘누가 누구를 어떻게 보는지’와 그 근거를 읽게 한다.

1. 상단: 폰 얼굴/이름, A→B 방향, 같은 소유자일 때 반대 방향 전환.
2. 요약: 복합 상태와 최근 인지한 변화 이유. 기본 태그의 실제 판정 근거를 사용하고 없는 상태를 확정 문구로 만들지 않는다.
3. 관계8축: 애정·신뢰·존중·의존·권력·호혜성·의무·갈등을 이름/짧은 설명/수치·게이지로 제공. 더 보기나 그룹 구분으로 읽기 쉽게 하되 8축 조회를 없애지 않는다.
4. 최근 사건: ‘무슨 사실을 알았는지 / 어떻게 받아들였는지 / 이유는 확인됐는지 / 갈등은 해결됐는지’ 독립 표시.
5. 활성 갈등/책임/의존 근거: 실제 엔터티가 있는 경우에만 표시. 권력500에 근거가 없으면 ‘공동 결정 기록 없음’ 등으로 설명.

색·하트 하나로 관계 전체를 좋은/나쁜 상태로 축약하지 않는다. 중립 반복의 점수 미변화를 실패로 표시하지 않는다. 타 소유자 관계는 공개 허용 정보만 받으며 비공개 숫자를 잠금 아이콘 뒤에 넣지 않는다. 방문 대역과 실제 온라인 표시를 구분한다. 상세 패널 열기/접기·세로/가로·읽기 크기를 검수한다.

## 6. 다음 버전 수용 기준

- 같은 상황의 성격/관계 차이가 후보·반응·대사에서 관찰 가능하며, 단순 문구 교체만으로 완료하지 않는다.
- 실제 새 생활에서 첫공로불일치가 발생하고 사실인지→확인/정정→복구 또는거리두기로 이어지는 근거를 제출한다. 일반설정의 발생빈도 기록과 강제설정 fixture를 구분한다.

- 관계창에서 방향·8축·최근사건의 사실/해석·갈등상태를 확인할 수 있고 비공개 정보 누출이 없다.
- 동의/기술중단 벌점0, 같은사건 중복0, 정정으로 행동/대사 재실행0, 이전폰/관계/기억 보존을 유지한다.
