DEV27 시작 화면은 로컬 개발 UI 납품으로 조건부 수용한다. PC 최초/폰 이어하기 화면을 김PO가 육안 확인했다. START03/04/05/07/08/10의 인증 실기 연결은 남는다. 193개 통과는 개발 보고이며 이번ZIP에 전체시험로그/최종commit은 없다. 다음회신에 코드/시험/배포의 버전 대응을 명시한다.

PC 최초 화면에서는 ‘이 기기에서 시작하기’가 위에 있고 Google/이메일이 아래에 보인다. 보고서의 첫사용자 버튼 순서와 차이를 명시한다. **게스트 시작을 주 버튼으로 두는 현재 작은안을 수용**한다. Google·이메일 선택은 바로 보이며 게스트/로그인의 가치·저장 위치를 설명한다. 돌아온 로컬 사용자는 이어하기가 첫 버튼인 계약을 유지한다. 상태/문구의 최종 읽힘은 디자인 검수로 확정한다.

## 2. 결정: 저장 형식3에 두 방+카드 저장 계약 함께 포함

수용한다. 두 방 구조와 카드 프로필의 **빈/비활성 저장 계약**을 한 번의 형식 migration으로 준비한다. 첫4종의 실제 가중치·대사·검증 전에는 일반사용자 카드 선택/효과를 활성화하지 않는다. 데이터 자리 마련과 기능 완성을 구분한다.

이전폰의 card_ids는 빈목록, 기존3축/관계/기억/원snapshot 유지. 기존폰에 무작위카드 부여 없음. 현재폰을생활방에 보존하고 아늑한방추가·폰복제/초기관계재추첨 없음. legacy 백업/저장부족/실패/형식거절·계정서버허용형식의 호환 순서를 SB0005로제시한다.

card schema/rule/profile version·정렬된card_ids·유효적용시점을 기록한다. effective_from_tick만으로는 정지중같은tick에서여러프로필변경의순서를구분못할수있으므로 안정적인profile version/commit order를함께제안한다. 과거필요snapshot은 최근몇개card_history 삭제로 소실되지않게하며, 실제사건/행동참조에필요한보존정책을정한다.

관계원장이카드를직접감정기여에쓰지않는최소안은수용한다. 그러나 고집센의설명수용·욱하는의확인질문과같은카드효과는 단순 life.js 후보점수가아닌 credit 응답/행동후보일수있다. 이를 실제지원하는 위치와대사만변경되는경계를명시한다. 카드선택후 기존수락하드조건·인지·사실증거는불변이다. PERS-SYS001 및PLAY안/QA 전 계수를임의채우지않는다.

약3.5일은개발자예상이며전체12/28종납기가아니다. 순서는두방→카드작은안→국소분쟁의현재제안을수용하고 남은실기/시작UI검수는병행한다.
