## 2. 제품 목표와 체험

동그란 폰들이 공간을 돌아다니며 성격·욕구·관계·기억에 따라 자발적으로 행동하는 생활 시뮬레이션이다. 플레이어가 사건마다 선택지를 누르지 않아도 이야기가 이어진다. 같은 공간에서도 폰에 따라 친해지거나 협력하거나 오해하거나 거리를 두는 다양한 관계를 만든다.

핵심 순환:

**폰 만들기 → 월드 배치와 환경 구성 → 자율 이동·생활·만남 → 실제 사건과 기억 형성 → 다음 행동과 관계 변화 → 환경 변경 및 관찰**

친구는 초대를 수락한 뒤 자신의 폰으로 내 월드의 공간에 참여한다. 방문 폰은 호스트 소유 폰으로 전환되지 않는다. 서로 같은 장소에서 활동하는 모습이 있어야 하며 메뉴에 이름만 나타나는 방문으로 대체하지 않는다.

초기 성공 기준은 자동 인사 횟수나 점수 상승량이 아니다. 플레이어가 행동의 이유를 이해하고, 환경을 바꾸었을 때 만남이 달라지며, 같은 성격이라도 관계에 따라 반응이 달라지는 경험이다. 콘텐츠마다 강제 행복·화해·친밀 결말을 만들지 않는다.

## 3. 폰 생성·꾸미기·성격

### 3.1 외형

- 첫 화면은 표정 없는 빈 원. 본체는 1:1 완전한 정원이다.
- 합성 순서: back_hair → base → eyes_pair → mouth → front_hair → frame_accessory.
- 눈·입·앞/뒤 머리·프레임은 독립 편집. 눈 pair 내부 비대칭 허용, 눈/입 없는 저장 허용.
- 기본 베이스만 원형 표시 clip을 강제한다. 머리와 장식은 원 밖 돌출 허용. 눈·입 display_clip은 비교 중이며 원본은 비파괴 보존한다.
- 직접 그리기, 파츠 선택, 초안 보호, 최소 20단계 undo/redo, 저장 중/실패/취소/버전 충돌을 지원한다.
- 기존 폰 외형 수정은 같은 pawn_id의 외형 버전 변경이다. 관계·기억·성격을 초기화하지 않는다.
- 실제 저장 확정 전에 월드에 불완전 폰을 표시하거나 저장 성공을 연출하지 않는다.

### 3.2 성격

공정성 민감도(fairness_sensitivity), 친밀 지향(closeness_orientation), 위험 회피(risk_aversion)를 각각 low/medium/high로 선택한다. 기본은 medium, 총 27조합. 기존 6프리셋·직접 수정·무작위를 제공하고 프리셋 이름보다 실제 축 값을 기준으로 평가한다.

성격은 행동 후보 선호와 사건 해석의 경향이다. 욕구·현재 목표·관계·상대 의사를 덮어쓰지 않으며 진단·도덕 등급으로 표시하지 않는다. 성격 저장 확정 이후 새 평가부터 적용하고 과거 사건의 당시 snapshot은 보존한다. 과거 정보 정정은 당시 성격·규칙·seed·반복배수로 재계산한다.

## 4. 월드·공간·생활

- 2D 공간에 쉼터·작업대·이야기 장소 및 이동 가능한 바닥·장애물을 둔다.
- 시제품은 12×8 정수 grid, 4방향 이동/BFS 및 실제 점유를 재사용한다. 추후 맵 확대·다른 이동 방식은 별도 검토한다.
- 활동 지점의 중심 점유와 협력자 인접 참여를 구분한다. 완료·취소 시 점유를 해제한다.
- 배경 그림의 가구 위치·크기와 충돌/활동 지점을 일치시킨다. 장식을 실제 상호작용 가구처럼 오인시키지 않는다.
- 가구 이동/닫기·장애물 변경 전에 유효/충돌/도달 가능/통로 막힘을 색과 문구 또는 윤곽으로 표시한다. 이동 중 배치 변경 시 경로를 재계산한다.
- 길막·피로·점유·대상 이탈은 완료 사건이 아니다. 안전하게 대기·대체 행동·취소한다.
- 생활 일시정지/재개와 ×1/×2/×4를 제공한다. 복구는 정지 상태, 화면 숨김은 진행 유예, 오프라인 사건 소급 없음이 단계 A 기준이다.
- 월드 구성 변경 자체로 관계 점수를 올리지 않는다. 바뀐 환경에서 실제로 발생·인지한 사건만 반영한다.

## 5. 자율 행동 시스템

행동 루프:

1. 권한·차단·동의·공간·기술 조건을 확인한다.
2. 욕구·현재 목표·활동 자원·관계·성격·기억에 따라 유효한 후보를 만든다.
3. 후보를 선택하고 목적지로 이동한다.
4. 상호작용을 제안하고 상대가 자기 상태에서 반응한다.
5. 수락된 활동을 진행하고 실제 완료 여부를 판정한다.
6. 확정 사건을 원장에 한 번 반영하고 인지·기억·8축·태그를 투영한다.
7. 상태를 저장한 뒤 다음 행동을 평가한다.

최소 행동은 혼자 쉬기·작업·이동·접근·인사·대화·도움/협력·거절·거리두기다. 접근은 수락·완료가 아니며 높은 애정이 수락을 강제하지 않는다. 플레이어 승인 팝업을 매 대화마다 요구하지 않는다. 지속 책임·중대 전환 등은 가벼운 행동과 별도 동의 계약이다.

같은 seed·초기 상태·배치·규칙 버전은 재현 가능한 결과를 내야 한다. UUID 등 비결정적 식별자는 관계 효과·행동 비교와 구분해 검증한다. tick·완료 사건·기억·중복 제한은 단일 로컬 commit 경계로 연결하고 저장 실패 시 원본 상태를 유지한다. 여러 탭 감지 정지는 서버 CAS/트랜잭션 검증을 뜻하지 않는다.

반복 대기 60tick·종류별 3회 상한은 현재 실험값이다. 최종 밸런스로 확정하지 않는다. **행동 가능 여부와 반복 감정 효과 제한을 별도로 정의**한다. 상한 도달 후 휴식·다른 활동·새 근거의 사건은 계속 가능해야 한다. 정확한 집계 scope·리셋·중립 대화 기록 방식은 김도현이 현 구현을 제시하고 정연우와 검수한다.

## 6. 관계·기억·태그

### 6.1 방향성 8축

| 축 | 의미 | 구현 원칙 |
|---|---|---|
| 애정 | 정서적 호감과 가까움 | 인지된 사건 기여 |
| 신뢰 | 말·행동을 믿는 정도 | 사실·독립 행동 증거 구분 |
| 존중 | 능력·인격에 대한 인정 | 호감과 별개, 낮은 애정이어도 협력 가능 |
| 의존 | 상대 부재 시 어려움 | ResourceLink 등 실제 대체곤란도 근거 |
| 권력 | 결정 영향과 거절 자유의 관계 | DecisionRole 근거, 계정 권한과 별개 |
| 호혜성 | 주고받음의 공정감 | 원천/기여 근거, 시험 성격 배수는 허용 사건만 |
| 의무 | 수락한 책임과 기대 | acceptedCommitment만, 도움은 자동 빚이 아님 |
| 갈등 | 욕구·의견·목표 충돌 | scope별 Conflict 상태와 잔여 severity |

모든 축은 1~1000 정수로 관리한다. A→B와 B→A는 서로 다르다. 초기 시험값은 애정/신뢰/존중/의존/권력/호혜성/의무/갈등 = 100/300/300/1/500/500/1/1이며 출시 밸런스 확정이 아니다. 권력 500에 활성 근거가 없으면 no_active_basis를 표시한다. 전체 관계를 단일 건강 점수나 하트 하나로 환산하지 않는다.

### 6.2 기억과 정보 정정

사건 인지 known/unknown, 사유 인지 known/unknown, 해결 open/resolved는 독립 차원이다. ‘사건은 알고 이유는 모르며 아직 해결되지 않음’이 가능하다. 미인지 사건은 해당 observer의 감정 기여 0이다. 해결 후 기억은 지우지 않는다.

동일 source의 knowledge_revision 정정은 원래 기여 슬롯을 교체하고 checkpoint 이후 순서를 재투영한다. clamp를 고려하며 당시 snapshot·규칙·seed·반복배수를 보존한다. 새로운 행동·보상·푸시를 재실행하지 않는다. 중복 revision/correction_id는 추가 효과 없이 처리하고 payload 충돌·순서 위반은 거절한다. 태그 전체 이력 재구축 범위도 함께 검증한다.

### 6.3 복합 관계

좋아하지만 못 믿음, 싫지만 존중해 협력함, 의존하지만 갈등함, 회복 후 거리두기 등 복합 상태를 지원한다. 태그는 설명용이며 행동·동의·권한을 자동 확정하지 않는다.

기존 v0.1 태그 기준을 유지하고 rel_tags_exp_v03 실험은 분리한다. 감정 기반 전환은 서로 다른 유효 source 2회 연속 및 해당 태그 조건, ‘편안한 친구’는 긍정 사건 3회 조건도 검증한다. 역할 종료·동의 철회 등 즉시 해제는 별도다. 세부 임계표는 기준 원본/definition_version을 참조하고 새 값을 임의로 출시하지 않는다.

## 7. 첫 관계 서사: 정연우 v0.6.1 반영

### STORY-A: 접근·거절·여건 변화·협력

A가 접근하지만 B가 바쁘거나 피곤해 거절한다. 거절 자체의 관계 효과는 0이고 양쪽은 다른 활동을 이어간다. B가 쉬어 상태가 달라진 뒤 새로 평가해 수락할 수 있다. 실제 완료·인지된 협력만 원장에 반영한다. 재접근 끝에 반드시 수락하도록 강제하지 않는다.

### STORY-B: 관계가 다른 협력

같은 성격·능력·공간·seed에서 관계를 바꾸어 비교한다. 낮은 애정/높은 존중은 공동 목표가 있으면 협력 가능해야 한다. 높은 애정/낮은 신뢰는 친밀 접근과 중요한 위임을 구분해야 한다. 후보 자격·상대 반응·선택 이유를 검증하고 항상 같은 특정 행동을 고르도록 요구하지 않는다. 실제 위임 기능이 미구현이면 차이를 검증할 최소 행동 계약과 미완료 범위를 명시한다.

### STORY-C: 공로 불일치·정정·복구/거리두기

**첫 신규 갈등 범위는 같은 소유자의 폰 사이 가벼운 공동작업의 공로 기록 불일치로 수용한다.** 자율 장기 약속·재화 이전·타 소유자 책임 변경·공개 관계 선언을 함께 추가하지 않는다.

실제 공동작업 수락/완료 → 기여 기록·합의한 표시 기준 → 게시 결과 불일치 → observer별 인지 → 사유 확인 또는 미확인 → 기록 정정·전달 → 별도 복구 실행 또는 거리두기를 연결한다. 불일치는 악의 증거가 아니다. 근거 없이 숨겨진 고의 사건을 만들어 내지 않는다.

최소 증거는 joint_work_id, contribution_refs, attribution_rule_id, published_credit_refs, source_event_id/observer/knowledge_revision, correction_action_id/수신 인지, conflict_id/topic/scope, repair_plan_id/실행·수용 근거다. 필드명은 실제 스키마와 정합시킨다.

EVT07 정보 정정과 EVT08 독립 행동, EVT09 정정 전달과 EVT12 실질 복구를 구분한다. EVT08/10은 독립적 고의 증거 없으면 발화하지 않는다. EVT09는 실제 정정 반영과 수신 인지, EVT12는 별도 계획의 필요한 수용·실행 근거가 있어야 한다. 같은 증거를 이중 긍정 효과에 쓰지 않는다. 정정·사과·선물만으로 모든 갈등 해소나 친밀 회복을 강제하지 않는다. 해당 scope만 변경하고 기억 및 다른 갈등은 보존한다.

## 8. 친구 방문·동의·공개 정보

실제 방문 흐름은 초대 → 소유자 수락 → 호스트 공간 접근 확인 → 폰 입장 → 허용 활동 → 퇴장/철회/단절 → 재접속 또는 종료다. 초대 만료·차단·접근 철회·중복 입장도 처리한다. 구체적인 온라인 만료시간·시계·권위 호스트 이탈 정책은 설계 후 결정한다.

동의 canonical은 activity_participation, light_auto_events, role_commitment, public_relation_declaration, major_transition이다. 로컬 방문 대역은 첫 2scope만 사용하고 나머지 3scope는 비허용으로 유지한다. legacy alias는 명시적 문서 import에서만 취급하고 wire에서 자동 수용하지 않는다.

호스트는 공간 접근을, 소유자는 자기 폰의 참여 범위를 관리한다. 기능 거절·철회·단절·기술 중단은 감정 벌점·배신 기억을 만들지 않는다. 폰의 기본 자율 거절도 0효과다. 독립적 유해 행동이 발생했다면 그 근거만 별도 사건으로 평가한다.

자기 소유 폰끼리는 방향 전환 상세 조회 가능. 다른 소유 폰의 성격·역방향 수치·사적 기억·내부 태그·비공개 revision·후보 가중치/seed/trace는 응답·추천·대사·알림에서 제외한다. 서버 공개 allowlist를 사용하며 브라우저에 받은 비밀을 화면에서 숨기는 방식으로 대체하지 않는다. 로컬 대역에는 ‘로컬 방문 데모’를 표시한다.

## 9. 화면과 아트 제작

| 화면 | 핵심 기능 |
|---|---|
| 폰 제작 | 빈 원·그리기·6슬롯·undo/redo·초안·저장 |
| 성격 선택 | 3축·6프리셋·직접 수정·무작위·경향 설명 |
| 월드 | 공간·생활·일시정지/속도·폰 선택·환경 편집 |
| 폰 관찰 | 행동/공개 표면 이유/필요 → 아는 기억 → 자기 방향 관계 |
| 관계 상세 | 8축·근거·복합 태그·기억 3차원·방향 |
| 방문 관리 | 소유자 구분·허용 범위·입퇴장·중립 단절 표시 |
| 저장/설정 | 로컬 상태·실패/복구·공개/참여 설정 |

짧은 행동 표시와 경량 일지를 중심으로 하고 인사마다 긴 팝업을 띄우지 않는다. 접근에는 점수 상승 연출 없음, 바빠서 거절은 싫어함으로 단정하지 않음, 도움은 자동 의무 없음, 길막은 중립, 공로 불일치는 사유 미확인, 정정과 실질 회복은 분리해 표시한다. 색만으로 상태를 구분하지 않고 작은 크기 얼굴·배경 대비·가림·모션 fallback을 검수한다.

## 10. 개발 구성·데이터·저장

기존 저장소와 계약을 재사용하고 전면 재작성 여부는 근거 없이 결정하지 않는다. 구현 언어·엔진의 새 지정은 하지 않는다. 책임 경계는 다음과 같다.

- 폰/외형/성격: pawn_id·소유자·appearance/profile 버전·적용 시점.
- 월드/배치: world_id·grid·가구·점유·활동 지점·배치 버전.
- 시뮬레이션: tick·seed·현재 욕구/행동·후보 평가·경로·수락/완료.
- 관계 원장: action/source/observer·인지 revision·기여·checkpoint·해석 snapshot.
- 관계 원천: ResourceLink·DecisionRole·acceptedCommitment·Conflict 및 근거.
- 태그/공개 projection: 버전된 판정과 소유·권한에 따른 허용 정보.
- 방문: 소유·접근·동의 scope·present/connected·만료/철회.
- 저장: command_id·expected version·원자 commit·재전송·실패 복구.

로컬 폰 최종 생성은 외형·성격·로컬 소유 식별을 함께 확정한다. 로컬 복구는 운영 계정 복구가 아니다. 로그인 없이 시작하는 UX는 후보 방향이며 실제 온라인에서 익명 식별·복구·삭제·소유권 정책을 명시한다. 로그인 없음과 인증/권한 검증 없음은 같은 뜻이 아니다.

온라인 전에는 서버 권위 tick·트랜잭션·멱등성·공개 snapshot·채널 권한·철회 캐시 무효화·호스트 이탈을 설계한다. 공유 서비스의 다른 게임 데이터와 격리한다. 현재 계획서는 운영 Auth/DB/Edge 변경·배포 승인을 포함하지 않는다. 구체적 변경/접근 정책/복구안을 제시하고 별도 결정 후 실행한다.

## 11. 현재 상태: 보고와 검증 구분

김도현 보고: 로컬 폰 3명 자율 생활, 공간 영향, pause/속도/저장 복구, 로컬 방문 대역, 6슬롯·외형 수정 연결. Node 114개 통과(신규 15, 기존 99), 대표 브라우저 화면 확인. 전체 AUTO22·DQA14·새 갈등 생성·태그 전체 이력 재구축·축소/가림 QA·실제 온라인은 완료되지 않았다. 타입검사/원격 CI는 최신 상태 증거를 제출한다.

총괄이 과거 재실행한 20개 계약/원장 시험은 그때의 제한된 결과다. 이번 114개 또는 브라우저 검증을 독립 재현했다고 주장하지 않는다. 정연우 v0.6.1도 보고 기반 검토다. 증거대조표 22건 전부 exact_AUTO_case_executed=false 및 결과 미제출이며, 관련 동작 보고/부분 보고는 합격이 아니다.

새 디자인 원본이 없다는 이유로 기존 수령 6슬롯을 다시 요청하지 않는다. 기존 자산을 재사용하고 공간 분리 자산 및 실제 필요한 신규 항목을 구체적으로 요청한다. 이전 3라운드 공방/27경로는 회귀 검사로 보존하되 중심 화면으로 복원하지 않는다.

## 13. 검증·납품 규칙

정연우 AUTO-01~22와 신규 15검사를 정확히 매핑하고 누락을 실행한다. 개별 항목마다 fixture/버전·seed·초기 월드/성격/관계·코드경로 또는 commit·환경·명령·기대/실제 출력·pass/fail/partial/blocked/not_run을 제출한다. 우선 반례는 AUTO08/11 복합 관계, AUTO12 공로 의도 미확인, AUTO15/16/22 회복·거리두기, AUTO19/20/21 복구·방문·비공개다. 성격 27조합과 과거 공방 27경로는 별도 시험군이다.

필수 통합 시험: autonomy → event ledger → known memory → directed 8 axes → save → reload. 완료 action/source·observer·scope·기여·commit을 추적한다. 동일 요청 재전송·정정·복구에서 사건/효과 중복 없음, 저장 실패 원본 유지, 미인지0효과, 다른 갈등 영향0, 태그 이력 재구축을 검증한다.

사용자 납품은 실행 가능한 시제품/주소와 실행 방법, 폰 제작·환경 편집·관찰 안내, 재현 환경, 실제 결과 파일 및 화면 기록, 알려진 문제를 포함한다. 내부 검사 trace는 공개 UI와 구분하고 비공개 데이터를 일반 로그로 유출하지 않는다. 외부 보상/푸시 어댑터가 없는 모델의 reexecutions=0은 실지급 안전성 증거가 아니다.

시제품 체험 가능, G-A-REL 관계 통과, 실제 친구 방문 통과, 운영 출시 가능은 서로 다른 판정이다. 문서·단위테스트 숫자만으로 전체 완료를 선언하지 않는다.

## 14. 담당·다음 회신

김도현은 구현·통합·실행본·기술 증거·작업량을 담당한다. 김디자인은 공간/화면/원본 자산·축소/가림·실제 화면 검수를 담당한다. 정연우는 행동·사건·인지·복합 관계·증거 계약·AUTO 기대값 및 실제 결과 검수를 담당한다. 김PO는 범위·결정·우선순위·게이트 수용을 맡고 별도 중복 구현하지 않는다.

김도현 다음 회신 요청:
