## 1. 수신과 검증 수준

이번 ZIP은 김시스템 회신만 포함한다. PLAY-PROP-001 및 콘텐츠 PLAY-C01~06은 미수령이므로 콘텐츠 2개 선정과 SYS-C01/02 규칙화는 대기한다. 제출된 빈 템플릿을 완성 카드로 취급하지 않는다.

김시스템은 별도 소스 ZIP을 정적으로 대조했다고 보고했다. 이번 김PO 검토는 외주 회신 문서와 JSON을 읽은 것이며 해당 소스 ZIP·현 최신 commit을 독립 대조하지 않았다. 코드 차이에 대한 발견은 기술 검수 요청의 근거다. 설계 fixture는 not_run, production_import_allowed=false, relation/tech review pending이며 통과 결과가 아니다.

## 3. 추가 정의가 필요한 중요한 차이

### 미인지 완료와 반복 횟수

제안에는 ‘실제 효과 적용 횟수’와 ‘unknown 완료도 당시 반복 판정 보존’이 함께 있다. 미인지 방향에서 점수는 0인데 quota를 예약하는지, 실제 known 효과만 count하는지 명확하지 않다. 동결과 뒤늦은 인지 때문에 같은 과거 Day의 유효 기여가 상한을 초과하지 않는지 검증해야 한다. 상호 인사에서 한 당사자만 미인지인 상황도 가능한지 사건 유형별로 설명한다. 김시스템은 선택지·반례를 제시하고 정연우가 의미를, 김도현이 구현을 검수한다. 카운터나 원장 정책을 이 문서에서 임의 확정하지 않는다.

### 중립 완료와 기억

활동의 완료 사실·불변 action/source·당시 반복 제한 사유는 남겨야 한다. 관계 긍정 기여·긍정 태그 횟수에는 넣지 않는다. 이를 기억에 노출하는 범위·보존 기간·정정 가능성은 관계 검수 후 결정한다. 기존 120건 생활 로그에만 의존하면 오래된 완료/정정·중복 검증 근거가 사라질 수 있으므로 별도 안정 기록안에 필요 보존 정보를 명시한다. 모든 기록을 무제한 보관하라는 지시는 아니다.

## 4. 시험 ID 불일치 보완 요청

SYS-PROP-001 3.6절은 SYS-FX-01~10이지만 JSON은 SYS-FX-01~08이다. 특히 동일 ID의 의미가 다르다.

| ID | MD | JSON |
|---|---|---|
| SYS-FX-05 | 양방향 인지·효과 | 동일 완료 재전송 |
| SYS-FX-07 | 재전송·저장 실패·다중 탭 | 저장 실패 |
| SYS-FX-08 | 상한 이후 정정·다른 종류 | 과거 지식 정정 |

MD의 09/10은 JSON에 없다. 새 v1.1에서 ID별 시나리오를 일치시키고 삭제/이동된 항목은 대응표를 남긴다. 기존 JSON 05의 재전송도 누락하지 않는다. 시험 입력에 방향·Day·tick·간격·상한·known 상태·source를 넣고, 카운터/관계/긍정 태그/활동 기록/저장 전후의 기대값을 구체화한다. 미실행 상태는 유지하며 설계 문서 수정만으로 pass로 올리지 않는다.

## 5. 다음 회신

김시스템은 SYS-PROP-001 v1.1로 위 모순과 시험 ID를 보완한다. 김PO가 김도현·정연우의 검수 결과를 모아 규칙을 확정한 뒤 A2 세부기획에 반영한다. 김플레이 회신 수령 후 콘텐츠 후보 최대 2개를 선정하여 SYS-C01/02의 실제 규칙화를 별도로 요청한다. 현재 A1 공간 제작은 계속 진행한다.
