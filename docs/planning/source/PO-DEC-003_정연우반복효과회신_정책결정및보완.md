- 상태: 관계 의미 검토 수용·정책 결정. 코드 적용·시험 통과·외부 발송 완료 아님.

## 1. 수신 범위

이번 ZIP에는 정연우 회신만 있다. 김시스템 SYS-PROP-001 v1.1 및 김플레이 PLAY-PROP-001은 이번 자료에 포함되지 않았다. 기존 김시스템 v1.0 검토와 이번 관계 자문을 연결하되 다른 외주의 보완 완료로 기록하지 않는다.

정연우도 최신 소스·DEV-19 전문·실제 시험 출력을 확인하지 않았다고 명시했다. 관계 의미 수용과 실제 구현 통과는 구분한다. JSON의 not_run 및 production_import_allowed=false는 유지한다.

## 2. 승인 요청 2건의 결정

### 2.1 미인지 사건의 당시 기회 예약: 원칙 채택, 기술 검수 조건

관계 후보로 적법한 완료 사건이라면 방향별 효과 자격을 원래 순서·Day·tick에서 판정하고 보존한다. 미인지 방향도 당시 자격을 예약·동결하여, 뒤늦은 인지로 과거 상한을 재배정하거나 오늘의 효과 기회를 새로 쓰지 않는다. 미인지 때 감정 기여는 0이며 실제 인지 revision이 생겨야 원슬롯에 투영한다.

이는 실제 표시 점수 증가 횟수가 아닌 **유효 효과 기회 횟수**를 제한하는 계약이다. 변수명·문서에도 이를 구분한다. last_granted_effect_tick은 원래 자격 부여 tick이며 뒤늦게 알게 된 tick이 아니다. Day 변경·인지 취소·재인지·clamp로 quota를 환급하거나 재지급하지 않는다.

현재 자료만으로 구현 가능성을 확정하지 않는다. 김도현은 저장·정정·멱등성·마이그레이션·성능 영향을 검수하고 적합한 구현안을 제출한다. 구현이 어렵다면 조용히 ‘실제 점수 증가 횟수’로 바꾸지 말고 대안과 체험 영향을 김PO에게 올린다.

직접 대면 인사는 한 당사자가 인사 자체를 전혀 모르는 시험을 만들지 않는다. 비대칭 인지는 실제 인지 차이가 가능한 도움/기여 발견 등 사건으로 검증하며 사건 정의의 observer/target 방향을 명시한다.

### 2.2 0기여 원장 통합: A2 보류, 최소 호환안 채택

상한/간격 때문에 효과 0인 새로운 완료 인사·대화는 안정적인 neutral_activity_history로 보존하고 기존 EVT-01 감정 기여 원장에는 넣지 않는다. repeat_multiplier=0 우회는 금지한다. 기존 120건 표시 로그만으로 근거 보존을 대체하지 않는다.

반대로 **당시 효과 자격은 있었지만 아직 미인지인 사건**은 상한 때문에 중립인 사건과 다르다. 이후 인지 재투영을 위해 원 source 및 방향별 자격·snapshot·순서를 보존해야 한다. 김도현은 이 두 상태를 같은 ‘원장 미삽입 중립’ 분기로 합치지 않는 저장안을 제출한다. 두 방향 중 한쪽만 자격을 얻은 물리 행동도 한 번의 완료 사실을 공유하고 방향 상태를 따로 유지한다.

영구적인 모든 원시 기록 보관을 강제하는 결정은 아니다. 중복·과거 정정·태그 replay에 필요한 참조/기회 snapshot의 보존·압축/삭제 조건은 기술안과 함께 확정한다.

## 3. 함께 확정할 의미

- 물리 완료 1건과 방향별 관계 투영은 별개. 공유 효과 상한으로 방향 차이를 지우지 않는다.
- Day는 PO-DEC-002 A안 유지: index=floor((480+tick)/1440), UI Day=index+1. 첫 전환 tick960. 완료 확정 tick으로 집계하고 Day를 넘어 최소 효과 간격을 유지한다.
- 인사·가벼운 잡담은 light_social 효과군으로 묶는 방향을 수용한다. stable scope는 가구 위치/ID로 바꾸지 않아 배치 변경으로 상한을 우회할 수 없어야 한다.
- minor_help는 별도 후보다. 모든 기존 도움을 자동으로 새 상한에 넣지 않는다. 사건 정의별 매핑·수치·중요한 도움과 복구의 구분은 김시스템/정연우/김도현 검수 후 확정한다.
- 35tick 접근, 60tick 효과 간격, 3회 상한은 A2 시험값이다. 물리 접근 제한·효과 자격 제한은 분리한다.
- 상한/간격으로 자격이 없는 완료는 긍정 태그 근거 제외. 여러 축이 바뀌어도 source는 하나이며 revision도 신규 source가 아니다.
- 유효한 긍정 사건이 clamp 때문에 표시 변화 0인 경우는 상한 중립과 구분한다. 기존 태그 정의가 허용하는 긍정 근거 자격을 적용하며 ‘표시 delta>0’만으로 판정하지 않는다.
- 갈등·정정·복구는 인사 상한 비대상이나 독립 증거·멱등성 유지. 기능 철회·단절·정중한 거절은 기본 벌점 0이다.

## 4. REL-SYS fixture 보완 요청

### 시계 불일치

REL-SYS-02의 tick990/1000/1050은 A안에서 모두 day_index=1(UI Day2)이다. 제시된 Day1→Day2 경계가 아니다. 통합 검사에는 다음 값을 사용하도록 수정 요청한다.

| 완료 tick | day_index / UI | 전제 | 기대 |
|---|---|---|---|
| 950 | 0 / Day1 | 유효 light_social 완료·인지, 당일 기회 있음 | 효과 자격 및 기존 인사 정의의 +4 |
| 960 | 1 / Day2 | 별도 실제 완료, 새 Day quota 있으나 간격10 | 자격 없음·효과0·중립 기록, 새 Day count0 |
| 1010 | 1 / Day2 | 별도 실제 완료·인지·자격·쿨다운 충족, 간격60 | 자격 및 +4, 새 Day count1 |

950→960은 접근 간격35보다 짧아 실제 자율 행동으로 새 인사가 완료될 수 있는지는 별도다. 따라서 위 표는 반복 판정 단위시험으로 분리하고, 전체 생활 통합시험은 실제 접근/활동 시간을 충족하는 경계 사례를 김도현이 구성한다. 불가능한 생활 입력을 전체 통합 통과로 표시하지 않는다.

REL-SYS-01의 tick100/170/240/310은 A안 day_index=0이다. JSON의 day_index=1과 불일치하므로 0으로 맞추거나 ‘합성 시계의 독립 단위시험’이라고 명시한다. Day1 count는 삭제/0으로 재설정하는 것이 아니라 과거 이력을 보존하고 새 Day bucket을 시작하는 뜻으로 문구를 수정한다.

### 인지와 원슬롯

REL-SYS-03은 도움 행위자/수혜자/observer/target, 실제 완료·기여 근거·사건 definition_version·scope와 방향별 expected 기여를 구체화한다. ‘A는 알고 B는 모름’만으로 양쪽 정서 기여가 유효한 사건이라고 가정하지 않는다. 아직 해당 이벤트 정의가 없으면 설계 미완료/blocked로 표시한다.

REL-SYS-04는 시험 시작 전에 unknown 원 source가 이미 존재하는지와 0→1 revision의 최초 등록/정정 차이를 명시한다. ‘새 긍정 source ID0’은 독립 source를 추가하지 않는다는 의미다. 같은 기존 source의 긍정 자격 false→true로 태그 결과가 바뀔 수 있으므로 긍정 근거 총수가 항상 불변이라는 뜻으로 해석하지 않는다. 기대 태그 이력도 초기 상태와 사건 순서에 맞춰 구체화한다.

추가 반례: 미인지 자격을 예약한 3건 후 4번째 완료와 뒤늦은 인지, 인지 known→unknown→known에서 quota 불변, clamp 상한의 긍정 자격, 같은 action 재전송, 저장 실패의 전체 롤백. fixture는 v1.1로 수정하고 실제 출력 전에는 not_run을 유지한다.
