# 《동그란 사이》 개발자용 PRD

- 패키지 버전: 0.2 / 2026-10-12 / 기술 설계·견적 검토용
- 총괄: 김PO 역할. 김디자인 역할과 화면 계약 협의, 정연우 역할의 관계 자문 반영.
- 원본: `동그란_사이_PRD_v0.1.md`. 원본을 보존하고 이 문서의 보완 규칙을 새 패키지에 적용한다.
- 실제 인물의 참여나 검증을 뜻하지 않는다. 모든 초기 수치·정원·구현 방식은 **제안**, 사용자 확정 요구는 원형 파츠 얼굴·개인 월드·친구 초대·광장·목적별 맵·다양한 관계·8축 1~1000이다.
- 플랫폼·엔진·DB·인증·호스팅은 미정이다. 아래는 제품 독립적인 논리 계약이며 특정 서비스를 전제하지 않는다.

## 1. 구현 범위와 승인 게이트

| 단계 | 제공 범위 | 완료 판단 |
|---|---|---|
| A 관계 시제품 | 얼굴 편집, 자기 폰 3명, 개인 월드, 공동 공방, 사건·기억·8축·복합 태그 | 얼굴→활동→사건→관계 변화→다음 행동의 한 흐름과 아래 A 검증 통과 |
| B 소셜 알파 | 지속 관계, 친구 초대, 광장, 공방 공동 참여, 소유권·동의·차단·신고·복구 | 사용자 전체 요구 U-01~08 및 B 검증 통과 |
| 이후 | 목적 맵 추가, 파츠 공유, 집단 관계 | 별도 범위·비용 검토 |

A만 완성하고 전체 제품 완료로 선언하지 않는다. A 폰 3명/B 사용자당 8명, 개인 월드 4사용자, 광장 16사용자, 공방 2~4폰은 성능 검증 전 제안 정원이다. 자유 채팅·전투·개방 경제·생성형 대화·사용자 스크립트 맵은 초기 제외 제안이다. 목표 연령·로맨스는 콘텐츠 제작 전에 결정한다.

## 2. 모듈과 책임 경계

| 모듈 | 책임 | 입력/출력 경계 |
|---|---|---|
| 얼굴 편집·합성 | 파츠 원본, 변환, 표정, 미리보기, 초안 복구 | AppearanceDraft→검증된 immutable AppearanceVersion |
| 생활·행동 | 욕구·성향·이동·행동 후보 | 허용된 후보만 선택, 사건 발생 의도를 권위자에게 제출 |
| 월드·인스턴스 | 레이아웃, 경로, 정원, 위치, 활성 시계 | 동일 pawn_id의 동시 위치 금지 |
| 활동·약속 | 참가 수락, 역할, 작업·중단, 약속 상태 | 수락 전 역할 의무를 활성화하지 않음 |
| 관계 엔진 | 방향별 해석, 감정 기여, 파생축, 기억·태그 | deterministic reducer, 클라이언트 delta 입력 금지 |
| 공개 projection | 소유권별 수치·기억·태그 필터 | 모든 조회·푸시·알림·미리보기에 같은 정책 |
| 소셜·권한 | 친구, 초대, 차단, 승인, 신고 | 관계 점수보다 권한이 우선 |
| 영속·동기화 | 명령 중복 방지, 트랜잭션, 순번, 재접속 | commit 이후에만 결과 전송 |

A는 단일 실행 권위자를 사용해도 되지만 B와 동일 사건·명령 모델을 유지한다. B는 관계·소유권·활동·보상·위치의 서버 판정이 필수다. 같은 폰의 얼굴 수정이나 대표 폰 변경으로 관계를 새로 만들지 않는다.

## 3. 관계 데이터와 방향 규칙

Relationship의 유일 키는 `(from_pawn_id,to_pawn_id)`이며 자기 자신은 금지한다. 실제 만남에서 양방향 생성은 원자적으로 처리한다. 값은 모두 정수 1~1000, 처음 만남의 제안값은 애정100/신뢰300/존중300/의존1/권력500/호혜성500/의무1/갈등1이다.

| 축 | A→B 데이터 근거 | 갱신 |
|---|---|---|
| 애정·신뢰·존중·호혜성 | A가 알고 해석한 B의 사건 | 사건별 감정 기여와 성향 배수 |
| 의존 | A=수신자, B=제공자 자원·역할 연결 | importance×B의 기여비중×대체곤란도 합을 [0,1] 제한, `1+round(999×합)` |
| 권력 | A가 B와 함께하는 활동에서 가진 결정 지분 | pair별 유효 활동의 중요도 가중 평균, `1+round(999×평균)` |
| 의무 | 책임을 수락한 A, 그 책임 상대 B | 활성 수락 약속·돌봄 책임의 burden 최댓값, 없으면1 |
| 갈등 | A가 B와 느끼는 미해결 주제 | 활성 항목 severity 최댓값, 없으면1 |

권력은 양방향 합을 1000으로 강제하지 않는다. 근거 활동이 없으면 500과 `basis_status=no_active_basis`를 함께 저장하여 중립 관계라는 오해를 막는다. 실제 계정 권한과 무관하다. 의존은 임의로 서로 복제하지 않는다. 공동 의무도 각 책임 수락을 따로 기록한다. 도움받았다는 기억은 자동 채무가 아니다. 수락하지 않은 은혜 기록은 감사 기억만 만든다.

갈등 신규 사건은 사소한 충돌의 증가량 또는 중대 사건의 직접 severity를 정의표에서 지정할 수 있다. 기존 갈등 병합은 `(observer,target,topic,scope_id)`로 제한한다. 다른 활동의 사건을 같은 주제라는 이유만으로 무조건 병합하지 않는다. severity가 1이 되면 일반 갈등은 해결되지만 중대 상처 기억은 약속된 복구 요건이 별도로 필요하다.

태그는 역할·감정·긴장·과거를 중첩한다. 낮은 애정만으로 혐오, 높은 애정만으로 연애를 만들지 않는다. 친구/혐관 등 양방향 판정과 신뢰하는 동료/애증 등 방향 판정을 정의표에서 구분한다. 진입·해제 임계값은 원본 제안표를 출발점으로 사용하되 서로 다른 유효 사건 2회로 평가한다. 동일 틱·재전송·정보 수정 재평가는 새 근거 횟수에 포함하지 않는다. 차단·동의 철회·역할 종료는 즉시 처리한다.

## 4. 사건 처리·버전·정보 수정

### 4.1 정상 처리

1. 명령의 인증·소유권·참가·동의·차단·상태·버전을 검증한다.
2. 권위자가 event_id, instance_sequence, 규칙 버전, 난수 seed, 활성 시점을 부여한다.
3. 폰별 인지 여부를 확인한다. 모르는 사건은 해당 방향에 감정·기억 효과가 없다.
4. 사건 정의의 base_delta×해석배수×반복배수를 `round_half_away_from_zero`로 계산한다.
5. 사건 기여와 구조 변화·기억·약속·갈등을 기록하고 관계 projection을 계산한다.
6. 내부 태그·행동 후보를 평가하고 트랜잭션을 commit한다.
7. 권한별 DTO를 만들어 저장 결과를 전송한다.

동일 선물 반복 제한 제안은 발신·수신·종류·활성일별 1/0.5/0.2/0(4회 이후). 부정 사건·약속 이행에 자동 적용하지 않는다. 반복 순서는 권위자의 처리 순번으로 결정한다.

### 4.2 멱등성과 규칙 버전

- 명령 키 `(actor_user_id,command_id)`에 입력 hash와 원 결과를 보관한다. 동일 키·동일 입력이면 원 결과, 동일 키·다른 입력이면 충돌 오류.
- 최초 효과 키 `(source_event_id,observer_pawn_id,relationship_id,effect_kind)`는 **rule_version을 포함하지 않는다**. 규칙 버전이 바뀌어도 같은 사건을 새로 적용하지 않는다.
- 효과 기록에 실제 사용한 rule_version·해석 입력·기여량을 남긴다. 새 규칙은 새 사건부터 사용한다. 과거 변경이 필요하면 별도 migration_id, 대상 범위, dry run, 복구 절차를 작성한다.
- 정보 수정 키 `(source_event_id,observer_pawn_id,relationship_id,knowledge_revision)`는 증가하는 revision을 쓴다. 같은 revision 재처리는 무효이며 서로 다른 revision도 동일 정보를 근거로 효과를 누적하지 않는다.

### 4.3 뒤늦은 정보의 재해석

클램프된 점수에서 과거 delta를 빼고 새 delta를 더하면 상한·하한에서 잃은 양을 복구하지 못한다. **감정 기여 원장과 순서 있는 replay를 기준값**으로 삼는다.

제안 의미론: 새 정보가 과거 판단을 정정하면 원 사건 슬롯의 기존 유효 기여를 대체하고, 그 사건 직전 checkpoint부터 이후 유효 기여를 순서대로 재투영한다. 각 슬롯에서 1~1000 clamp를 적용한다. 이때 원 사건 당시 규칙 버전과 저장된 해석 입력을 사용하고 새 정보만 대체한다. 증거 없이 기존 seed·성향·반복배수를 다시 추첨하지 않는다.

예: 시작990, 원 효과+30, 후속-20이면 현재980. 원 효과가+10으로 정정돼도 replay 결과는980이다. 현재값에 -20을 더해960으로 만드는 단순 차분은 잘못이다. 사용자에게는 수정 전/후 실제 projection 차이를 보여준다. 새 발견 자체의 감정이 필요하면 사건 정의에 별도 `discovery_effect`를 명시하고 별도 키로 한 번만 적용한다.

의도적인 거짓말 발견처럼 기존 약속·갈등 상태를 바꾸는 정정은 원 구조를 되감아 중복 생성하지 않는다. 지식 revision을 참조하는 명시적 상태 전이로 처리하고 기억에는 최초 해석과 정정 이력을 연결한다. 새 지식 없이 재조회하는 행위는 관계 사건이 아니다.

## 5. 논리 스키마·영속성

| 엔터티 | 주요 추가 필드/제약 |
|---|---|
| Pawn, AppearanceVersion | owner_id, 영속 pawn_id, immutable 외형 버전, 체크섬, 파츠·표정 원본 |
| Relationship | 방향 유일키, 8 scores, revision, basis_status, projection_version |
| Event | source_event_id, instance_sequence, rule_version, seed, clock_id, active_tick, payload_hash |
| EventKnowledge | observer_id, revision, learned_at, known_facts, parent_revision |
| EffectLedger | 최초효과 유일키, knowledge_revision, contribution, applied_rule_version, supersedes_ref |
| RelationshipCheckpoint | relationship_id, ledger_sequence, state, 규칙/스키마 버전; 정정 슬롯 이후 checkpoint 무효화 |
| Memory, Conflict | owner/observer, target, visibility, source refs, topic/scope, severity, resolution_requirements |
| Commitment | issuer, accepter, beneficiary, clock_id, due_tick, accepted_at, burden, state |
| ResourceLink, DecisionRole | 방향 근거·활동 범위·중요도·기여지분·대체곤란도 |
| Consent | consent_id, scope, participants, version, expires_at_utc, state |
| CommandReceipt, Outbox | command_id/input_hash/result; commit된 푸시와 전송 상태 |

관계·기억·갈등·약속·보상·처리 receipt·outbox는 동일 작업의 원자적 commit 범위다. 재시도 시 일부 효과만 두 번 반영되지 않는다. 여러 관계에 영향 주는 사건은 고정된 ID 순서로 잠그거나 동등한 낙관 충돌 재시도를 사용한다. 관계 revision CAS를 실패하면 최신 상태에서 동일 명령을 재평가하되 ID·seed는 유지한다. 클라이언트의 expected_version 충돌은 자동 덮어쓰지 않는다.

폰의 현재 인스턴스는 원자적 위치 예약으로 정한다. 이동 시 이전 위치 해제·새 위치 획득이 함께 확정되어야 한다. 정원 검사는 참가 승인과 동시에 실행한다. 차단·동의 철회와 명령은 같은 권위 순서로 직렬화하며 차단 commit 이후 이벤트는 생성하지 않는다. 이미 commit된 과거 이벤트는 새로 적용되지 않으며 알림은 현재 권한으로 다시 필터한다.

## 6. 시계·중단·복구

- 사건 순서는 instance_sequence가 기준이고 클라이언트 시각은 판단 근거가 아니다.
- 활성 플레이20분=게임1일은 제안. clock_id별 active_tick/day를 저장한다. 개인 월드 비활성·일시정지 때 시계 정지, 공유 인스턴스는 권위 시계 사용.
- 약속 due_tick은 생성 clock_id에 고정한다. 인스턴스를 옮겨도 기한을 새 시계로 바꾸지 않는다. 소속 시계가 정지한 동안 불이행 없음.
- 동의 만료24시간과 재접속 유예60초는 제안 실제 시간. UTC 서버 시각으로 처리하고 UI 지역 시간 표시와 분리한다.
- 연결 끊김은 기술 중단으로 표시한다. 새 중대 사건을 시작하지 않고 유예 후 활동 저장·중단; 관계 벌점·배신 기억 없음.
- 마지막 cursor는 스트림 ID+sequence 조합. 재접속은 스냅샷 revision과 cursor를 함께 받거나 권한 필터한 후속 이벤트를 받는다. cursor 범위 만료는 스냅샷 복구로 처리한다.
- 얼굴 초안 로컬 저장, 확정 외형은 성공한 버전만 활성화한다. 두 기기 월드 편집은 writer lease를 가진 한 세션만 가능하며 lease 만료·전환 안내를 제공한다.

## 7. 김디자인과 합의한 화면/API 계약

운송은 HTTP/소켓/RPC 미정. 공통 명령: `command_id, expected_version, payload`; 결과: `command_id,status,entity_version,event_id,event_sequence,reason_key,retryable`. request_id라는 기존 이름은 command_id와 동일 의미로 매핑하며 consent_id와 혼용하지 않는다. 오류는 복구 방법을 제공하되 상대 차단·사적 상태를 설명하지 않는다.

| 화면 | 조회/명령 | 핵심 계약 |
|---|---|---|
| SCR-01 얼굴 | GetAppearance/SaveAppearance | 레이어 원본·변환·외형 버전·검증 결과; draft 유지 |
| SCR-02 월드 | GetWorld/SaveLayout/EnterInstance/InviteFriend | layout_version, 권한, clock, 이동·설치 가능 상태 |
| SCR-03 폰 상세 | GetPawn/SetRepresentative | 공개 외형·이름과 소유자 전용 성향·욕구 분리 |
| SCR-04 관계 | GetRelationshipProjection | direction,visibility,8축(허용된 경우),basis_status,공개 가능한 태그·기억·약속 |
| SCR-05 광장 | ListNearby/ProposeActivity/BlockUser/Report | 주변 폰 공개 요약, 제안 상태, 일반 오류 |
| SCR-06 공방 | GetActivity/SubmitAction/RespondConsent/Leave | 목표·역할·진행·수락 여부·선택 비용·예상 방향·불확실성 |
| SCR-07 결과 | GetEventResult | 이전/이후 공개 점수·실제 차이·안전한 reason_key·남은 문제 |
| SCR-08 설정 | GetSettings/UpdateSettings | 방문/자율 활동/중대 사건 범위, 버전, 철회 결과 |

얼굴 제안 규격은 파츠당512×512 투명 캔버스, 중심 pivot(0.5,0.5), 정규화 위치·크기·회전. 순서는 뒷머리→베이스→눈→입→앞머리→프레임. 엔진 좌표 변환은 어댑터에서 하고 저장 규격은 일관되게 유지한다. 프레임 의미·픽셀 스타일·월드 표시 크기는 디자인 시안으로 결정한다.

저장 상태는 idle/dirty/saving/saved/error/conflict. 공통 화면 상태와의 대응은 아래와 같다. 충돌 시 자기 초안을 보존하고 최신본 확인 및 명시 재적용을 제공한다. `saved`는 서버 commit 확인 후 표시한다. 선택 preview는 확정 숫자를 보장하지 않고 알려진 조건에 따른 방향·불확실성만 제공한다. UI는 event_id+sequence로 결과 연출을 한 번만 재생한다. 복구 이벤트는 목록에 남기되 과거 연출을 다시 자동 재생하지 않는다.

| 공통 상태 | 구현 상태 | 의미 |
|---|---|---|
| draft | idle 또는 dirty | 아직 확정하지 않은 초안; dirty면 수정됨 |
| saving | saving | 확정 저장 요청 처리 중 |
| saved | saved | commit 확인 완료 |
| failed | error | 저장 실패, 초안 유지 및 재시도 가능 |
| conflict | conflict | 최신 버전과 충돌, 명시 재적용 필요 |

### 7.1 공개 projection의 필수 제한

자기 소유 폰→상대는 정확 점수·자기 기억을 볼 수 있다. 두 폰 모두 자기 소유면 양방향 상세 가능하다. 상대 소유 폰→자기는 별도 공개 동의 없는 한 전환 버튼을 숨기고 정상 관계 응답에 해당 방향 필드를 제공하지 않는다. 임의 조회 시에는 안전한 접근제한 응답 `visibility=restricted,scores=null`만 반환하고 사적 기억·갈등·약속·태그 필드는 전달하지 않는다. UI 문구는 ‘공개된 정보가 없습니다’이다. restricted는 관계 존재 여부나 상대 감정·차단 여부를 설명하지 않는 일반 접근제한 상태다.

양방향 임계값을 이용한 친구·혐관 태그는 비공개 반대 방향 수치를 추론시키므로 상호 공개 동의가 없으면 외부 DTO에서 제외한다. 자기 방향의 ‘나는 이 상대를 신뢰함’ 같은 표현만 가능하다. 내부 행동 엔진은 전체 상태를 쓰더라도 행동 이유를 UI에 그대로 보내지 않는다. 상대 감정은 관찰 가능한 행동으로만 추측할 수 있다.

이 정책은 조회뿐 아니라 사건 결과, preview, 푸시, 알림, 참가자 목록, 공개 타임라인, 분석 로그에도 적용한다. 상대 asset 편집 원본은 비공개이며 표시용 합성 이미지도 공개 범위를 검사한다. 탈퇴·폰 삭제·보존 기간·운영 접근 정책은 외부 알파 전 확정하며 식별 원문을 분석 이벤트에 넣지 않는다.

## 8. 사건 콘텐츠 계약과 자문 반영

EventDefinition은 `id,version,conditions,knowledge_conditions,interpretation_branches,emotion_contributions,structural_transitions,memory_keys,conflict_rules,consent_requirements,dialogue_keys`를 갖는다. 기획 데이터 변경은 버전 생성과 검증을 거쳐 배포한다.

초기 사건은 인사/식사/선물/원하는 도움/원치 않은 도움/약속 이행/지연/은폐 불이행/공로 인정/공로 독점/사과/복구 이행의12종 제안. 지연 시 존중+15는 고정 보상이 아니다. 책임 있는 사전 고지로 해석하는 분기에만 적용하고 악화 없음·불신 분기를 함께 정의한다. 사과 자체가 갈등을 삭제하지 않는다. 감사와 의무 수락은 별개다. 평범한 충돌·중대 배신의 severity와 복구 요건을 분리한다.

## 9. 구현 순서와 인수 검증

## 10. 인계 산출물과 미결정

개발 납품: 실행 빌드·소스·빌드 안내, 데이터/사건 스키마, API 계약, 규칙 버전/마이그레이션 안내, 테스트 결과, 오류·복구·운영 안내, 알려진 문제. 디자인 납품과 동기화할 항목은 파츠 규격·피벗·표정 fallback·화면 상태·reason_key·공개 정책이다.

착수 전 플랫폼/엔진/시점/기준 기기/프레임 의미/직접 조작 범위, 콘텐츠 전 목표 연령·로맨스 범위, B 외부 배포 전 인증·삭제·보존·신고 운영을 결정한다. 정원·사건 수치·반복배수·태그 임계값·시간 비율은 A 관찰과 B 부하 검증 후 조정한다. 변경은 요구 ID·화면 ID·계약·사건 버전·인수 테스트를 함께 갱신하고 김PO가 두 문서의 차이를 관리한다.
