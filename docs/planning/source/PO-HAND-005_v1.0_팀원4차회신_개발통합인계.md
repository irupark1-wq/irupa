## 3. 김도현 구현 항목

### A. 수락과 후보 다양성

ACCEPT-01~06 및 AUTO11/16/22를 사용한다. 낮은애정/높은존중 협력, 높은애정/낮은신뢰 잡담과 중요한위임 차이, 높은신뢰라도 비공개/권한없음 거절, 높은존중이라도 피로/길막 중립을 비교한다. 현재 정적 사본의 trust220/conflict450 일괄 게이트가 이를 막는지 최신코드에서 확인하고 변경안을 제시한다. 기존 임계값을 근거 없이 유지하거나 새 값을 단독 출시하지 않는다.

같은seed의 후보자격/가중치/독립응답과 성공분기를 고정한 원장 계산시험을 구분한다. AUTO 시험 수치는 해당 definition 버전과 대조한다. 단순 대사톤 변경만으로 행동 다양성 완료를 선언하지 않는다.

### B. 제3자 기록 흐름

A작업/B실제도움 완료→C별도 결과기록→부분 기록이 있는 경우 B의 합법 열람→B확인 요청/표현→C사실확인→정정게시/전달→별도복구 또는거리두기를 구현 후보로 삼는다.

- true_contributors 원천은 불변. recorded_contributors는 별도 기록/view이며 고의 미확인이다.
- C의 관측증거가 없다는 사실만으로 ‘분명 못 봤다’를 단정하지 않는다. 실제 관측범위/행동/가림의 최소 모델과 근거 누락/불명 상태를 개발자가 제안한다. 불명증거를 의도적으로 삭제해 누락을 생성하지 않는다.
- C가 B참여를 직접 확인한 경우 누락을 만들지 않는다. 제3자 없음·기록/열람 미완료·실제 도움 없음은 안전 종료한다.
- 기본 확인 대상은 B→C. 작업자A에 자동 책임/감점 부여 없음.
- 동일record/도움/누락대상/topic/scope에서 재열람/재전송으로 새issue를 반복 생성하지 않는다.
- 정정은 실제 새 action과 해당observer 인지가 있어야 EVT09 후보. 과거 누락사실의 인지revision과 새로운 정정행동 source를 구분한다. EVT12는 별도 수락/실행 및 실제 conflict가 필요하다.
- 기록 오류 확인사항이 닫혔다고 다른Conflict를 삭제하지 않는다. 기억·거리두기는 보존한다.

신규 witness/record 기능의 작업량이 크면 권한있는 단순 관측모델과 완전시야모델을 비교해 작은안을 제시한다. OpenIssue/Conflict를 데이터 이름만 바꿔 우회하지 않는다.

### C. 실제 말풍선·관계창

시안의 ‘잠깐 이야기했어요’는 서술예시다. 실제 말풍선은 화자가 청자에게 말하는 문장으로 연결하고 일지의 완료서술과 분리한다. dialogue_key·발화자/청자·행동단계·인지/사유·topic/scope·공개권한·완료/저장 참조를 대조한다. ×1/×4, pause/reload, 가장자리, 다중폰 겹침, 중복action/revision에서 읽힘과 재연출을 검사한다.

관계창에 A→B 방향·복합요약·8축 조회·최근인지 사건·사실/해석/사유/해결·활성근거·저장오류를 제공한다. DES-09에 8축이 모두 그려져 있지 않아도 요구를 제거하지 않는다. 시안의 일반대화사실과 작업분담갈등은 실제 서로 다른기록이면 별도카드로 구분하고 한사건처럼 섞지 않는다. 관련 없는 사건에는 해결구획을 억지로 붙이지 않는다.

시안의 배경 가구·예시 얼굴은 월드/사용자 폰 원본을 덮어쓰지 않는다. DES-06 기존 월드 보호배경을 유지한다. 생성이미지 텍스트를 자산으로 쓰지 않고 DOM/기존폰트로 조판한다. DES-09 문서에 인용된 DES-08 원문은 이번ZIP에 없으므로 실제 수치계약을 원문 수신 후 대조한다. 본문 13/12px·폭220/170은 해당문서의 참고값이며 지원 화면에서 가독성 검증한다.
