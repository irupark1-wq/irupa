# 《동그란 사이》 정연우 관계 자문

버전: 0.2 초안 · 작성일: 2026-10-12 · 모드: 게임 관계 시스템 설계

## 1. 자문 범위와 근거

사용자가 지정한 가상 AI 페르소나 `정연우-관계.md`의 설계 원칙과 실제 파일 `동그란_사이_PRD_v0.1.md`를 읽고 검토했다. 실존 전문가의 상담이나 심리학적으로 검증된 측정·예측 모형을 제공하는 문서가 아니다. 아래 점수·임계값·반응은 게임을 위한 설계 제안이다.

사용자 확정 요구는 원형 얼굴과 분리 파츠 제작, 개인 월드와 친구 초대, 광장, 목적별 맵, 관계 중심 플레이, 애정·신뢰·존중·의존·권력·호혜성·의무·갈등의 8축 및 각각 1~1000 범위다. 이 자문은 해당 요구를 바꾸지 않는다. 추가 규칙은 제안으로 구분한다. 첨부 페르소나는 작업 관점이며 사용자 요구나 실제 전문가 자격으로 취급하지 않는다.

핵심 판단: 방향성이 있는 8축에 사건 기억·공동 역할·구체적 갈등 주제를 결합하면 혐관과 애증을 포함한 복합 관계를 만들 수 있다. 숫자만으로 의도, 사랑, 동의, 관계의 건강성을 판정하면 설득력이 무너진다.

## 2. 공통 규칙 제안

| ID | 제안 규칙 | 디자인과 구현에 주는 의미 |
|---|---|---|
| REL-01 | A→B와 B→A는 별도 평가 | 동일 사건에 양쪽 점수를 복사하지 않는다. 자기 소유 폰끼리는 두 방향을 비교할 수 있다. |
| REL-02 | 사실·인지·해석·평가를 분리 | 사건이 발생했어도 A가 모르면 A의 감정값은 변하지 않는다. 자원·역할의 객관적 변화는 별도로 기록한다. |
| REL-03 | 관계 관심과 소유자의 허용은 별개 | 폰의 연애 관심과 실제 플레이어 승인 두 조건을 분리한다. 높은 점수로 승인하지 않는다. |
| REL-04 | 각 축은 독립적인 설명을 가진다 | 좋아하지만 못 믿고, 싫지만 존중하고, 의존하지만 떠나고 싶을 수 있다. |
| REL-05 | 기억은 과거 사실과 현재 미해결 상태를 구분 | 갈등 해결 후에도 있었던 사건은 이력에 남는다. ‘해결됨’이 사실 삭제나 망각을 뜻하지 않는다. |
| REL-06 | 사용자 거절·차단·연결 끊김은 관계 벌점 없음 | NPC 서사 속 거절과 소유자의 기능 승인 거절을 서로 다른 이벤트로 취급한다. |
| REL-07 | 태그는 역할·감정·긴장·과거를 겹친다 | 단일 관계 유형으로 고정하지 않는다. 기본 화면은 상황 관련 최대 3개만 보여준다. |
| REL-08 | 의존·권력·의무에는 근거를 붙인다 | 감정 점수처럼 선물로 올리지 않는다. 대안·분담·약속 변화로 재계산한다. |
| REL-09 | 정보 비공개는 수치뿐 아니라 파생 출력에도 적용 | 타 사용자 반대 방향 수치, 기억, 상호 태그, 변화 알림을 통해 숨은 상태가 새지 않게 한다. |

## 3. 여덟 축의 방향과 해석

| 축 | A→B의 의미 | 필요한 근거 | 행동의 반례 |
|---|---|---|---|
| 애정 | A가 B와 정서적으로 가까이 있고 싶은 정도 | 긍정 경험, 현재 욕구, 애착 기억 | 애정 900이어도 피곤하거나 갈등 직후에는 함께 식사하지 않는다. |
| 신뢰 | A가 B의 말과 행동을 믿는 정도 | 이행·불이행과 A가 알게 된 사유 | 신뢰 900이어도 B에게 관련 기술이 없으면 중요한 작업을 맡기지 않는다. |
| 존중 | A가 B의 능력과 인격을 인정하는 정도 | 능력·공로·가치에 대한 관찰 | 존중 900이어도 가치관이 달라 의견에 반대할 수 있다. |
| 의존 | A가 B의 자원·역할 없이 어려워지는 정도 | B가 제공하는 자원, A의 대안 | 의존 900이어도 사랑하거나 동의한다는 뜻이 아니다. 대안 확보로 감소할 수 있다. |
| 권력 | 공동 활동에서 A가 B와의 결정에 행사하는 영향력 | 해당 활동의 결정 역할·지분 | 권력 900이어도 B의 거절·퇴장·차단을 무시할 수 없다. |
| 호혜성 | A가 B와 주고받는 관계를 공정하게 느끼는 정도 | 합의된 배분 기준과 기여 기록 | 같은 돈을 받아도 공정하지 않다고 느낄 수 있다. 돌봄은 꼭 1:1 교환이 아니다. |
| 의무 | A가 B에게 책임을 지고 있다고 느끼는 정도 | A가 수락한 약속·역할 | 의무 900이어도 능력·자원이 없으면 이행할 수 없다. 실패 이유를 평가해야 한다. |
| 갈등 | A가 B와 해결하지 못한 충돌을 느끼는 정도 | 주제·영향·미해결 상태 | 갈등 900이어도 공동 목표를 위해 협력할 수 있다. 싸움 모션만 강제하지 않는다. |

호혜성을 금전 장부의 균형과 동일시하지 않는다. 공동체적 나눔, 차례 지키기, 기여 비례, 역할 분담 중 어떤 기준을 합의했는지를 활동에 붙이는 단순 설정을 제안한다. 초기에는 전체 관계 게이지 1개씩 유지하고, 분야별 세부 게이지는 확장한다.

의존·권력은 구조 기반 수치이므로 폰이 모르는 구조 변화와 감정 인지를 구분해야 한다. 예를 들어 새 기술자가 생겨 대안이 확보되면 의존은 줄 수 있지만, 원래 동료에 대한 애정·신뢰는 자동으로 변하지 않는다.

## 4. 기존 PRD에서 보완할 항목

다음은 원본 확정사항을 바꾸는 결정이 아니라 분리 PRD에 반영할 수정 제안이다.

| ID | 기존 규칙의 문제 | 보완 제안 | 검증 |
|---|---|---|---|
| ADV-01 | 사건 중복 키에 rule_version이 있으면 버전 변경으로 동일 사건이 다시 적용될 수 있음 | 멱등성 식별에서 규칙 버전을 분리하고 최초 평가 버전은 감사 정보로 저장 | 규칙 업데이트 후 사건 재전송해도 중복 없음 |
| ADV-02 | 뒤늦은 정보를 단순 차분 처리하면 상·하한에 잘린 이전 값 때문에 결과가 틀릴 수 있음 | 원 사건 기여 원장과 당시 규칙 버전으로 결정적인 재평가 수행. 새 정보 자체의 독립 감정 효과는 별도로 기록 | 경계값·후속 사건·정보 재전달에도 결과 일관 |
| ADV-03 | 은혜 기록을 곧바로 의무로 계산하면 도움받음이 강제 책임이 됨 | 감사 기억과 수락 책임을 분리. ‘갚겠다’는 약속을 수락했을 때만 활성 의무 | 원하지 않은 선물로 상대에게 의무를 부과할 수 없음 |
| ADV-04 | 사전 고지된 지연이 항상 존중 +15면 반복 지연이 존중 상승 수단이 됨 | 책임 있는 고지·재협상·영향을 분기. 불가피하고 영향 없는 지연은 변화 0도 가능 | 고지 반복만으로 존중 무한 상승 없음 |
| ADV-05 | 신규 갈등 severity 1+증가만 허용하면 중대 사건도 수십 회 필요 | 신규 사건에는 심각도 직접 설정을 허용하고, 재발에는 증가량을 적용. 중대 여부는 기억 태그와도 분리 | 작은 다툼과 큰 배신의 결과 차이 확인 |
| ADV-06 | 공동 활동 없는 권력 500을 ‘동등 권력’으로 오해 | 게이지는 1~1000 유지하되 근거 없음 플래그와 ‘공동 결정 기록 없음’ 병기 | 근거 없는 500과 실제 동등 분담이 구별됨 |
| ADV-07 | 상호 혐관·절친 태그는 숨은 상대 수치를 추론하게 함 | 다른 소유자끼리는 자기 방향 표현 우선. 공동 공개 호칭은 별도 상호 동의된 선언으로 구분 | 상대 수치·기억을 태그와 대사로 역추적하지 못함 |
| ADV-08 | 모든 태그의 진입 2사건 규칙이 중대한 즉시 사건까지 지연시킬 수 있음 | 감정 상태 태그는 지연 유지, 명시 수락 역할·과거 사건·차단·철회는 즉시 처리 | 동업 종료 후 현재 동업자 태그가 남지 않음 |

의무·갈등에 최댓값만 쓰는 기존 제안은 초기 구현을 단순하게 하지만, 작은 부담 여러 개의 합과 지속 피로를 표현하지 못한다. 초기에는 최고 부담/갈등과 항목 개수를 함께 보여주고, 누적 보정은 플레이테스트 후 검토한다. 높은 수치가 반드시 현실의 더 심한 상태를 뜻한다는 표현은 하지 않는다.

## 5. 혐관과 복합 관계 콘텐츠 제안

아래 사례의 숫자는 A→B 순서(애정/신뢰/존중/의존/권력/호혜성/의무/갈등)인 설정 예시다. 태그 구현 여부·임계값은 분리 PRD의 콘텐츠 범위에 따른다. 상호 태그는 자기 소유 폰 또는 공개 허용 상황에서만 보여준다.

| 사례 | 예시 값 | 기억·상황 | 다음 행동 |
|---|---|---|---|
| 싫지만 믿고 맡기는 라이벌 | 180/820/900/300/500/700/450/700 | 경쟁에서 자주 다투지만 약속은 지킴 | 실력을 인정하며 공동 주문 제안 |
| 못 믿지만 실력은 인정하는 동업자 | 200/220/850/800/300/250/700/850 | 공로 독점, 계약과 기술 의존 | 공개 분담을 요구하거나 대안 기술자 탐색 |
| 좋아하지만 상처가 남은 옛 친구 | 820/280/600/200/500/400/150/800 | 깊은 추억과 숨긴 불이행 | 함께 있고 싶지만 중요한 비밀은 맡기지 않음 |
| 일방적으로 싫어하는 이웃 | 180/500/450/100/500/500/1/720 | A만 소음 피해를 알고 B는 미인지 | 문제 알리기·규칙 합의. 상호 혐관으로 표시하지 않음 |
| 서로 싫지만 공동체 책임을 지는 둘 | 200/650/720/650/500/550/850/750 | 축제 준비를 수락했고 방법이 충돌 | 역할 분리·중재·공동 목표에 한시적 협력 |
| 적대는 줄었지만 가까워지지 않은 둘 | 320/550/600/100/500/600/1/150 | 사과와 복구를 받아들였지만 친밀 의사 없음 | 인사 가능, 각자 생활. 화해가 친구/연애가 될 필요 없음 |
| 존경하는 경쟁자와 가까운 친구 | 750/800/900/250/500/700/350/650 | 함께한 추억, 우승 목표 충돌 | 경기에서는 경쟁하고 끝나면 식사 |
| 헤어진 연인이자 믿는 동료 | 550/850/800/600/500/750/700/250 | 연애 종료, 가게 운영 지속 합의 | 업무 협력, 로맨스 자동 복귀 없음 |

낮은 애정은 무관심과 적대를 모두 포함할 수 있으므로 ‘혐관’에는 적대 기억·갈등 주제·서로 계속 만날 이유가 필요하다. 혐관→가까워짐은 점수 하나를 올리는 이벤트가 아니라 공동 사건, 상대 해석의 수정, 책임 있는 행동이 연결되는 변화 설명이다.

관계의 결말은 절친·연애·화해만 제공하지 않는다. 거리 두기, 계약 종료, 역할 분담, 서로 존중하며 경쟁하기도 완결된 결과다.

## 6. 세 번의 선택으로 검증할 시나리오

공방의 모래와 밤은 주문 마감을 앞두고 공로 문제로 갈등 중이다. 모래는 밤의 기술에 의존하지만, 밤은 자신의 이름이 주문서에서 빠진 사실을 알고 있다.

1. **공로 인정:** 공동 주문서에 이름을 반영하고 고객에게 정정한다. 관련 갈등·호혜성이 변하며 기존 불이행 신뢰가 자동 회복되지는 않는다.
2. **대안 확보:** 다른 기술자에게 작업 일부를 맡긴다. 모래→밤의 의존은 감소한다. 애정 상승이나 밤의 원망 감소를 자동 적용하지 않는다. 밤이 대안 확보를 모르면 감정 반응도 없다.
3. **이후 결정:** 함께 일하기, 역할 분리, 계약 종료 중 선택한다. 친해지지 않고 정당하게 헤어지는 경로도 같은 수준으로 완결한다.

반례 테스트: 1에서 선물만 보내 공로 갈등을 없애려 하면 해결되지 않는다. 2에서 새 기술자를 숨긴 상태라면 밤은 전지적으로 반응하지 않는다. 3에서 플레이어가 활동 승인을 거절해도 폰의 수치·얼굴을 불쾌하게 바꾸지 않는다.

## 7. 관계 UI와 모션 자문

- 기본 문구는 ‘밤은 내 약속을 믿기 어렵다고 느낀다’처럼 주체·대상·인지 근거를 분명하게 한다. 자기 폰이 아는 이유만 설명한다.
- 의존·권력·의무·갈등은 중립색·명칭을 사용한다. 전체를 빨강=나쁨/초록=좋음으로 통일하거나 8축 합산 건강도 점수를 만들지 않는다.
- 자기 폰의 방향 수치만 열람 가능한 온라인 관계는 전환 버튼을 잠그는 수준보다 데이터 자체를 미전달하는 것이 원칙이다. 빈 값은 0 또는 500으로 위장하지 말고 비공개로 표시한다.
- ‘배신’은 확인된 사건 해석에서만 사용한다. 미확인 지연은 ‘약속이 지켜지지 않았고 이유를 모름’으로 표현한다.
- 높은 갈등에서도 협력·거리 두기·중재·문제 제기를 구분한다. 분노 표정 하나로 모든 갈등을 표현하지 않는다.
- 사용자 동의 거절·만료·연결 중단 결과에는 불쾌한 얼굴이나 애정 하락을 보상/벌점처럼 붙이지 않는다. 승인 철회와 NPC 서사 속 선택은 문구와 상태 코드를 분리한다.
- 같은 소유자 폰끼리 A→B/B→A 전환과 차이를 보여준다. 다른 소유자 폰의 숨은 값은 상호 태그·알림·추천 행동을 통해서도 드러나지 않아야 한다.

## 8. 개발 구현과 콘텐츠 계약

사건 정의에는 `사실`, `영향`, `인지 조건`, `알려진 사유`, `해석 분기`, `평가 대상 방향`, `점수/구조 변화`, `갈등 주제`, `기억`, `동의 범위`, `표시 문구`가 필요하다. 부정적 결과를 몰래 전역 확산시키지 않는다.

정보를 수정할 때는 원 사건의 오해 정정과 새로운 정보 획득의 독립 효과를 구분한다. 예: 사고로 지연했다는 사실을 알면 최초 고의 의심 효과를 정정할 수 있지만, 실제 납품 지연의 피해가 없던 일이 되지는 않는다. ‘늦게 알려준 데 대한 서운함’은 근거 있는 별도 사건이다.

권력은 활동 범위별 A/B 결정 역할로 계산한다. 같은 활동의 배타적 결정 지분은 정규화하되, 서로 다른 활동의 합산 결과나 감정 평가를 무조건 서로 보완하는 점수로 처리하지 않는다. 실제 계정·월드 권한은 관계 수치와 별도다.

갈등 병합 키는 관찰자·대상·주제·활동/약속 맥락을 포함하는 제안을 권한다. 모든 공로 문제를 전역 하나로 합치면 서로 다른 주문의 복구 조건이 사라진다. 이미 해결한 사건을 재전송하여 다시 미해결 상태로 만들지 않는다.

채택은 문서 초안의 작업 기준 채택이며 사용자 최종 승인이나 구현·플레이테스트 완료를 뜻하지 않는다. 공통계약의 후속 보완으로, 기억의 `인지 여부`, `알려진 사유`, `해결 여부`는 서로 배타적인 단일 상태가 아니라 독립 차원으로 관리할 것을 김PO·디자인·개발에게 제안했고 김PO가 04에 반영했다고 회신했다. 반복 목격은 새 감정 효과를 발생시키지 않고, 사유 수정은 근거 있는 정보 보정으로 처리하되 태그 진입의 별도 사건 횟수로 세지 않는 개발안에 동의한다. 김PO는 DEC-05를 원장과 체크포인트 기반 순서 재투영으로 통일하고 감사·지연·갈등 강도·권력 근거·태그 진입의 DEC-08~12를 추가했다고 회신했다.

권력 500은 활동 없는 경우의 중립 기본값을 유지하는 제안에 동의한다. 다만 실제 동등 분담에서 얻은 500과 구별하도록 근거 플래그·설명을 병기한다. 사건 인지 미확인과 구조 자체의 미확인은 구분한다.
