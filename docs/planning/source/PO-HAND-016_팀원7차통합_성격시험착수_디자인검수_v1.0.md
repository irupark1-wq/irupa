## 1. 최우선 결정

성격·관계를 다음 플레이 가능한 개발의 중심으로 유지한다. 이번에는 PERS-SYS-001을 실제로 수신했으므로 ‘시스템 정본 미수신’ 상태를 해소한다. 외주7에는 김시스템 자료만 있다. 김플레이 PERS-PLAY-001 정본은 이번에도 미수신이며 외주 자료를 김플레이 납품으로 표기하지 않는다.

정연우의 관계 의미 검수를 수용한다. 다만 정연우가 이번 시스템 수치와 코드까지 검수한 것으로 기록하지 않는다. 최신 원문 우선순위는 본 PO-HAND-016 및 PO-PERS-002 v1.1 보완 → PO-HAND-015 → PO-PERS-002 v1.0 → PO-PERS-001 v1.1/v1.0이다. 과거 ‘로그인·두 방 먼저’ 문구로 작업 순서를 되돌리지 않는다.

## 2. 김시스템 제안 결정

| 요청 | PO 결정 |
|---|---|
| 후보별 점수표 | **첫 시제품 실험안으로 채택. 출시 수치 확정 아님.** 최신 기본 점수 단위를 먼저 대조한 후 적용 |
| 1 : 1/2 : 1/4 합성·±14 상한 | 시험안 수용. 절댓값 내림차순·동률 카드 ID 순, 마지막 1회 half-away-from-zero 반올림, 최종 clamp |
| 기존3축 중복 | 기존 기질을 유지하고 카드 영향은 별도 추적. 겹침 때문에 기존 축을 삭제하거나 재추첨하지 않음 |
| 대상 추가 수락 확률/점수 | 이번 차수에서 보류. 대상 자신의 기질·상태·동의·관계 방향을 사용하는 기존 독립 반응을 유지 |
| 진행 중 카드 수정 | 이미 시작된 intent는 당시 카드/규칙 snapshot 유지, 새 선택부터 새 카드 적용. 권한 철회·안전 조건은 언제나 우선 |
| fixture JSON | 설계·시험 입력 참고로만 수용. production_import_allowed:false와 not_run을 유지. 서버 콘텐츠로 자동 import하지 않음 |

점수는 관계 delta가 아니라 유효 행동 후보의 선호 보정이다. 무카드 상태는 기존 후보·점수·선택·난수 흐름의 회귀 기준이다. 기존 행동의 동률/난수 계약을 먼저 유지하고 새 후보의 정렬은 기존 재현성을 깨뜨리지 않게 적용한다. 김시스템 수식이 카드3장의 비우월성을 증명한 것은 아니므로 실제 선택 분포와 반례를 확인한다.

기본 점수 단위가 다른 경우 그대로 +12 등을 넣지 않는다. 김도현은 실제 점수 범위·대표 후보 차이·적용 가능한 변환안을 보고한다. 단위가 맞으면 별도 재승인 대기 없이 시험 제작한다. 관계 효과·갈등 수치는 바꾸지 않는다. 계수 조정은 규칙 버전을 올리고 변경 전후 결과를 제출한다.

## 3. 최소 제작 범위와 게이트

**G-PERS-1: 카드 선택·저장·기존 행동 연결.** 0~3장, 권장2장, 중복/4장/미지원 카드 거절, 기존 폰 수정, 취소·실패 rollback, snapshot/replay를 연결한다. 최신 코드에서 실제 지원하는 휴식·작업·만남·도움 후보에 먼저 적용한다. 이것만으로 전체4종 완료를 선언하지 않는다.

**G-PERS-2: 근거 있는 확인·기준 설명·증거 검토·설명 수용.** 욱하는/고집 센의 행동 차이를 위해 필수다. 현 action에 연결할 수 있으면 재사용하고, 없으면 PERS-SYS-001 부록의 최소 계약을 바탕으로 구현 매핑을 제출한다. 별도 kind 4개 신설 자체를 요구하지 않는다. 확인/설명/검토/수용의 실제 단계·증거·후속 상태가 관찰되어야 한다. 독립적인 ‘불편 표현’ kind는 별도 구현을 후순위로 둘 수 있으나 근거 있는 질문에서 불편함이 표현되는 경로는 보존한다.

새 액션 매핑에는 실제 코드 key, source/인지, 접근·권한·피로, 상대 반응, commit 결과, 중복 방지, 사건 효과, 중단/실패를 적는다. 미정 단계는 blocked_action_undefined로 명시한다. 다른 확정 기능 제작은 계속한다. 발화만 새로 만들고 상태 변화나 증거가 없으면 행동 구현으로 판정하지 않는다.

**G-PERS-3: 생활 장면·관계·공개 범위.** PERS-C01~12와 기존6장면을 실행한다. 네 카드 각각 on/off 차이, 두장6조합, 15세트 유효성·순서불변·상한, 혼자 생활·거절 후 생활·다른 방·미인지·회복 후 거리 유지 사례를 제출한다. 단계별 통과를 기록하며 전체 게이트는 모두 충족한 뒤 판정한다.

현재 실제 source에 맞는 짧은 발화는 먼저 연결 가능하다. 다만 미수신 김플레이 장면/대사팩을 구현 완료로 표기하지 않는다. 새 사실·수리·재료 전달 콘텐츠는 임의 추가하지 않는다.

## 4. 관계 문구 정정과 갈등250의 근거

PO-PERS-002 v1.0의 ‘모든 행동은 상대를 필요로 하지 않아야 한다’는 문구를 정정한다. **폰의 생활 진행은 상대 없이도 지속할 수 있어야 한다. 사회적 행동에는 상대의 독립 응답과 위치·동의·권한 조건이 적용된다.**

‘협력=사랑 증가 금지’는 **공존/공동작업 참가만으로 자동 친밀·연애·갈등 해소가 발생하지 않는다. 실제 승인된 완료·인지 사건의 방향별 효과는 기존 정의대로 평가한다**로 정정한다. 따라서 검증된 EVT-04 효과를 일괄 제거하지 않는다.

갈등250의 PO 정책 근거는 **PO-HAND-009 §2 / CR-DEV25-CREDIT-01·02·03**이며 원문을 이 패키지에 포함한다. 이것은 제한된 공로 분쟁의 정책 채택이고 최신 소스의 EventDefinition 구현 버전·활성화 게이트 통과 증거는 아니다. 김도현은 실제 definition ID/version, 승인 정책 대응, 현재 활성 상태를 제출한다. 해당 계약이 확인되지 않은 분기는 새 카드 기능을 이유로 활성화하지 않는다.

범위는 실제 도움·모호한 공로 규칙·정수 비율 4×overlap<work·양쪽 독립 주장과 상대 인지·같은 record/rule·미해결 한정 영향이다. 성격→입장 고정 매핑, 질문만으로 갈등, 같은 source 중복, 450/700 자동 승격은 금지한다. 이름 표시 쟁점의 수정 수용과 정정자 인지/EVT-09는 분리한다. 정정·합의로 기억이나 친밀도를 자동 바꾸지 않는다.

## 5. DES-17 디자인 판정

생활방 세로/가로×3시간대 총6장을 **개발 합성 검수용으로 접수**한다. 6개 파일 SHA-256은 manifest와 일치 확인했다. 김PO는 가로 낮/밤·세로 낮을 직접 열람했다. 분위기와 빈 바닥 방향은 시제품 검토에 적합하다. 나머지 화면을 포함한 실제 폰·가구·UI 합성, 보호 영역, 시간대 구조 정합은 아직 통과 판정하지 않는다.

좌표는 수동 측정 제안이다. floor_rect 변경을 확정하지 않는다. 12×8칸·논리 배치·점유·저장값은 그대로 유지하고 픽셀 변환/앵커만 제안 좌표와 비교한다. 세로 셀55×105, 가로116×38의 차이는 실기기 선택칸·폰 크기·가구 겹침·화면 크롭을 검수한다. 구조가 움직이면 자동 시간대 crossfade를 승인하지 않는다. 우선 단일 낮 배경 합성으로 검토하고 기존 배경 복구 경로를 남긴다.

파일은 약1.8~2.13MB로 목표1.5MB를 넘는다. 손상시키지 않는 최적화·지연 로딩을 검토하되 6장을 처음부터 모두 로드하지 않는다. 기존 UI는 유지하고 성격 작업을 이 아트 검수로 막지 않는다.

가구 제외는 이번 납품 범위로 수용하고 기존 가구 파일을 유지한다. 디자이너 문서에 인용된 별도 사용자 승인·지시는 외부 진행 보고로 기록하며 김PO의 추가 발주 근거로 자동 확대하지 않는다. 아늑한 방은 최신 원본 부재로 미납품이다. 김도현은 legacy-room/background-room-portrait.png 및 background-room-landscape.png의 실제 경로·최신 원본·좌표/장식 명세를 김PO에 전달한다. 기존 가구를 새로 요청하지 않는다.

## 6. 다음 DEV 회신과 담당 후속

김도현은 본 문서 수용 여부, 최신 커밋, 후보/baseScore/seed/반응 코드 위치, 의미 action 매핑, 시험 규칙 버전, 실제 소요와 G-PERS-1~3 결과를 제출한다. 요청자 기질이 상대 수락 계산에 잘못 들어가는지 최신 코드로 확인한다. 구형 코드 자문의 의심을 현 버그 확정으로 표기하지 않는다.

정연우에게는 이번 시스템 수치와 action 매핑의 의미 검수를, 김시스템에게는 실제 분포·중복 편향 보정을, 김플레이에게는 PERS-PLAY-001 정본과6장면을 요청한다. 김디자인에게는 실제 합성 결과와 필요한 좌표 변경, 아늑한 방 원본을 전달한다. 모두 김PO 경유로 진행한다.

고문 검토 관점: 이번의 성공은 카드 이름이나 배경 수가 늘어나는 것이 아니라, 사용자가 ‘이 폰이 왜 이런 행동을 했는지’를 실제 장면에서 이해하는 것이다. 항상 친절/항상 싸움/대사만 변경을 반증 조건으로 삼는다. 로비스타인 문서는 참고 프레임이며 실제 인물의 검수·승인으로 기록하지 않는다.
