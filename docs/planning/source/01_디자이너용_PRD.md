## 1. 목표와 범위

내가 직접 얼굴을 만든 동그란 폰이 생활과 공동 사건에서 다양한 관계를 형성하고, 그 관계가 행동과 화면에 드러나게 한다. 꾸미기→생활→사건→관계 변화→다음 행동의 연결이 디자인의 핵심이다.

| 원본 ID | 확정 요구 | 디자인 대응 |
|---|---|---|
| U-01 | 원형·눈·입·머리카락·프레임 개별 제작 | SCR-01, 파츠·레이어 규격 |
| U-02 | 자기 폰끼리/다른 사용자 폰과 관계 | SCR-03/04, 방향·공개 범위 표시 |
| U-03 | 개인 월드·친구 초대 | SCR-02/08, 방문·편집 권한 |
| U-04 | 광장 만남 | SCR-05, 인사·활동 제안 |
| U-05 | 목적별 맵 | SCR-06, 공동 공방 역할·선택 |
| U-06 | 8축 각 1~1000 | SCR-04, 숫자 상세·원인 |
| U-07 | 혐관 등 다양한 관계 | 개인 방향 설명·기억·복합 태그 |
| U-08 | 생활·사건 중심 월드 분위기 | 생활 공간과 사건 피드백; 기존 작품 표현 복제 금지 |

단계 A는 자기 폰 3명·월드·공방으로 핵심 경험 검증. 단계 B는 친구 초대·광장·사용자 간 관계·권한·신고를 연결한다. A만으로 전체 사용자 요구 완료를 선언하지 않는다. 플랫폼·엔진·아트 스타일·목표 연령은 미결이다. 모바일 화면을 최종 확정하지 않고 PC 가로 화면 와이어프레임부터 검토한다.

## 2. 시각 언어와 정보 구조

[제안] 2D 탑다운/약한 사선, 둥근 실루엣, 차분한 생활 배경, 사건 대상에 명확한 윤곽을 사용한다. 픽셀아트 여부는 미결이다. 월드는 얼굴과 행동이 먼저 읽히고 장식은 이를 가리지 않아야 한다. 관계의 높은 값을 일괄 초록, 낮은 값을 일괄 빨강으로 표시하지 않는다. 의존·권력·의무·갈등은 상태 설명과 맥락을 함께 읽는다.

상단에는 시간·저장·연결 상태, 중앙에는 월드/작업 대상, 하단에는 선택 폰·행동, 별도 패널에는 관계와 사건 기록을 둔다. 기본 카드는 이름·방향·개인용 설명·최근 공개 가능한 원인을 보여주며 정확 숫자는 상세로 펼친다.

기본 흐름: SCR-01 얼굴 저장 → SCR-02 월드 → SCR-03 폰 → SCR-04 관계 → SCR-07 사건 결과. 소셜 흐름: SCR-05 광장 → 제안/수락 → SCR-06 공방 → SCR-07 → 월드/광장 복귀. SCR-08은 모든 화면에서 진입 가능하다.

## 3. 화면별 제작 명세

| ID·화면 | 필수 요소·행동 | 필요한 데이터 | 빈 상태 |
|---|---|---|---|
| SCR-01 얼굴 | 파츠 탭·캔버스·그리기/지우기·색/굵기·변환·좌우 복제·20단계 이상 취소/재실행·프리셋·실크기/표정 미리보기·저장 | pawn_id, appearance_version, layer originals/transforms, draft, limits | 기본 원형+프리셋 선택 안내; 빈 그림도 허용 규칙 명시 |
| SCR-02 월드 | 폰 선택·이동·생활·가구 배치/회수·유효 경로 미리보기·초대·저장/연결 상태 | world_id/version, layout, permissions, pawn states, clock, participants | 첫 폰 생성/가구 배치 안내 |
| SCR-03 폰 상세 | 외형·성향·욕구·현재 행동·대표 폰 변경·관계 진입 | owner, pawn_id, appearance, traits, needs, controllable | 떠난 폰은 식별 정보 삭제 정책에 맞춘 대체 표시 |

| SCR-06 공방 | 목표·참가자·역할·기여·진행·돌발 문제·선택 비용/예상 방향·중단 | activity/version, roles, progress, options, consent, server clock | 참가자 대기; 자기 폰으로 시작 가능 |
| SCR-07 결과 | 확정 사건·알려진 원인·허용된 변화·새 기억·남은 문제·다음 행동 | event_id/sequence, authorized effects, reason_key, next_actions | 결과 대기와 결과 없음 구분 |
| SCR-08 설정 | 방문 공개 범위·자율 행동·중대 전환 동의·큰 글씨·움직임 감소·음량·알림·차단 목록 | settings/version, scopes, pending consents, blocked public entries | 대기 동의/차단 대상 없음 |

### 3.1 모든 화면의 공통 상태

| 상태 | 표현 | 취소·실패·재시도 |
|---|---|---|
| loading | 기존 내용 유지 또는 골격, 읽는 중 표시 | 가능한 화면에서 뒤로가기; 요청 취소는 저장 취소와 구분 |
| ready/idle | 실제 권한에 맞춰 행동 활성 | 권한 없음은 대체 가능한 안내 |
| dirty | 미저장 표시·초안 보존 | 나가기 시 저장/초안 유지/명시 폐기 |
| saving/pending | 중복 클릭 억제·처리 중 | 응답 유실은 '확인 중'; 성공을 먼저 표시하지 않음 |
| saved/confirmed | 확정 버전 및 결과 표시 | 재전송 결과는 추가 성공 연출 없음 |
| error/offline | 원인 범주·복구 행동, 초안 유지 | 재시도는 동일 request_id로 상태 확인; 새 행동 생성과 구분 |
| conflict | 최신 변경 있음, 초안 안전 보존 | 최신 확인→초안 재적용 선택. 자동 덮어쓰기 금지 |
| cancelled/declined/expired | 미확정 종료, 대기 제거 | 필요 시 새 제안. 거절·만료 자체에 관계 벌점 없음 |

온라인 저장 전 '완료'를 보여주지 않는다. 로컬 초안 저장과 서버 확정 저장은 별도 문구다. 편집을 나가는 행동이 이미 전송된 저장을 취소했다는 뜻으로 표현하지 않는다.

### 3.2 개별 실패·복구

- SCR-01: 파츠 규격 오류는 해당 파츠를 강조하고 다른 편집 보존. 외형 저장 성공 뒤 기존 pawn_id 유지. 저장 충돌은 새 버전 확인 후 자기 초안 재적용.
- SCR-02: 경로 차단 가구는 빨간색만이 아닌 금지 윤곽+이유 표시. 서버 배치 거부 시 마지막 확정 배치로 복구하고 초안 유지. 두 기기 편집 충돌은 두 번째 읽기 전용/기존 세션 종료 선택.
- SCR-03/04: 삭제/권한 변경 시 기존 사적 캐시를 지우고 안전한 대체 상태. 상대의 차단 여부를 특정하는 오류 문구 금지.
- SCR-05: 정원 초과 시 다른 인스턴스 탐색. 초대 실패는 '지금 요청을 전달할 수 없습니다'와 재시도 가능 여부 제공. 중복 친구 요청은 기존 요청 표시.
- SCR-06: 동의 대기/수락/거절/만료를 구별. 접속 단절은 기술 중단, 60초 복귀 유예 제안. 퇴장은 즉시 허용, 벌점이나 의무 상태는 서버 확정값만 표시. 기술 중단은 관계 벌점 없음.
- SCR-07: 확정 전 delta는 표시하지 않는다. 순번 공백은 동기화 표시 후 스냅샷 복구. 재접속 시 지나간 결과는 기록 목록으로 표시하고 축하/상처 연출을 연속 재생하지 않는다.
- SCR-08: 저장 실패 시 이전 설정과 자기 수정안을 구별. 차단은 서버 확정 즉시 접촉·초대·공동 활동을 닫는다. 신고는 접수 사실만 표시하고 제재를 약속하지 않는다.

## 4. 얼굴 파츠·아트 제작 규격

| 항목 | 제안 규격·의도 |
|---|---|
| 원본 | 파츠별 512×512 RGBA 투명 캔버스; 원본과 합성 프리뷰 분리 |
| 좌표 | 캔버스 정규화 0~1; 중심 pivot=(0.5,0.5); 회전 단위·크기·변환 허용범위 개발 명세에 고정 |
| 원형 영역 | 중앙 원형 베이스, 여유 외곽 포함; 원형 지름 384px 제안, 외곽 64px씩 장식 여유 |
| 순서 | back_hair → base → eyes → mouth → front_hair → frame_accessory |
| 눈 | left/right 개별 객체 또는 pair; 혼용을 막도록 저장 mode 명시. 좌우 복제는 원본 보존 |
| 표정 | neutral 필수, happy/sad/angry 선택; 없으면 기본 변환 대체, 임의 그림 재생성 금지 |
| 출력 | PNG 원본·레이어 manifest·월드 합성 프리뷰. 런타임 압축/atlas 방식은 엔진 검토 |
| 미리보기 | 48/64/96px 크기와 밝은/어두운 배경 테스트; 최종 월드 표시 크기는 시점 확정 후 결정 |
| 이름 | pawn_{id}/appearance_v{n}/{slot}_{expression}.png, 공유 프리셋은 preset_{slot}_{nn}_{expression}.png |

manifest는 slot, expression, asset_id, width/height, pivot, transform, sort_order, checksum, appearance_version을 포함하는 제안이다. layer transforms의 단위와 허용범위는 개발자용 계약을 따른다. 프레임은 얼굴 주변 테두리·장식으로 가정했으므로 사용자 의미 확인 전 고정하지 않는다.

프리셋 제안: 눈 8·입 8·앞머리 6·뒷머리 6·프레임/장식 8. 단계 B 외부 이미지 업로드·파츠 공유는 제외. 작성 원본은 소유자 편집 자산이고 공개 프로필에는 허용된 합성만 제공한다.

## 5. 모션·소리와 관계의 행동 표현

| 상태 | 연출 제안 | 타이밍 가설 | 감소 모션 대체 |
|---|---|---|---|
| 대기/이동 | 약한 흔들림/이동 방향 반응 | 루프; 엔진 속도에 맞춤 | 위치 이동만 |
| 기쁨 | 작은 도약·입/눈 선택 표정 | 400~600ms | 표정+문구 |
| 슬픔 | 약한 내려앉음·표정 | 600~800ms | 표정+문구 |
| 화남 | 짧은 기울기·긴장 표시 | 300~500ms | 표정+아이콘 |
| 머뭇거림 | 잠깐 멈춤·시선 이동 | 500~800ms | '망설임' 표시 |
| 도움/작업 | 대상 향하기·도구/진행 표시 | 활동 타이머 연동 | 진행 표시 |

모션은 사건 결과/현재 행동을 표현한다. 높은 갈등만으로 매번 공격적 표정을 강제하지 않는다. 긍정 사건에는 작은 확인음, 저장에는 중립 확인음, 오류에는 별도 아이콘·문구를 붙인다. 소리 없이 모든 결과를 이해할 수 있게 한다. 화면 흔들림과 급격한 점멸은 초기 제외한다.

정연우 자문 반영: 오프라인·사용자의 동의 거절·요청 만료에는 서운함 얼굴이나 관계 벌점을 연출하지 않는다. 게임 내부 상황에서 폰이 도움을 거절하는 사건은 사용자 승인 거절과 구별하고, 알려진 이유와 경계 표현을 표시한다. 모르는 사건을 '배신'으로 미리 명명하지 않는다.

감사 기억과 의무는 분리한다. 도움받았다는 이유만으로 채무/책임 수락 화면을 확정하지 않는다. 의무 근거에는 활성 수락 약속·역할만 표시한다. 지연 사전 고지에 존중 상승을 보장하는 보상 연출을 붙이지 않고 서버가 확정한 해석 분기만 설명한다.

관계 행동 예: 신뢰→도구 맡기기, 존중→의견 구하기, 애정→옆자리 선호, 갈등→주제 제기/거리 두기. 폰끼리 역할과 상황이 다르면 같은 게이지도 다른 행동을 보인다. 권한·거절·직접 조작은 이런 연출보다 우선한다.

## 6. 월드·맵 디자인 브리프

- 개인 월드: 입구·생활 공간·공방 이동 지점을 눈에 띄게 구분. 가구 12종 제안. 초대 방문자의 편집 불가와 사용 가능 가구를 아이콘으로 구분. 소유자 종료 시 저장 안내 후 방문자 광장 복귀.
- 광장: 스폰·대화 거리·활동 게시 지점·출구가 읽히는 동선. 폰 정원 16명 제안, 밀집 시 이름표 최소화와 선택 윤곽 제공. 자유 채팅 없이 정형 인사·표현·제안.
- 공동 공방: 2~4개 폰, 역할 배치 지점·자원·진행·문제 지점을 한 화면에서 연결. 역할 배정→작업→돌발 문제→선택→완료/중단→기여·분배. 갈등은 공로/분담 등 구체적 주제로 표시.
- 맵 납품: 레이아웃 원본, 충돌/통행 레이어, 상호작용 지점 ID, 스폰·출구·복귀 위치, 카메라 경계, 밝기/시간 변형. 타일 크기와 맵 크기는 엔진/기준 기기 검토 전 미결.

목적별 맵 초기 제작자는 제작팀이다. 유저 맵 편집 도구는 확장 검토이며 사용자 확정 기능으로 해석하지 않는다.

## 7. 관계 UI·프라이버시 계약

8축은 모두 1~1000, A→B의 평가이며 헤더에 '모래가 밤에게 느끼는 관계'처럼 방향을 명시한다. 자기 소유 폰끼리 양방향 전환 허용. 타 사용자 폰→내 폰의 비공개 점수·기억은 응답에 포함하지 않고 화면도 추측값을 만들지 않는다. 제한 상태는 가시성 필드만 전달한다.

내 폰의 기본 설명 예: '실력은 인정하지만 함께 일하기 불편함'. 상호 비공개 축에서 판정한 '절친·혐관·애증' 같은 내부 태그를 그대로 노출하면 상대 마음을 유출할 수 있다. 별도 상호 공개 동의 없으면 개인 방향에서 허용된 근거로 만든 문구만 표시한다. 공개 사건의 관찰 가능한 행동은 별도 기록으로 설명하며 상대의 사적 의도를 단정하지 않는다.

| 축 | 중립 설명 | 상세 근거 |
|---|---|---|
| 애정 | 정서적 가까움 | 알려진 공동 경험 |
| 신뢰 | 말·행동에 대한 믿음 | 약속 이행/알려진 은폐 |
| 존중 | 능력·인격 인정 | 의견/공로 사건 |
| 의존 | 상대 없이 어려운 일 | 자원·역할·대체 가능성 |
| 권력 | 공동 결정 영향력 | 활동별 결정 지분; 실제 조작 권한과 별개 |
| 호혜성 | 주고받음의 공정감 | 기대와 인식; 객관 기여와 구분 |
| 의무 | 느끼는 책임·부담 | 수락한 약속·역할 |
| 갈등 | 남은 충돌 강도 | 주제·해결 상태 |

권력은 공동 활동이 없어 기본값 500인 경우 숫자 옆에 '현재 판단 근거 없음'을 표시한다. 실제 활성 근거가 있는 500과 구별한다. 의존 설명은 '상대 없이 이 일이 어려움'처럼 역할에 연결하며 사랑·관계 건강도의 색으로 해석하지 않는다.

공동 활동 선택 전에는 알려진 비용·예상 변화 방향·불확실성만 표시한다. 확정 숫자와 상대 마음을 예측하지 않는다. 숫자는 방향 아이콘·텍스트 변화와 함께 표시하며 변화량 0/미확인/비공개를 구분한다. 과거 기억과 최근 변화 원인을 동시에 확인할 수 있다. 로맨스는 애정으로 자동 성립하지 않고 별도 관심·사용자 동의·수락 조건이 필요하다.

## 8. 개발자와 합의한 화면 데이터 계약

- 변경 명령: command_id(원본 request_id와 동일한 명령 중복 방지 의미), 대상 ID, expected_version, 행동 의도. 관계 delta는 화면이 생성·확정하지 않는다. 동의 대상은 별도 consent_id로 식별한다.
- 응답: 상태(status), 최신 entity_version, 안전한 reason_key, 허용된 데이터, 재시도 가능 여부. 차단 등 사적 사유를 구체화하지 않는다.
- 사건: event_id, event_sequence, instance_id, 확정된 authorized effects. event_id 기반 연출 중복 방지, 순번 공백 시 재동기화. 전달 재시도는 같은 명령 ID를 사용하고 새 사용자 의도만 새 ID를 만든다.
- 시간: clock_id/active_day/active_tick/paused로 생활·약속 표시. 동의 expires_at_utc는 실제 만료 시각이며 현지 시각 표시와 남은 시간을 구분한다.
- 초안과 확정: appearance_version/world version/settings version을 유지. 실패·충돌 시 자기 초안 복구; 상대 사적 자료는 캐시하지 않는다.
- 권한은 숨겨진 버튼만으로 보호하지 않고 서버가 최종 검사한다. UI는 반환된 allowed_actions로 표시를 맞춘다.
- 공개 변경/차단/로그아웃/상대 삭제는 캐시 무효화 이벤트와 함께 처리한다. 내부 관계 판정과 사용자 표시 문구는 별도 필드로 관리한다.

교차검토 보완: 반대 방향이 비공개이면 방향 전환 버튼을 숨기고 정상 응답은 해당 방향 필드를 제외한다. 임의 비공개 조회만 restricted/scores=null의 일반 거부 결과를 사용한다. 기억은 인지(known)·사유 인지(reason known/unknown)·해결(resolved/unresolved)의 세 차원을 각각 표시한다. 사건을 알고 있지만 이유는 모르며 아직 미해결인 상태를 하나의 선택 상태로 압축하지 않는다. 개발자 상태 draft는 UI idle/dirty, failed는 error에 대응한다.

## 9. 제작 납품물과 인계 순서

1. 화면 8종 와이어프레임 및 클릭 흐름: 기본/대기/빈 상태/실패/충돌/취소/재시도 포함.
2. 얼굴 에디터 상세: 도구·파츠 선택·변환·원본 보존·미리보기·저장 전이.
3. 스타일 보드: 시점·픽셀 여부·원형 폰/환경 조합 2안 비교, 사용자 승인 후 아트 바이블.
4. 파츠 프리셋 원본·합성 예시·manifest, 8상태 모션 시트·타이밍·감소 모션, 소리 큐 표.
5. 개인 월드/광장/공방 레벨 시트와 상호작용/충돌/스폰 ID.
6. UI 컴포넌트·상태 토큰·방향 화살표·오류 문구·관계 설명 키·공개 범위 표.
7. 원본 편집 파일·런타임 출력·변경 이력·알려진 문제·사용성 검증 기록.

인계는 화면 구조→데이터 필드 검토→정적 시안→상태 프로토타입→엔진 통합 순으로 진행한다. 개발자는 숨김 데이터/권한/버전/명령 중복을 검토하고 디자이너는 반영값·복구 동선·파츠 합성·가독성을 검토한다. 총괄은 범위·비용·미결정을 승인한다. 아직 위 납품물 제작과 검증은 완료하지 않았으며 본 문서는 제작 요구 명세다.

## 11. 착수 미결정·변경 관리

플랫폼/입력, 시점/픽셀 여부, 프레임 의미, 표시 최소 크기, 목표 연령/로맨스 범위, 자산 용량/압축, 폰/정원 한도, 공개 동의 세부, 삭제·운영 보존 정책은 미결이다. 요구 변경은 원본 U-ID와 화면 ID·데이터 계약·인수 테스트 영향을 함께 기록한다. 화면과 개발 명세 상충 시 안전한 공개 범위와 원본 사용자 요구를 우선하고 김PO가 결정 로그를 남긴다.
