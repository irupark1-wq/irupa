## 1. 추가 자료와 결정

정연우 검토는 김시스템 요청의 6쟁점 중 1/2/5/6 수용, 3/4 조건부 수용이다. SYS-CONF-001 전체 정의와 최신 코드를 직접 대조하지 않았다는 한계를 유지한다. 이번에 첨부된 QA는 설계/not_run이며 실제 결과가 아니다.

| 요청 ID | 김PO 결정 |

| DEC-SC-01 | 수용. 누락관찰과 확인요청을 사실/기억/열린확인사항으로 구분한다. 기본 감정 감점0, 실제Conflict 자동생성0. |

기존 ‘정연우의 제3자 사례 추가 검수 필요’ 중 의미 단계의 검수는 이번 자료로 수신 완료다. 실definition/코드와 실행 검증은 여전히 미완료다. 같은 의미승인을 다시 요청하지 말고 남은 구체규칙을 제안한다.

## 2. 구현에 적용할 엄격한 구분

### 게시관찰과 규칙위반

‘B 이름이 없다’는 게시 내용 관찰과 ‘적용되는 공로기준을 위반했다’는 판정을 분리한다. attribution_rule_id의 범위·버전이 해당 C기록에 적용되는지 확인한다. 공식 공로의무가 없는 개인일지에 이름이 없다고 부당공로를 확정하지 않는다. 근거가 없으면 관찰/확인 단계에서 멈춘다.

### 확인사항과 실제갈등

B가 기록을 인지하고 확인요청을 하면 OpenIssue를 만들 수 있다. C가 못봤음·미회신·권한부족·기술단절·확인시간요청은 그 자체로 대립/고의의 증거가 아니다. B가 도움종료 전에 떠났다는 조건도 필수로 추가하지 않는다. 관측증거 없음은 미목격확정/면책확정과 다르다.

실제Conflict 후보에는 예를 들어 기여근거를 두고 서로 반대 입장을 실제 표명한 분쟁이나, 별도 입증된 부당한 폄하/방해의 action·impact·인지·scope가 필요하다. 그 경우에도 고의가 불명인 채 갈등이 가능하며 EVT08/10으로 자동 승격하지 않는다. 이 독립 대립은 자율 행동으로도 도달 가능한 구체정의와 완료증거를 제출한다. 확인사항만 반복하고 실제 불화 요구를 완료 처리하지 않는다.

### 평가방향과 정정자

기본 해석대상은 B→C이고 A가 게시혜택을 얻었다는 이유만으로 A귀책/감점을 부여하지 않는다. C→B도 자동복제하지 않는다. B가 실제정정자가 C라는 사실을 알지 못하면 C에게 존중/호혜성을 귀속하지 않는다.

시험정의가 일치하는 경우 EVT09는 B→C 존중+15/호혜성기본+18, 공정성배수는 호혜성만 적용한다. 나머지축 불변. 예시 [420,550,600,1,500,500,1,1]→[420,550,615,1,500,518,1,1]은 medium성향·적법정정의 고정검산 시험이며 일반새밸런스가 아니다.

정정으로 기록확인사항이 닫혀도 실제Conflict가 자동해결되지 않는다. 실제Conflict가 없으면 EVT12를 생성하지 않는다. EVT12는 별도계획·수락·실행·필요수용이며 같은정정행동을 두 번 긍정효과에 쓰지 않는다. 정정 이후 기억·거리두기·자율거절은 유지한다.

## 3. source 계보 정본

1. HELP-001: 정확한 A/B 도움완료 source. C일지 오류 때문에 삭제/수정하지 않는다.
2. CREDIT-LOG-001: C의 실제게시/누락 source. B열람은 이source의 B knowledge_revision이며 새원천 발급 아님.
3. VERIFY-REQ-001: 별도확인요청 action. OpenIssue전이, 기본효과0, 긍정근거 아님.
4. CORRECT-001 / CREDIT-CORRECT-001: C의 실제정정 action/source. B의정정인지는 이새source의 observer revision이다.
5. REPAIR: 실제Conflict에 대한 별도복구계획/수용/이행이 있을 때만 후보.

식별자는 설명예시이며 실제namespace/키는 개발자검수로 정한다. 정정은 게시본을 갱신하되 이전누락source와 정정이력을 보존한다. 과거 source인지정정과 새로운 정정행동을 한 슬롯으로 덮어쓰지 않는다. duplicate action/revision·다중탭·저장실패는 추가효과0/원자rollback, 태그는 유효인지source의 순서replay로 재구축한다. PO-15 Day/예약/중립규칙 유지.

## 4. 개발자가 제출할 것

- 여섯증거·표시기준 적용범위·게시자/정정자/수신인지의 실제필드 및 권위참조.
- SYS-CONF-001-Q01~10 기대/실제와 외주 REQ04-SYS01~12의 대응표. 서로 다른 QA집합이므로 번호/수량을 통합하지 않는다.
- 규칙없는 일지, 누락만인지, 실제대립없음, C미확인/권한없음, 정정자미인지의 안전분기.
- B→C만반영·원HELP불변·지식revision/새정정source분리·동일근거EVT09/12차단·다른갈등보존.
- 신규 실제Conflict의 trigger/행동증거/impact/severity가정/해결조건·비발생반례. 이정의는 미결이며 CR/추가결정으로 처리.
- 명령·fixture·definition/코드version·seed·초기/결과·실행status·미완료·온라인범위 구분.

문서 추가만으로 DEV-20/22 판정보류를 해제하지 않는다. DEV/REQ원문·DES-08/실대사·PLAY카드 등 기존미수령사항도 자동수신완료로 바꾸지 않는다.
