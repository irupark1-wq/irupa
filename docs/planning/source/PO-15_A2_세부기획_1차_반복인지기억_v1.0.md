# PO-15 — A2 세부기획 1차: 반복·인지·기억·관계 설명

- 작성: 김PO / 수신: 김도현 / 참조: 정연우·김시스템·김디자인
- 작성일: 2026-10-13 / v1.0
- 기준: PO-PLAN-001, PO-DEC-001~003, 외주2.zip의 김시스템 v1.1 후속안.
- 상태: 제품 규칙 확정 및 개발 착수 명세. 기술 저장안 검수·실제 실행 통과는 별도.
- 범위: A2의 선행 기반을 우선 납품한다. STORY-C·가벼운 위임·외주 생활 콘텐츠까지 완료된 명세로 취급하지 않는다.

## 1. 이번에 구현할 사용자 경험

폰들은 같은 상대와 대화를 이어갈 수 있지만 매번 관계 점수가 오르지는 않는다. 게임 하루가 바뀌어도 이전 기억과 관계는 남는다. 과거 사실을 새롭게 알게 되면 당시 사건에 대한 평가가 바뀌고, 이를 새 행동·새 보상으로 중복 처리하지 않는다. 관계 상세는 인지한 사실·해석·사유 상태·해결 상태를 구분한다.

김도현은 저장안과 현 코드의 차이부터 짧게 검수한 뒤 이 범위를 구현한다. 어려운 사항은 비용·대안·사용자 영향을 회신한다. 미결인 전체 A2를 기다리며 이 기반 작업을 멈추지 않는다.

## 2. 시간과 반복 효과

### 시계

1tick=게임1분, 시작08:00, day_index=floor((480+tick)/1440), 표시 Day=day_index+1. tick0~959는 Day1, tick960~2399는 Day2다. 일시정지·비활성 화면·오프라인은 tick 진행 없음, 복구 시 paused=true다. 완료 확정 tick의 Day에 집계한다.

Day는 새 반복 bucket을 시작할 뿐 이전 관계·기억·태그·갈등·약속을 초기화하지 않는다. 재접속·현실 날짜 변경은 리셋 사유가 아니다.

### light_social 시험 규칙

- 인사와 가벼운 잡담은 light_social 한 군으로 묶는다. 안정 scope를 사용하여 가구 위치를 바꿔 상한을 우회하지 않는다.
- 방향별 bucket: clock/day/observer/target/effect_family/stable_scope. 정확한 물리 저장 키는 개발자가 검수한다.
- A2 시험값: 방향당 Day별 자격 3회, 최소 효과 간격60tick, 접근 재시도35tick. 출시값은 아니다. 기존 접근 타이머의 기준 tick을 확인한다.
- 접근·상대 반응·완료·효과 자격은 분리한다. 자격 상한으로 접근/대화 자체를 강제 거절하지 않는다.
- 마지막 자격 부여 tick은 Day를 넘어 보존한다. 신규 Day라도 최소 간격이 남으면 효과0이다.
- 새 완료의 중복 여부와 실제 수락/완료 증거를 먼저 검사한다. 같은 action 재전송은 기록/기회/관계효과 추가0이다.
- 도움을 light_social에 임의로 넣지 않는다. minor_help 및 기존 도움의 한도는 매핑 검수 후 추가한다. 갈등/정정/복구는 인사 한도 밖이나 독립 증거·멱등성은 필수다.

## 3. 완료 사실·중립 활동·미인지 사건

| 상태 | 기록 | 관계 기여와 태그 |
|---|---|---|
| 접근/거절/중단 | 상태·실패/취소 근거, 완료 사실 아님 | 기본0, 긍정 근거 아님 |
| 완료·자격 불허(상한/간격) | 안정적 neutral_activity_history와 물리 action 참조 | 관계0, 긍정 근거 아님, 기존 EVT-01 원장에 추가하지 않음 |
| 완료·자격 허용·인지 | 원 source·당시 snapshot·방향 기여 | 기존 사건 정의로 계산, 유효 긍정 근거 판정 |
| 완료·자격 허용·미인지 | 원 source·방향별 동결 자격·순서를 보존 | 현재 기여0, 이후 유효 인지 정정으로 원슬롯 투영 가능 |
| 유효 기여가 clamp로 표시0 | 유효 사건으로 유지 | 상한 중립과 구분, 기존 태그의 긍정 자격 적용 |

하나의 물리 action은 완료1건이며 방향별 투영은 별개다. 미인지도 적법한 관계 후보라면 당시 자격을 예약·동결한다. 뒤늦은 인지는 새로운 Day 기회를 소모하거나 과거 quota를 환급하지 않는다. 당시 자격을 얻지 못한 4번째 사건이 나중에 인지됐다고 유효 기여로 바뀌지 않는다.

직접 대면 인사에 불가능한 ‘한 당사자는 인사 자체를 모름’ 설정을 넣지 않는다. 비대칭 인지는 근거 있는 도움·기여 발견의 사건 정의로 시험한다. 사건 정의가 미완성이면 해당 시험을 blocked로 보고한다.

기존 원장의 repeat_multiplier=1 계약을 유지하며 multiplier=0을 우회 입력하지 않는다. 중립 기록은 최근120건 UI 로그와 분리하여 과거 중복/정정에 필요한 안정 참조를 유지한다. 보존/압축·이전 저장 호환안은 개발자가 제출한다.

## 4. 정정과 태그 재구축

source의 observer별 knowledge_revision만 갱신한다. 당시 성격·규칙·seed·반복 판정·순번을 유지하고 원슬롯 기여를 교체한다. checkpoint 이후 순서를 replay하며 태그 이력도 영향받은 구간부터 재구축한다. 실제 생활 행동·Day 기회·보상·푸시를 재실행하지 않는다.

긍정 근거는 적법한 독립 source·실제 완료·observer 인지·동결 효과 자격·기존 사건의 긍정 자격을 모두 만족해야 한다. 상한 중립·미인지·중복 revision을 긍정 사건으로 세지 않는다. 여러 축 변화도 source1건이다. 감정 태그2독립근거 및 편안한친구3긍정은 각각 기존 조건을 유지한다. 역할 종료 즉시 해제는 별도다.

인지 false→true는 같은 source의 자격을 바꿀 수 있으므로 태그 결과까지 불변이라고 요구하지 않는다. source 수·당일 quota·행동 수가 늘지 않는 것을 요구한다.

## 5. 공개 화면 명세

월드에는 행동을 짧게 표시하고 생활 일지는 반복 중립 대화를 묶어 읽히게 한다. 관계 상세에는 다음 정보를 분리한다.

- 사실: 자기 폰이 인지한 완료/기록.
- 해석: 자기 폰이 그 사실을 어떻게 받아들였는지.
- 사유: 알고 있음/미확인. 모르는 이유를 악의로 단정하지 않음.
- 해결: 열림/해결 및 정확한 갈등 대상. 해결이 기억 삭제나 자동 친밀을 뜻하지 않음.

중립 완료는 ‘둘은 잠깐 이야기를 나눴어요.’ 등 생활로 표시한다. ‘더는 친해질 수 없음’이나 실패/하락 연출은 하지 않는다. 접근 중 관계 상승 연출 없음, 실제 저장 확정 후에만 허용 변화를 표시한다. 모든 중립 표정을 금지하는 것이 아니라 의미 없는 실패/관계 악화 연출을 피하는 규칙이다.

타 소유자 비공개 수치·성격·인지 상태·기억·반대 방향 자격·trace/seed는 응답·대사·알림에 제외한다. 로컬 방문 데모와 실제 온라인은 구분한다.

## 6. 개발 및 디자인 납품

김도현: 현재 코드 적용 차이, 당시 자격/중립/미인지 상태 저장안, 이전 데이터 보존·rollback, 실행본·검사출력·남은 문제를 제출한다. 단일 commit으로 tick/카운터/완료/원장/태그를 저장하고 실패 시 원본을 유지한다. 새로운 epoch가 과거 관계를 초기화하거나 효과 재지급의 근거가 되지 않게 한다.

김디자인: 접근/거절/완료/중립·사실/해석/사유미확인/해결·저장실패 상태표와 기존 UI 보완안을 제출한다. 픽셀 크기/파일 규격은 개발자 실제 렌더 요청을 김PO가 취합한 뒤 확정한다. 신규 이미지부터 발주하지 않는다.
