# PO-PERS-001 — 성격 카드 개편 채택 및 시제품 기획

- 김PO → 김도현 / 참조: 정연우·김플레이·김시스템·김디자인
- 작성일: 2026-10-13 / v1.0
- 근거: 정연우 성격카드 개편 기획 제안 v1.0.
- 상태: 단계적 제품 채택·담당 과제. 실제 구현·테스트·외부 발송 완료 아님.

## 1. 결정

플레이어가 ‘어떤 폰인지’를 상상할 수 있는 생활 언어 성격 카드를 채택한다. 내부 3축을 모두 새 카드 이름으로 바꾸거나 지우는 방식은 채택하지 않는다. 카드와 기존 기질의 역할·영향이 겹치면 규칙을 정의하고 시험한다.

| 요청 | 김PO 결정 |
|---|---|
| 카드 최대3장 | 수용. 0~3장 선택 가능, 권장2장. 최소2장을 강제하지 않음. 미선택은 기존 기본 기질로 생활 가능 |
| 28종 목록 | 장기 후보 목록으로 수용, 전체 제작 약속 아님 |
| 우선12종 | 후보군 수용. 지원된 카드만 실제 선택 가능으로 공개 |
| 첫 구현 | 다정한·욱하는·고집 센·독립적인 4종으로 작은 비교 시제품 |
| 카드 기능 없는 표시 | 플레이 가능 표시 금지. 검토용 미리보기는 별도이며 일반 생성 흐름에서 미지원 카드 선택 불가 |
| 갈등/동의/인지 | 기존 계약 유지. 성격만으로 악의·배신·갈등/감점·수락 생성 금지 |

정연우가 ‘기존8개’라고 표현한 목록은 이번 문서에서 현 소스의 실제 지원 카드로 확인하지 않았다. 기획 후보와 구현된 기능을 구분한다. 김인간 자문은 제공 문서의 인용이며 김PO가 해당 자문 원문을 읽거나 별도 담당으로 위촉한 것으로 기록하지 않는다.

## 2. 단계와 우선순위

로그인/시작화면·계정저장·폰가로 편집·두방 및 승인된 국소 분쟁은 현재 제작 순서를 유지한다. 카드 UI와 콘텐츠 명세 준비는 병행하고, 코드 반영은 개발자가 영향/작업량을 제시해 순서를 조정한다. 12종을 모두 다음 로그인 버전의 필수 완료 조건으로 추가하지 않는다.

첫4종 → 조합/실제 생활 관찰 → 나머지 우선8종 → 확장16종 순서로 검토한다. 후보가 재미를 늘리지 않으면 추가 카드 수보다 행동·욕구·기억 연결부터 수정한다.

우선12종: 다정한, 욱하는, 사교적인, 낯가리는, 호기심 많은, 꼼꼼한, 느긋한, 장난기 많은, 의리 있는, 독립적인, 고집 센, 경쟁심 강한. 나머지16종은 원문 후보를 참조하며 카드 개수로 성격 다양성 검증을 대체하지 않는다.

## 3. 첫4종의 관찰 가능한 차이

| 카드 | 행동 변화 목표 | 상대·상황에 따른 한계 | 표현 |
|---|---|---|---|
| 다정한 | 도움/안부 후보를 더 주목 | 피로·자기 목표·상대 거절 유지. 무조건 자기 일을 포기하지 않음 | 배려하는 제안과 거절 수용 |
| 욱하는 | 인지한 불일치에 빠르게 확인/불편 표현 후보 | 질문 전에 존재하지 않는 사실을 알지 않음. 자동 공격·악의 단정·갈등250 없음 | 빠른 감정 표현 뒤 질문·설명 듣기 가능 |
| 고집 센 | 자신의 확인된 해석을 쉽게 바꾸지 않음 | 새 근거와 상대 설명을 받아들일 가능성 존재. 항상 제외/항상 반대 입장 아님 | 기준 유지·재확인·조건부 수용 |
| 독립적인 | 혼자 활동·휴식 및 접촉 거리 선호 | 존중·공동목표가 있으면 협력 가능. 낮은 애정/비사회성과 동일시하지 않음 | 혼자 시간 요청과 필요한 협력 |

카드별 최소1개 **행동 후보/반응 차이**와 해당 공개 대사 연결을 요구한다. 이름/문구만 달라지는 것으로 카드 기능 완료를 판정하지 않는다. 단일 seed의 한 번 선택만으로 경향을 보장하지 말고 후보 자격/우선순위와 실제 선택 비교를 함께 제출한다.

## 4. 선택 UX와 조합

폰 생성의 성격 화면은 카드 이름·한 문장·‘이럴 때 이런 모습을 보일 수 있어요’ 예시로 구성한다. 선택 수 0/3 및 추가/해제, 미리보기/취소/저장, 지원 여부를 읽게 한다. 샘플 얼굴을 강제하지 않는다.

상충 이름 조합을 일괄 차단하지 않는다. 다정한+욱하는는 도움과 빠른 서운함 표현이 함께 가능하다. 향후 사교적인+낯가리는는 익숙함/초면 조건을 나눠야 한다. 같은 카드 중복 선택은 불가이며 선택 순서가 결과를 바꾸지 않도록 조합 규칙을 정한다.

후보마다 카드 영향→상황/관계/기억 영향→상대 독립 반응을 구분한다. 가중치 중첩·상한·반올림·동률·seed·규칙 버전은 김시스템/김도현이 명세로 제안한다. 강한 카드3개가 항상 최적이라는 단일 정답을 만들지 않는다.

최초 UI는 카드가 중심이고 기존 3축은 고급 설정 또는 기존 폰 호환 설정으로 유지할 수 있다. 구체 위치는 디자인 검토한다. 카드 변경으로 내부3축을 몰래 재추첨하지 않는다. 어떤 값이 적용되는지 저장 계약에 명시한다.

## 5. 저장·이전 폰·원장

기존 pawn_id·외형·3축 값·관계8축·기억·역할·동의를 유지한다. 기존 폰에는 새 카드 선택을 제안하되 자동 부여/변환하지 않는다. 카드 없는 옛 폰도 기존 생활을 계속한다.

신규 카드 프로필은 schema/profile/rule version·card_ids·effective_from_order를 가진 제안 구조로 검수한다. 과거 사건 replay에는 당시 카드/기질 snapshot과 규칙을 사용하고, 당시 카드가 없으면 없던 상태로 재생한다. 현재 카드를 과거에 소급 적용하지 않는다.

카드·기질 동시 수정은 한 번의 확정 저장으로 적용하며 실패하면 전체 이전 상태로 복원한다. save_format·backup·migration·계정 import/두방 저장과의 호환 비용을 개발자가 제시한다. 새 카드가 owner 권한이나 provider 계정 정책을 바꾸지 않는다.

다른 소유자 카드 상세·내부 가중치/추론·반대 방향 관계는 기본 비공개다. 공개 소개 기능은 별도 허용 라벨 명세 전 추가하지 않는다.

## 6. 담당별 첫 과제

- 김플레이: PERS-PLAY-001로 첫4종의 생활 장면·대사·각 조합의 차이와 실패/거절·환경 영향 작성. 기존 미수령 대사팩/콘텐츠 요청과 중복하지 말고 카드 ID에 연결.
- 김시스템: PERS-SYS-001로 첫4종의 후보/반응 영향과 기존3축 겹침 해결, 조합 합성·제한·버전·비교 fixture 제안. 공정성→고정 입장 매핑 금지 유지.
- 정연우: 4종과 복합 조합의 해석·사실인지·서운함/쟁점/갈등·수락/회복 경계 검수. 신규 감정 기여가 필요하면 근거와 CR로 분리.
- 김디자인: 카드 선택/미선택/상충 조합 예시/지원 상태·저장/기존폰 수정의 와이어프레임. 카드 얼굴·표정으로 선악을 정답처럼 구분하지 않음. 신규 일러스트 선발주 없음.
- 김도현: 현재 성격/기질·후보·snapshot·로그인 저장/두방의 적용 영향, 작은 구현안·작업량·기존 데이터 보존/롤백·반영 차수 회신.

외주 결과는 김PO가 검토·채택해 개발/디자인 명세로 인계한다. 기존 로그인·방 기능을 멈추도록 요구하지 않는다.

## 7. 시제품 수용 시험

PERS-C01 첫4종 각각 on/off 후보 차이, PERS-C02 다정한+욱하는의 도움/확인 공존, PERS-C03 고집 센도 검증된 새 근거 수용 가능, PERS-C04 독립적 폰도 공동목표 협력 가능, PERS-C05 피로/권한/상대 거절은 카드와 무관하게 유지, PERS-C06 선택 순서/중복/0~3장과 가중치 제한, PERS-C07 동일 카드·다른 관계/기억과 동일 관계·다른 카드 비교, PERS-C08 카드 수정 뒤 과거 snapshot/replay 불변, PERS-C09 이전 저장/계정 import/두방/실패 복구, PERS-C10 공개 DTO/대사/알림 비공개 누출0, PERS-C11 상한 뒤 중립생활·긍정source 중복0, PERS-C12 성격만으로 새 갈등/고의/부정기여 생성0.

확장 후보의 원칙주의/질투/의심 관련 원문 QA는 해당 카드 구현 차수에서 수행한다. 첫4종 시험이 미지원 카드까지 검증한 것처럼 보고하지 않는다. 정의·초기 상태·환경/seed·기대/실제·행동/발화·commit·실행 여부를 제출한다.

## 8. 다음 결과물

첫4종의 상태/콘텐츠 규칙과 개발 영향 검토를 수신한 뒤 김PO가 실제 제작 명세를 개정한다. 현재 문서는 방향과 과제의 채택이며 새 카드12종 구현 완료 또는 원안28종 전부 승인 문서가 아니다.
