## 1. 결론

- 가구를 옮기거나 장애물을 놓으면 폰의 이동과 활동이 실제로 달라지는 배치 기능을 완성했습니다. 고르기 → 미리보기 → 놓기 또는 취소 순서이며, 놓기 전에 가능 여부와 이유를 보여 줍니다.
- 그림과 이동 판정을 맞췄습니다. 가구가 그려진 통그림 배경을 김디자인님의 **빈 방 배경 + 가구 조각**으로 바꾸고, 가구의 바닥 접점을 실제 칸 중심에 놓습니다.
- PO-14 §5 의 A1-01~12 가운데 **10개 통과, 2개 조건부**입니다(4절). 조건부는 폰 가로 화면의 배치 편집(칸이 너무 작음)과 D6 축소·가림 검수(김디자인 판정 대기)입니다.
- 실행 주소: **https://neinom.com** (이 보고와 같은 커밋으로 배포). 로컬은 `npm start`.

## 2. 플레이어가 겪는 변화

1. 하단 독의 **배치**를 누르면 생활이 멈추고 배치 패널이 열립니다. PC 는 오른쪽 옆, 폰 세로는 아래에 뜹니다. 바닥은 패널을 비켜서 전체가 보입니다.
2. 쉼터·작업대·이야기 자리·장애물 가운데 하나를 고르고 바닥 칸을 누르면 미리보기가 뜹니다. 놓을 수 있으면 파란 실선 칸, 체크 아이콘, "여기에 놓을 수 있어요."가 보입니다. 놓을 수 없으면 빗금 점선 칸, 겹침·막힘 아이콘, PO-14 §4 의 이유 문구가 보입니다. 색만으로 구분하지 않습니다.
3. **여기에 놓기**를 눌러야 저장됩니다. **취소**를 누르면 아무것도 바뀌지 않습니다. 장애물을 누르면 "치우기"가 됩니다.
4. **끝내기**를 눌러도 생활은 자동으로 다시 시작하지 않습니다. ▶ 를 눌러야 합니다(PO-14 §3).
5. 장소를 옮기거나 닫으면 그 장소에서 하던 활동은 완료 없이 멈추고, 기록에 "장소가 바뀌어 하던 일을 멈췄어요"가 남습니다. 관계 점수와 기억은 바뀌지 않습니다.
6. 저장에 실패하면 미리보기 초안이 남고 **다시 시도**·**취소**가 나옵니다. 다른 창에서 배치가 바뀌었으면 덮어쓰지 않고 **최신 배치 보기**를 보여 줍니다. 이 버튼을 누르면 새로고침 뒤 같은 초안을 최신 배치 기준으로 다시 판정해 보여 줍니다.
7. 가구를 쓰는 폰은 가구 바로 뒤에 조금 올려 그려서 "작업대 앞에서 일하는" 모습으로 보입니다.
8. 거절된 폰 위에는 "지금은 혼자 있고 싶어요", 길이 막힌 폰 위에는 "길이 막혔어요" 말풍선이 잠깐 뜹니다(DES-04 D4). 관계 효과와는 무관한 표시입니다.

## 5. 미완료·알려진 문제

1. **폰 가로 편집(A1-10 조건부):** 가로 배경의 이동 바닥이 1392×304px(칸 116×38)로 매우 납작합니다. 폰 가로 화면에서는 행 높이가 10px 입니다. 대안은 세 가지입니다. ① 폰 가로에서는 칸 번호 입력을 기본으로 쓰기, ② 편집 중 바닥 확대(줌), ③ 가로 배경 바닥을 더 높게 다시 그리기. 저는 ③을 김디자인님께 검토 요청하고, 그 전까지 ①로 두는 것을 권합니다.
2. **폰 겹침(A1-12 관찰):** PC 가로에서 행 높이 36px 에 폰이 115~132px 라, 앞뒤 행의 폰이 많이 겹칩니다. 폰 세로에서는 칸 너비 30px 에 폰 60px 라 옆 칸 폰과 겹칩니다. 판정 규칙은 1칸 그대로이고 그림만 겹칩니다.
3. **가구 표시 크기:** 폰 세로에서 1칸 너비(30px)대로 가구를 그리면 폰보다 훨씬 작아 보여서, 가구를 폰 크기의 0.8배까지 키워 그립니다. 충돌은 여전히 1칸입니다.
4. **D6 관찰(판정 아님):** 48px 에서 눈·입이 작지만 보입니다. 새 말풍선 2종은 44px 에서 의미(혼자 있고 싶음 / 길 막힘)가 그림만으로는 약합니다. 화면에는 글자 설명도 함께 뜹니다.
5. **배경 자산 정리:** 납품 배경 2장의 테두리에 붉은 반투명 번짐(약 1.7만 픽셀)이 있었고, 가로 배경 위쪽 바깥에 진한 잡티 764개가 있었습니다. 원본은 보관하고 게임용 사본만 기계적으로 정리했습니다(번짐은 갈색으로, 잡티는 투명으로). 가구 조각은 클릭 영역을 줄이려고 같은 크기(160×192, 앵커 80,180)로 잘랐습니다.
6. 배경 그림의 가구 위치와 판정을 맞추는 문제는 이번에 "그림에 가구 없음"으로 해결했으므로, 이전 통그림 배경 2장과 옛 가구 아이콘 4장은 게임에서 뺐습니다(참조 폴더에는 남아 있음).

### 6.2 반복 효과 제한 구체안 (정연우님 검수 요청 — REQ-02)

| 항목 | 제안 | 근거 |
|---|---|---|
| Day 길이 | 화면 시계와 같은 계산. 1 tick = 게임 1분, 시작 08:00, Day = ⌊(480 + tick) / 1440⌋ + 1. 첫날은 960 tick, 이후 1440 tick | 플레이어가 보는 "Day N" 과 집계 Day 가 항상 같음 |
| 집계 key | `Day × 폰 쌍(순서 없음) × 종류(인사·대화 / 도움)` | 현재 쌍·종류 집계에 Day 만 더함 |
| 상한 | 종류별 하루 3회, 같은 쌍·같은 종류 효과 사이 최소 60 tick (둘 다 현 시험값 유지) | PO-DEC-001: 시험 규칙 |
| 경계 | 사건이 **완료 확정된 tick** 의 Day 에 집계. 현재 사건은 한 tick 의 commit 안에서 확정되므로 PO 기본안과 그대로 맞음 | PO-DEC-001 기본안 |
| 늦게 안 사건 | 원래 확정 tick 의 Day 기준으로 재투영. 알게 된 시점의 Day 로 다시 세지 않음 | REL-03 |
| 리셋 범위 | 반복 횟수만. 60 tick 간격, 관계·기억·태그·약속·갈등은 그대로 | PO-DEC-001 |
| 효과 0 기록 | 상한에 걸린 완료 인사·대화를 원장에 "효과 0" 사건으로 남김. 태그의 긍정 사건 수에는 넣지 않음. 같은 action 재전송은 새 기록이 아님 | PO-DEC-001, REL-03 |
| 제외 | 갈등·정정·복구는 일일 상한 없음. 고유 증거·멱등성 검사는 유지 | REL-03 |
| 정지·오프라인 | tick 이 안 가므로 Day 도 안 감. 재접속·실제 날짜 변경으로 리셋 없음 | 현 구조 그대로 |
| 저장 | 집계는 저장본에 Day 와 함께 보존. 이전 저장본의 누적 횟수는 "현재 Day" 의 횟수로 옮김 | 기존 저장 호환 |

구현은 A2-1 에서 합니다. 원장 계약에 "효과 0" 표시 필드가 새로 필요하므로 계약 버전을 올립니다.

## 8. DES-04 (김디자인 A1 자산) 수용

11개 파일 모두 크기·RGBA·체크섬이 manifest 와 일치했습니다. 원본은 `docs/reference/design-20261013-e/` 에 보관했습니다(저장소에는 올리지 않는 폴더). 바닥 좌표 표, 가구 앵커·배율 규칙, "충돌은 1칸 논리 판정, 가림은 앵커 y" 지시를 그대로 구현했습니다. 디자이너가 권한 "활동 접근 칸과 가구 점유 칸 분리"는 PO-14 의 "가구 1칸·중심 1명" 결정을 따라 이번에는 적용하지 않았습니다. 대신 가구를 쓰는 폰을 가구 뒤에 그립니다.
