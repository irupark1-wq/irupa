# 김디자인님께 — 개발 연결을 위한 요청사항

작성: 김도현 / 2026-10-12 / v0.1. 김피오 패키지0.2의 SCR/CT/DQA를 기준으로 작성했다. 아직 디자인 파일을 받지 않았으며 본 문서는 전달용 요청서다.

전체 아트를 한 번에 완성하기보다 얼굴 편집·관계·공방 핵심 흐름을 먼저 부탁드립니다. 최종 시점/픽셀 여부/프레임 의미는 시안과 김피오님 결정을 반영합니다. 아래 크기·개수·단위는 확정 제작 지시와 개발 제안을 구별했습니다.

## 3. 화면 공통 상태 — 꼭 포함할 것

모든 SCR 화면에 해당하는 상태를 지정하고 해당하지 않는 경우 이유를 적어주세요. 요청중 버튼 억제와 서버의 중복 방지는 별개입니다.

| 상태 | 표시/동선 | 금지할 표현 |
| --- | --- | --- |
| loading/empty/ready | 로딩·아직 기록없음·실제내용 구분 | 실패를 빈 기록으로 위장 |
| dirty/draft | 로컬 초안 보존, 나가기 저장/보존/명시폐기 | 로컬 보존을 서버 저장 성공으로 표시 |
| saving/pending | 처리중/응답유실은 확인중, 같은 명령 상태조회 | 확정전 수치/보상/성공 연출 |
| saved/confirmed | 확정 버전/결과 표시 | 재전송의 성공 연출 반복 |
| error/offline | 원인 범주+복구 행동, 초안 유지 | 상대 차단/사적 이유 특정 |
| conflict | 최신본 확인+자기초안 재적용 선택 | 자동 최신 덮어쓰기/초안 삭제 |
| restricted | 공개된 정보가 없습니다 | 숨은 점수를0/1/500으로 대체 |
| consent 종료 | 거절/만료/취소/철회 구분 | 관계 벌점/상처 표정/승인 강요 |
| reconnecting/interrupted | 기술중단/복귀/안전퇴장 | 배신·불이행 판정 |

개발이 command_id/status/reason_key/retryable/allowed_actions fixture를 제공합니다. 디자인은 각 키의 표시·문구·재시도·취소 동선을 연결해주세요. request_id는 command_id의 별칭이며 consent_id와 구별합니다.

## 4. 관계 표시 사례 요청

1. 자기 폰 A→B/B→A: 전환 버튼, 정확8축, 최대3개 개인용 설명, 근거·기억·남은갈등.
2. 내 폰→타소유자: 자기방향만, 반대전환 숨김, 상대 속마음/상호태그 미표시.
3. 비공개/미만남/값1/변화0/로딩실패: 각각 다른 화면 상태.
4. 권력500 no_active_basis와 실제 동등 결정500: 숫자 같아도 근거 문구 구별.
5. 사건은 known, 이유는 unknown, 해결은 open: 독립3차원 동시 표시.
6. 좋아하지만 못믿음, 싫지만 존중함, 의존하지만 떠나고싶음: 단일 선악색/건강점수 사용하지 않음.
7. 공로갈등 사과후 책임복구 대기, 갈등해결후 거리두기: 화해가 친구/연애로 자동 전환되지 않음.
8. 선택 preview: 알려진 비용/방향/불확실성; 상대 숨은감정과 확정 delta를 보여주지 않음.

사용자 동의 거절과 폰의 서사적 도움 거절은 문구/아이콘/상태를 구별해주세요. 확인되지 않은 사유는 배신으로 명명하지 않습니다. 행동의 관찰 사실과 사적 의도를 분리합니다.

## 5. 공방·맵·생활 요청

공방: 목표/참가/역할/기여/진행/문제/선택/확정/완료·중단을 한 흐름으로 연결해주세요. 공로 인정, 대안 확보, 이후 협력·역할분리·계약종료 시안을 부탁드립니다. 개발 PRD의 ‘추가 보수’ 후보와 자문 시나리오의 ‘이후 결정’ 차이는 PO에게 보낼 선택 구조 확인 항목이며 최종 메뉴를 임의로 고정하지 않습니다.

개인 월드/광장/공방마다 맵 원본, 크기/좌표, 충돌·통행 레이어, interaction_id, 스폰/출구/복귀 지점, 카메라 경계, 가구 앵커/footprint, 자리/도구 이용 지점, 경로 막힘 예시를 주세요. tile 크기·정원은 실험 전 제안입니다. 복수 목적맵 최종 목록은 PO 결정 후 추가합니다.

‘감정이 바뀌어도 행동은 똑같음’을 피하기 위해 자리 선택·도구 맡김·협력/거리두기·의견구하기·망설임 표현 사례를 요청합니다. 대사뿐 아니라 이후 행동을 보여주며 조작/권한/현재욕구가 우선입니다.

## 6. 모션·소리·접근성

원문은 8상태 모션 시트를 요청하지만 모션 표의 구체 항목은 대기/이동/기쁨/슬픔/화남/머뭇거림/도움·작업입니다. 8상태의 정확한 목록과 도움·작업 분리 여부를 확인해주세요. 추가 상태를 임의로 요구하지 않습니다.

각 상태에 시작/루프/종료, duration/ms, pivot, 위치변환, 선택 표정, 이벤트 연결, 중단우선순위, reduced-motion 대체를 기록해주세요. 표정 파츠가 없어도 동작해야 하고 얼굴을 임의로 다시 그리지 않습니다. 큰 갈등이 항상 분노 모션은 아닙니다.

큰글씨/키보드 초점/아이콘+텍스트/색 구분/무음/움직임감소 사례를 부탁드립니다. 화면 흔들림·급격한 점멸은 초기 제외입니다. 소리 cue는 역할/재생조건/반복방지/음량/파일/라이선스를 정하고 무음에서도 모든 확정 결과를 이해할 수 있어야 합니다.

## 7. 파일 인계 양식과 회신 항목

권장 묶음: README(버전/범위/미완료) + 화면 PDF/PNG 또는 열람 링크 + 편집 원본 + assets PNG + manifest + map metadata + tokens + motion/sound sheet + 변경 이력. 형식은 제안이며 현재 사용하는 디자인 도구를 존중합니다. 별도 로그인만으로 열람 가능한 링크라면 이미지/명세도 함께 제공하면 구현 검토가 수월합니다.

회신 부탁드릴 항목:

- 시점/스타일2안, 프레임의 의미, 목표 화면과 최소 폰 표시크기 제안.
- D-01~04의 첫 납품 가능 순서, 포함 파일, 샘플 범위.
- 눈mode, transform 단위/범위, 8모션 목록, 선택 표정 fallback.
- 상태/비공개 표시 계약에 대한 수정 의견과 개발에서 필요한 DTO fixture.
- 기존 PRD와 다른 사항은 CR-ID·관련SCR/CT/DQA·변경이유로 표시.

개발 수령 검수: 파일/버전 확인→투명도·치수·레이어·pivot·누락 검사→6크기/배경 비교→편집/월드 합성 일치→상태/권한 표시→관련 DQA. 검사 결과와 수정 요청을 남긴 후 채택합니다. 파일을 받았다는 이유만으로 디자인 승인/검증 완료라고 보고하지 않습니다.
