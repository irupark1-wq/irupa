## 1. 한 장 요약

**지금 상태:** 게임이 https://neinom.com 에서 열린다. 폰 3명이 혼자서 쉬고·만들고·인사하고·돕는 생활을 하고, 관계 8축과 기억이 쌓이며, 저장·복구와 로컬 방문 대역이 동작한다. 테스트 114개가 통과한다. 계정·클라우드 저장용 Supabase 테이블(SB-0002)이 준비됐다.

**PO-13 과의 거리:** PO-13 이 요구하는 것 중 **이미 있는 것이 약 60%**, **고쳐야 하는 것이 약 20%**, **아직 없는 것이 약 20%**다. 없는 것의 핵심은 세 가지다. ① 배경 그림과 실제 이동 공간이 아직 "대략" 맞는 상태(A1), ② 폰끼리 공로를 두고 어긋나고 바로잡는 이야기(STORY-C)가 없음(A2), ③ 정연우 검증 사례 22개를 하나씩 실행한 결과 파일이 없음(A3).

**제작 순서:** PO-13 §12 의 A1 → A2 → A3 → B0 → B1 → C 를 그대로 따른다. 단, B0(온라인 설계)은 A2 와 겹쳐서 진행한다. 계정·클라우드 저장 연결은 B1 의 앞부분으로 떼어 A3 뒤에 넣자고 제안한다(이미 DB 가 준비돼 있어 비용이 작고, 테스터가 폰을 바꿔도 월드를 잃지 않게 되기 때문).

**김PO 께 지금 필요한 것:** PO-14(A1 공간 세부계획서)와 김디자인 자산 4종. 자세한 요청은 REQ-01.

**예상 작업량(담당 1명, 집중 작업일 기준, 추정):** A1 3~4일, A2 5~7일, A3 2~3일, B0 2~3일(병행), 계정 연결 2일, B1 6~10일. 합계 로컬 완료까지 약 2~3주, 실제 친구 공존까지 약 4~6주. 납기 확정이 아니며 세부계획서를 받은 뒤 단계마다 다시 산정한다.

## 4. 원장 정정 뒤 태그 재구축과 사실/해석 DTO (§14 회신 3)

- **지금:** 지식 정정이 들어오면 원래 사건 슬롯을 바꾸고 그 사건 이후를 다시 계산한다. 태그 이력에는 해당 사건의 긍정 여부만 뒤집는다. "태그 전체 이력을 처음부터 다시 만들어도 같은가"는 아직 검사하지 않았다.
- **A2-5 에서:** 정정된 사건의 위치를 checkpoint 로 잡고 그 뒤 태그 전이를 전부 다시 계산해, 즉시 뒤집기 결과와 같은지 자동 검사한다. 다르면 전체 재구축 결과를 정답으로 한다.
- **DTO 두 겹:** ① 사실 DTO = 사건 목록(누가·무엇을·언제), 기억 3차원(사건 인지/사유 인지/해결), 정정 이력. ② 해석 DTO = 8축 값, 복합 태그, 설명 문장, 규칙 버전. 화면은 ①을 먼저 보여주고 ②는 "해석" 으로 구분해 표시한다. 온라인에서는 ②의 상대 방향 값을 allowlist 로 거른다.
