## 1. 시작 화면 (PO-START-001) — 납품

### 1.1 흐름

준비 화면 → 시작 화면 → (이 기기의 월드 이어하기 | 이 기기에서 시작하기 | Google·이메일 로그인 → 계정 월드) → 월드 입장(시간이 지난 월드는 멈춘 상태, 소급 없음).

| 항목 | 구현 |
|---|---|
| 준비 화면 | 제목 + "폰들의 하루를 준비하고 있어요." 가짜 진행률·강제 대기 없음. 준비가 끝나면 바로 닫힘 |
| 처음 온 사용자 | Google로 계속하기 → 이메일로 계속하기(누르면 입력칸이 펼쳐짐) → 이 기기에서 시작하기(별도 선택, 첫 폰 그리기로) |
| 이 기기에 월드가 있는 사용자 | 첫 버튼 "이 기기의 월드 이어하기" + 제목(폰 이름들)·폰 수·"생활 Day N HH:MM까지 이 기기에 저장됨". 로그인은 아래에 계정 저장용으로 유지. "새 월드 만들기"는 보조(확인 → 지금 월드를 `.before-new-world` 로 따로 보관 → 빈 월드). 보관할 공간이 없으면 지우지 않고 내려받기를 먼저 안내 |
| 로그인한 사용자 | 같은 화면 안 계정 칸에 **로그인 상태 / 월드 저장 위치 두 줄**(DES-12), 계정 월드 목록·불러오기·이 월드를 계정에 저장. 자동 불러오기 없음 |
| 로그인 확인 중 | 이 기기에 로그인 기록이 있으면 "로그인 확인 중…"(게스트로 잘못 보이지 않음). 8초가 넘으면 "확인이 늦어지고 있어요. 이 기기의 월드로 계속할 수 있어요." 늦게 확인돼도 고른 월드를 바꾸지 않음 |
| 인증 복귀 | `/auth/` 가 먼저 처리하고 결과 키만 전달 → 시작 화면 계정 칸에 결과 표시(로그인했어요 / 취소했어요 등) |
| 저장본을 못 읽을 때 | 앱이 멈추던 것을 고침. 준비 화면에서 이유(새 버전 형식 / 손상)와 "원본 저장본 내려받기" · "원본을 보관하고 새로 시작"(`.unreadable` 로 보관, 공간 부족이면 지우지 않음). 자동 새 월드 없음 |
| 언어 | 시작 화면에도 한국어·English·日本語 선택. 제목 그림도 언어별 |
| 소리 | 게임에 소리가 없어 소리 설정은 넣지 않음(실제 제공 기능만) |
| 이용·개인정보 링크 | 아직 문서가 없어 넣지 않음. **Google 앱 게시 전에 개인정보처리방침 주소가 필요할 수 있습니다**(김PO 확인 필요) |
| 모션(사용자 의견 반영) | 장식만: 통통 걷는 예시 폰 셋(눈 깜빡임), 떠오르는 빛 먼지, 은은한 빛, 카드·버튼 차례 등장, 제목 숨쉬기. 생활 시간·욕구·관계와 무관. 기기의 "동작 줄이기" 설정이면 모두 멈춤. 예시 폰은 플레이어 폰이 아님 |

계정 칸은 더보기의 것을 시작 화면으로 잠시 옮겨 씁니다(같은 버튼·같은 규칙, 입장하면 더보기로 돌아감).

## 2. 성격 카드 (PO-PERS-001) — 영향 분석과 작은안

### 2.1 지금 성격이 쓰이는 곳

| 곳 | 쓰는 축 | 카드가 닿을 수 있는 것 |
|---|---|---|
| 생활 후보 고르기(`life.js`) | 셋 다 | **카드 영향의 주 무대**: 도움·대화·휴식·혼자 활동 후보의 점수 |
| 행동별 수락(`accept.js`) | 친밀 지향·위험 회피 | 대화·협력·위임 응답 경향(독립 거절 조건은 카드와 무관하게 유지) |
| 공로 기록 흐름(`credit.js`) | 공정성 민감도 | 확인 부탁 의사(말할지 여부) |
| 말투(`dialogue.js`) | 친밀 지향 | 대사 톤 |
| 관계 원장(`core`) | 공정성 민감도(호혜성 배수) | **카드는 닿지 않게 둡니다**(PO-PERS v1.1 §1: 성격은 관계 변화의 독립 source 아님) |
| 성격 화면(`app.js`) | 셋 다(프리셋·27조합) | 카드 화면이 들어갈 자리 |

### 2.2 작은안

1. **저장 계약**: 폰에 `cards = { schema: 1, rule_version, card_ids: [], effective_from_tick }` 를 따로 둡니다. 기존 3축(`trait`)은 그대로이며 카드 때문에 다시 뽑지 않습니다. 바꿀 때마다 이전 카드 묶음을 `card_history` 에 남깁니다(최근 몇 개만).
2. **과거 재생**: 관계 원장은 카드를 읽지 않으므로 과거 점수는 카드 변경과 무관합니다(PERS-C08). 생활 후보 기록(`trace`)에는 그때 카드 묶음을 함께 남깁니다.
3. **영향 방식**: 카드는 **유효한 후보 안에서 점수만** 조정합니다. 후보 자격·거절 조건·피로·권한·상대 응답은 그대로(PERS-C05). 카드별 조정은 상한이 있고, 3장 합계도 상한을 둬서 3장이 늘 최적이 되지 않게 합니다(PERS-C06). 순서와 무관하게 카드 묶음을 정렬해 씁니다.
4. **첫 4종 후보 변화(제안, 수치는 김시스템 명세 후 확정)**
   - 다정한: 도움·안부 후보 가산, 상대 거절 수용 대사
   - 욱하는: 인지한 불일치에 확인 부탁 후보를 더 빨리(사실·인지가 있을 때만, 갈등 생성 없음)
   - 고집 센: 설명을 들은 뒤 바로 받아들이는 경향을 낮춤(새 근거가 있으면 수용 가능)
   - 독립적인: 혼자 활동·휴식 후보 가산, 공동목표 협력 후보는 유지
5. **화면 노출**: 기능이 있는 카드만 선택 가능하게 보입니다. 지금은 화면에 넣지 않았습니다(결정: 기능 없는 카드를 플레이 가능처럼 보이지 않음).
6. **계정 저장·두 방 호환**: 카드는 저장본 안의 폰 자료라 계정 저장(SB-0004)과 두 방에 그대로 실립니다. 저장 형식 번호를 올리고(옛 저장본 백업), 계정 서버의 허용 형식 범위도 함께 올립니다(SB-0005 로 묶음).

### 2.3 작업량과 반영 차수

| 일 | 작업량 | 막는 것 |
|---|---|---|
| 저장 계약·형식 변환·백업·시험(15세트 입력·순서·중복·상한) | 약 1일 | 없음 |
| 카드 선택 화면(0~3장, 미리보기·취소·저장, 기존 폰 제안) | 약 1일 | 김디자인 와이어프레임(없으면 기존 스타일로 먼저) |
| 첫 4종 행동 영향·대사 연결·PERS-C01~12 시험 | 약 1.5일 | **김시스템 PERS-SYS-001(가중치·상한)**, 김플레이 PERS-PLAY-001(대사) |

합계 약 3.5일. 순서 제안: 두 번째 방 → 성격 카드(저장 계약은 두 방의 저장 형식 변경과 한 번에 묶어 형식을 한 번만 올림) → 국소 분쟁 250.
