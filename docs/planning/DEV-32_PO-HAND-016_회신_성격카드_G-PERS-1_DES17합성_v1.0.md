## 3. G-PERS-1 구현 내용

### 3.1 점수 단위 대조와 적용
- 김시스템 표의 값(+12 등)은 기존 후보 점수 단위와 같은 크기(성향 한 단계 = 6~30점, 변동 ±5)라 **변환 없이** 썼습니다. ±14 상한은 성향 한 단계보다 작아, 카드가 기질·욕구·관계를 덮지 않습니다.
- 합성: |값| 내림차순(동률은 명세 ID warm·quick·firm·independent 순) → w1 + w2/2 + w3/4 → 마지막 1회 0에서 먼 쪽 반올림 → ±14.
- 저장 ID ↔ 명세 ID: `kind`=warm(다정한), `hot_tempered`=quick(욱하는), `stubborn`=firm(고집 센), `independent`(독립적인). 저장 ID는 PO-HAND-011 계약 그대로.

| 후보(코드 kind) | 명세 행 | 다정한 | 욱하는 | 고집 센 | 독립적인 |
|---|---|---:|---:|---:|---:|
| rest | rest | 0 | 0 | 0 | +12 |
| work | work | 0 | 0 | 0 | +8 |
| social(이야기 자리) | social | +4 | 0 | 0 | −5 |
| meet | meet | +6 | 0 | 0 | −8 |
| assist | assist | +11 | 0 | 0 | **0**¹ |
| repair | repair | +4 | 0 | +2 | 0 |
| credit_check | credit_ask | +3 | +12 | +3 | 0 |
| record·read_board·correct_record·deliver | (표에 없음) | 0 | 0 | 0 | 0 |

¹ 독립적 +3 은 "상대 요청·동의한 공동 목표" 조건이 게임에 아직 없어 적용하지 않음(blocked_condition_undefined).

### 3.2 저장·수정·되돌리기
- 0~3장, 중복·4장·지원하지 않는 ID는 거절. 정렬해서 저장. 같은 세트로 다시 저장하면 버전 그대로.
- 카드 변경은 외형·성향과 **한 번의 저장(commit)**. 저장 실패면 카드·성향·외형 모두 이전 상태(시험).
- `effective_from_order` = 변경한 순번. 이미 시작한 행동은 그대로 끝나고, **다음 후보 선택부터** 새 카드. 생활 기록(trace)에 선택 당시 카드 세트·규칙 버전을 남김. 지난 기록·관계·기억·사건은 바뀌지 않음(시험).
- 기존 폰·옛 저장본은 카드 0장 그대로(자동 부여 없음). 모르는 규칙 버전·맞지 않는 카드 칸이 든 저장본은 열지 않음(원본 보호).

### 3.3 화면
- 성격 화면 맨 위에 "성격 카드 n/3장": 카드 이름·한 문장·"이럴 때" 예시. 3장이면 나머지는 잠김. 선택은 민트 테두리(좋고 나쁨 표시 아님).
- 증거: `docs/evidence/pers/pers01-pc-card-select.jpg`, `pers02-phone-card-select.jpg`.
- 문구는 PO-PERS-001 §3 표를 줄인 개발 임시안. 김디자인 카드 시안·김플레이 문구가 오면 교체.

## 4. 15세트 진단(같은 월드·seed, 첫 폰만 카드 변경, 1500 tick)

`node scripts/game1_cards_diagnostics.mjs 1500` → `docs/evidence/pers/cards-diagnostics-1500.txt`. 대표값:

| 카드 | 고른 행동 비율 rest/work/social/meet/assist(%) | 만남이 후보일 때 고른 비율 |
|---|---|---|
| 없음 | 33 / 16 / 18 / 23 / 8 | 37% |
| 다정한 | 34 / 20 / 13 / 26 / 5 | 36% |
| 독립적인 | 35 / 19 / 26 / 11 / 10 | **17%** |
| 다정한+독립적인 | 33 / 23 / 17 / 21 / 5 | 31% |
| 욱하는, 고집 센 (단독·둘) | 없음과 같음 | 37% |

읽는 법과 한계(있는 그대로):
- **독립적인**은 차이가 뚜렷함: 다가가 말 거는 만남이 절반 이하로 줄고, 혼자 쉬기·작업·이야기 자리 혼자 가기가 늘어남. 협력 제안을 받으면 수락은 상대 반응 규칙 그대로.
- **다정한**은 차이가 작음: 이 월드에서는 도움 후보가 생기면 카드 없이도 이미 100% 고름(도움 후보 자체가 드묾). 만남 후보는 늘었음. 다정함이 잘 드러나려면 "도움이 필요한 상황"이 더 자주 생겨야 함(김플레이 장면·김시스템 분포 검토 필요).
- **욱하는·고집 센**은 기본 생활에서 차이 없음: 두 카드가 바꾸는 후보는 "본인이 실제로 알고 있는 기록 누락의 확인 부탁"뿐이고, 이 후보는 기록 흐름에서 누락을 읽었을 때만 생김. 카드만으로 질문·항의를 만들지 않는 것이 계약(PERS-C12)이므로 정상. 실제 차이는 G-PERS-2 에서.
- 1회 seed·폰 3명 시뮬레이션이라 분포 확정값이 아님. 김시스템의 분포 보정 검토 자료로 씀.

## 5. G-PERS-2 연결 계획(의미 action 매핑)

지금 기록 흐름(credit.js): 도움 완료 → C 기록(목격 기준) → B 열람(누락 인지) → B 확인 부탁(`credit_check`, OpenIssue) → C 재확인·정정(`correct_record`) → C 전달(`deliver`) → B 인지 → EVT-09.

| 명세 행동 | 지금 코드 | 계획 | 상태 |
|---|---|---|---|
| credit_ask(근거 있는 확인) | `credit_check` | 카드 보정 적용 완료 | 연결됨 |
| credit_review(증거 재검토) | `correct_record`(부탁받은 C 가 기록 재확인) | 같은 행동에 review 보정(+2/+8/+10) 연결 제안 | **정연우 의미 확인 후 적용** |
| credit_state_standard(기준 설명) | 없음. 지금은 재확인하면 항상 정정 | C 가 "목격 3칸 밖이라 적지 않았다"는 실제 기준을 B 에게 설명하는 분기 추가. 정정 대신 설명으로 끝날 수 있음 | blocked_action_undefined(정정 vs 설명 갈림 조건 필요) |
| credit_accept_explanation(설명 수용) | 없음 | B 가 설명을 들은 뒤 OpenIssue 를 "설명 듣고 닫힘"으로 종료. 관계 효과 0, 기억은 남김 | 정연우: 종료 상태 이름·기억 문구 |
| express_discomfort(불편 표현) | 없음(확인 부탁 말풍선 안에 서운함 표현 있음) | 독립 kind 는 후순위(PO 허용). 확인 부탁 경로의 표현 유지 | 후순위 |

필요한 결정(김PO 경유): ① 재확인 결과가 "정정"이 될지 "기준 설명"이 될지 갈리는 조건(실제 목격·기록 규칙에 근거), ② 설명 수용 종료 상태의 이름과 기억 문구(정연우), ③ 대사 정본(김플레이 PERS-PLAY-001 미수신). 예상 작업량: ①②가 정해지면 약 2일(행동 2개 + 시험 + 장면 증거).
