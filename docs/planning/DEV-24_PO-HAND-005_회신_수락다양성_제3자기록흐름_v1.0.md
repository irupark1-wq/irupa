## 3. 제3자 기록 흐름 (credit.js, 규칙 `CREDIT-RULE-workbench-v1`)

### 3.1 흐름과 저장 필드

1. **도움 완료**(원천, 불변): `credit.helps[action_id] = {worker:A, helper:B, tick, witnesses}`. 도움 영수증은 이후 어떤 기록 오류로도 고치지 않습니다.
2. **C 의 결과 기록**(작업대 기록판, 4틱): `credit.records[id] = {writer:C, true_contributors:[A,B], recorded, omitted, rule_id, rule_applies, revision}`. C 가 B 의 참여를 본 근거가 있으면 B 가 기록되고, 근거가 없으면 B 가 빠집니다.
3. **B 의 열람**(작업대에 갈 때 지나가며, 또는 일부러 2틱): `readers[B] = {revision}`. 사실 인지(이유 미확인) 기억 1개. **감정 변화 0**.
4. **확인 부탁 의사**: 공정성 민감도에 따라(변형 A/B) B 가 말할지 정합니다. 말하지 않으면 `observed` 로 남습니다.
5. **확인 부탁**(B→C 대화): C 가 받으면 `verification_accepted`, 바쁘면 `verification_pending`(35틱 뒤 재시도, 하루 2번 상한, 벌점 0).
6. **C 의 정정**(3틱): 도움 영수증에 B 가 있을 때만. `revision` +1, `corrected_by:C`, `correction_action_id`(새 source).
7. **전달**: C 가 B 에게 알리거나 B 가 고쳐진 기록을 다시 읽음. B 가 정정자를 알면 **B→C EVT-09**(존중 +15, 호혜성 +18). 모르면 사실만 갱신.

열린 확인사항(issue) 상태: `observed → intends_request → verification_pending ↔ verification_accepted → correction_published → resolved_record`.

새 저장 필드: `state.credit`(schema 1, variant, helps, records, issues), `state.init_rule`, `state.world_seed`. 각 상자 최근 60개 보관. 기존 저장본은 불러올 때 `credit` 빈 상자만 추가되고 다른 값은 바뀌지 않습니다.

### 3.2 목격 모델(작은안)

"권한 있는 단순 관측": 같은 소유자의 다른 폰이 도움 순간(수락 시점과 완료 시점) 작업자에게서 3칸 이내에 있고 쉬는 중이 아니면 본 것으로 기록합니다. 가림·시선 방향은 아직 없습니다. **"본 근거 없음"은 "못 봤다고 확정"이 아닙니다.** 그래서 누락은 고의가 아니라 사실로만 남습니다.

완전 시야 모델(가구 가림·시선)은 비용이 큽니다(약 2~3일). 지금 단계에는 필요하지 않다고 봅니다.

## 4. 실제 갈등(Conflict) — blocked, 변경 요청(CR) 제안

PO-HAND-005 v1.1 DEC-SC-02 에 따라 "확인사항 반복"을 갈등으로 바꾸지 않았습니다. 정의가 정해지면 아래처럼 넣을 수 있습니다. **정연우 검수 + 김PO 결정이 필요합니다.**

| 항목 | 제안 |
|---|---|
| 계기(trigger) | C 가 확인 후 "B 는 기여하지 않았다"고 실제로 반대 입장을 표명하고, B 가 도움 영수증을 근거로 다시 이의를 제기(두 번의 실제 대화 action) |
| 행동 증거 | 반대 표명 action id 2개, 원 도움 source, 기록 source |
| 영향 | 기록 미정정 상태 지속(공로 표시 손실) |
| severity | 정연우 정의 대기(180 임의 적용 안 함) |
| 해결 조건 | 정정 게시 + 전달 + 별도 복구 계획 수락·이행(EVT-12). 정정만으로는 해결 안 됨 |
| 비발생 반례 | C 바쁨·미회신·권한 없음·기술 단절·확인 시간 요청, 정정자 미인지, 기준 없는 메모 |
| 비용 | 정의 확정 후 약 1~2일(반대 표명 행동, Conflict 생성 연결, 시험) |

## 5. 말풍선 PNG(DES-09) 렌더 검사

- 9-slice 36px 로 본체 PNG 를 붙였을 때, 크기마다 조각 사이에 **가는 이음선**이 보였습니다(폭 12/16/18px, 늘림·반복 모두). 원인 하나는 본체 안쪽 투명도가 254(완전 불투명 255 아님)인 점이고, 그것을 고쳐도 Chrome 조각 경계선이 남았습니다.
- 그래서 **본체는 PNG 에서 잰 값으로 CSS 로 그립니다**(외곽선 #624430 2px, 크림 #fcf4e1, 둥근 모서리 12px). 본체 PNG 가 단순 둥근 사각형이라 겉모습은 같습니다.
- **꼬리 PNG 는 채택**(18×12 로 표시, 본체 아래선을 2px 덮어 이음새 없음). 안쪽 투명도 254 → 255 만 고친 사본을 `prototype/assets/ui/` 에 두었고, 원본은 `docs/reference/design-20261013-g/`(로컬 보관)에 그대로 있습니다. 쓰지 않는 본체 PNG 는 배포 폴더에 넣지 않았습니다.
- 확인한 것: 한 줄·두 줄, 220px(PC 13px)·170px(모바일 12px), 짧은 "응." 캡처 `docs/evidence/hand005/speech-bubble-des09.png`.
- 김디자인님께: 9-slice 로 쓰려면 안쪽 알파 255 인 본체가 필요합니다(REQ-05 에 적음).

## 7. 말풍선 대사 — 정연우 검수용 제출

- 파일: `prototype/dialogue.js` (출처 표시 `dev-provisional-v1`, 개발 임시 문구. 김플레이 대사팩 채택 시 표만 교체).
- 이번 추가 상황 5개:
  - `credit_ask`(B→C): "기록에 내 이름이 없네. 확인해 줄래?" 외 말투별 6개
  - `credit_ask_accept`(C): "그래, 다시 볼게." / "응, 확인해 볼게."
  - `credit_ask_pending`(C): "지금은 어려워, 이따 볼게." / "하던 일 끝나고 볼게."
  - `credit_fixed`(C→B, 전달 시): "기록은 고쳤어." / "작업 기록 다시 적어 뒀어."
  - `credit_ack`(B): 따뜻 "확인했어, 고마워." / 보통 "확인했어." / 무뚝뚝 "…확인했어."

- 일지 문구도 DLG-05 에 맞춰 "작업 기록에 내 이름이 빠진 것을 봤어요 · 이유는 아직 몰라요" 로 바꿨습니다.
- 호출 규칙: 저장이 확정된 생활 기록만 말풍선이 됩니다. 같은 기록은 항상 같은 대사이고, 재생·새로고침으로 새 대화처럼 다시 연출하지 않습니다. 혼자 기록판을 읽는 일은 대화가 아니므로 말풍선이 없습니다.
