- 기준: PO-REQ-001 v1.0. A2 기반 결과는 DEV-22.

## 1. 결론

- **"모두 친절하고 불화가 드물다"의 원인은 빈도가 아니라 콘텐츠 미구현입니다.** 실제 생활에서 부정 사건과 갈등이 생기는 경로가 하나도 없습니다. 거기에 모든 관계가 같은 값에서 출발해 위로만 움직입니다.
- 이번 버전에 넣은 것은 세 가지입니다. ① 폰 위 대화 말풍선(기록 기반, 개발용 임시 대사), ② 관계창 개편(방향·요약·8축·최근 사건 사실/해석·근거), ③ 원인 점검에서 찾은 기록 오류 수정("자리 점유"를 "길 막힘"으로 잘못 남기던 것).
- **넣지 않은 것은 생활 속 갈등 생성(STORY-C)입니다.** PO-REQ-001 이 "미정 갈등 규칙은 외주·관계 검수 뒤 적용"이라고 했고, 정연우 REQ-01 잔여 답변과 OUT-SYS-003 이 필요합니다(4절).

## 3. 이번에 반영한 것

### 3.1 폰 위 대화 말풍선

- **언제:** 저장이 확정된 생활 기록에서만 나옵니다. 제안→수락/거절, 대화 완료, 중립 대화, 도움 제안·수락·거절·완료, 복구 제안·수락·완료가 해당합니다. 접근만 한 상태나 혼자 하는 활동에서는 말하지 않습니다.
- **무엇을:** 상황 17종에 각각 2개 이상의 변형이 있습니다. 말투(무뚝뚝함)는 성격의 친밀 지향에서, 따뜻함은 화자 자신의 방향 애정·신뢰에서 정합니다. 무뚝뚝한 말투와 낮은 애정은 따로 판단합니다. 방문 폰이 끼면 관계 정보 없이 일반 말투를 씁니다. 대사에 숫자, 속마음, 미인지 사실은 들어가지 않습니다(자동 검사).
- **같은 기록 → 같은 대사:** 다시 열거나 정정이 replay 되어도 지난 대화를 새 대화처럼 다시 말하지 않습니다. 화면을 처음 그리기 전의 기록은 말하지 않습니다.
- **표시:** 폰을 따라 움직이고, 뒷줄 폰에 가려지지 않게 맨 위층에 그립니다. 다른 말풍선과 겹치면 한 칸 위로, 화면 밖이면 안쪽으로 옮깁니다. 표시 시간은 실제 2.2~4.5초(글자 수 비례)로 생활 속도와 분리했습니다. 폰마다 대기열은 최대 2개입니다.
- **읽기:** 말풍선을 누르면 생활이 멈추고 그 말풍선이 ▶ 를 누를 때까지 남습니다. 더보기에서 켜고 끌 수 있습니다. 생활 일지에도 대사가 “…” 로 남습니다.
- **대사 출처:** 개발용 임시 문구(`dev-provisional-v1`)입니다. 김플레이 대사팩(OUT-PLAY-002)을 채택하면 표 하나만 바꾸면 됩니다.
- 상태 글자("이동하고 있어요" 등)는 선택한 폰에만 보이게 했습니다. 상태는 작은 아이콘 말풍선으로 계속 보입니다.

### 3.2 관계창

1. 머리말: 두 폰 얼굴과 이름, A→B 방향, 같은 소유자끼리면 "반대 방향 보기".
2. 요약: 실제 판정된 관계 설명(없으면 "아직 정해진 관계 설명은 없어요."), 최근 알게 된 일(사실+해석), 마지막 변화(저장된 변화량).
3. 8축: "마음"(애정·신뢰·존중·갈등)과 "관계 구조"(의존·권력·호혜성·의무) 두 묶음. 이름, 짧은 설명, 수치, 막대를 모두 보여 줍니다.
4. 최근 사건: 사실 / 해석 / 이유 / 해결을 따로 보여 줍니다(해당 없는 항목은 생략).
5. 근거: 실제 엔터티가 있을 때만 갈등·역할·자원·약속을 보여 줍니다. 권력 근거가 없으면 "공동 결정 기록 없음 (권력은 기본값)".
- 다른 소유자 방향은 공개 정보만 받습니다("이 방향은 공개된 정보가 없어요."). 잠금 아이콘 뒤에 숫자를 두지 않습니다.
- 한국어 조사를 이름 받침에 맞게 자동으로 고릅니다("모래가 보는 밤", "밤과 인사하고").

- 화면: PC 1440×900·폰 375×812 에서 말풍선 대화(제안·거절 쌍), 누르면 멈춤·유지, 관계창 위·아래. 증거는 `docs/evidence/req001/`.
- 영어·일본어 대사·문구 106줄 추가.
- 확인하지 못한 것: ×4 에서 오래 돌렸을 때 말풍선 대기열의 체감. 브라우저 창이 가려지면 타이머가 늦춰져서, 짧게만 확인했습니다. 실제 휴대폰 기기 확인도 하지 않았습니다.

**개발 제안(검수용, 채택 전):**

- 수락 판단에 애정(가까이 있고 싶은가)과 존중(같이 일할 만한가)을 따로 씁니다. 대화 제안은 애정과 친밀 지향, 작업 도움은 존중과 공동 목표를 봅니다. 그러면 "싫지만 존중해 협력"이 생깁니다.
- 신뢰는 "중요한 맡김"(가벼운 위임) 수락에만 강하게 씁니다. 그러면 "좋아하지만 못 믿음"이 대화는 받고 맡김은 거절하는 차이로 보입니다. 위임 정의가 확정되어야 합니다.
- 신뢰가 낮을 때 모든 제안을 끊지 않고, 짧은 인사만 받고 긴 대화는 거절하는 단계형으로 바꿉니다.
- 관계 초기값을 쌍마다 조금 다르게 시작하는 선택지를 둡니다(예: 애정 ±40, 존중 ±60). 시험값이며 PO 결정이 필요합니다.
- 갈등은 PO-REQ-001 대로 실제 공동작업 공로 기록에서만 시작합니다. 공로 기록자가 협력자 참여를 직접 보지 못한 경우에만 이름이 빠지게 합니다(REQ-02 제안). 고의 분기는 만들지 않습니다.

**작업량(추정, 입력 수령 뒤):** STORY-C 생활 연결 3~4일, 반응 모델 1~2일, 대사팩 반영 0.5일, 말풍선·관계창 디자인 스킨 0.5~1일. 완료일은 새로 약속하지 않습니다(PO-REQ-001 §6).
