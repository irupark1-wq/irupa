# 김도현 → 김PO·정연우·윤디자인 통합 개발 회신

2026-10-13. 대상: 김PO 개발착수 검토회신 05, 정연우 전달 ZIP v0.4, 윤디자인 전달 ZIP(본문 작성자는 김디자인). 전달용 문서이며 다른 채팅에 실제 발송하지 않았다.

세 자료를 읽고 최신 김PO 결정과 각 담당자의 제안을 구분했다. 첨부의 과거 사용자 발언은 이 채팅의 직접 승인으로 처리하지 않는다. 원본은 `docs/reference/po-v0.3`, `rel-v0.4`, `design-v0.4`에 보존했다. 제안 JSON의 production 승인 플래그는 변경하지 않았고 운영 데이터로 가져오지 않았다. 디자인 ZIP은 Markdown 4개로, 실제 투명 PNG나 클릭 시제품은 포함되지 않았다.

## 김PO 보고: 실제 구현과 남은 작업

허용된 계약·순수 로직 범위에서 `src/contracts/game1-traits.ts`를 구현했다. 성격 3축 검증, 27조합, 6프리셋, 확정값의 불변 복사, 승인 범위 정규화, 동일 authority stream 내 순서 비교, 제한된 공정성 배율 및 슬롯별 clamp 계산을 포함한다. 서로 다른 stream의 순서는 비교하면 오류를 반환한다.

Node 24에서 `node --test tests/game1-contracts.test.mjs` 10개가 통과했다. 이는 계약과 계산의 단위 검증이다. 실제 저장 트랜잭션, 재접속, 권한, 전체 사건 원장, 27개 공방 경로, 화면 QA의 통과를 의미하지 않는다. TypeScript는 Node의 타입 제거로 실행했으며 별도 정적 타입 검사는 아직 구성하지 않았다. CI에도 같은 검사를 추가했지만 원격 CI 통과는 실행 결과를 확인해야 한다.

W01/W20의 기초 구현을 시작했고 W20~24 전체를 완료로 처리하지 않는다. 후속 순서는 (1) 사건 슬롯·인지 정정·멱등 원장 및 파생축 fixture (2) 공방 선택·승인·중단 DTO와 27경로 (3) 원형 합성/그리기 시제품 (4) 화면 저장·충돌 검수다. 실제 Auth 설정, 운영 DB 마이그레이션, 배포는 이번에 실행하지 않았다. 기존 보안 기준과 game1_/GAME1_ 이름 규칙을 계속 적용한다.

## 정연우 확인 요청 8개 회신

| 질문 | 결정·개발 처리 | 현재 상태 |
| --- | --- | --- |
| 1 승인 범위 | canonical은 activity_participation, light_auto_events, role_commitment, public_relation_declaration, major_transition. light_autonomous_events/responsibility_acceptance/public_relationship_declaration은 명시적 문서 가져오기에서만 변환한다. wire에서는 거절한다. | 정규화 함수·테스트 구현. 실제 기존 DB 이관 대상 없음 |
| 2 EVT07/08 계보 | 같은 지연에 대한 사유 인지는 기존 source 슬롯의 knowledge revision으로 교체한다. 독립 행동 EVT08에는 별도 action evidence가 필요하다. 구조적 정정은 correction_id로 중복 차단하며 감정 보상과 분리한다. | 설계 수용, 원장 구현 대기 |
| 3 태그 | v0.1 기본 namespace 유지, rel_tags_exp_v03은 실험용. 진입/이탈 카운터는 서로 다른 유효 source 사건 2개를 요구하며 인지 revision 재전송으로 증가하지 않는다. 역할 상태는 확정 후 즉시 반영한다. | 설계 수용, projection/카운터 대기 |
| 4 파생축 | ResourceLink, DecisionRole, acceptedCommitment, Conflict에서 계산하고 승인된 근거가 없으면 권력 500과 '공동 결정 기록 없음'을 제공한다. 과거 power520/550 예시는 debug reference로만 남긴다. | 입력 fixture 및 계산 대기 |
| 5 성격 적용 | snapshot은 사건 권위 경계에서 고정한다. 성격 저장 effective_from은 authority_stream_id와 authority_order_id를 함께 가진다. 과거 재해석/재시도는 기존 snapshot, 이미 승인된 비용은 기존 payload를 유지한다. 서로 다른 instance 순번을 비교하지 않는다. | 순서·snapshot 보조 함수 검증. 실제 동시 저장은 미검증 |
| 6 배율 | 인지된 EVT09/10의 reciprocity contribution에만 low/medium/high=0.8/1/1.2 적용. 기본 +18→+14/+18/+22, -30→-24/-30/-36. 정확한 유리수 반올림은 절댓값 절반에서 0 바깥 방향. 다른 축·갈등값은 그대로다. | 계산·경계 테스트 통과. 사건 적법성 판정은 별도 |
| 7 공방 비용 | time5/material3은 테스트 전용 포인트. 실제 통화·active_tick과 필드/namespace를 분리하고 운영 밸런스로 수입하지 않는다. | 계약 수용, DTO 대기 |
| 8 정정/회복 | EVT09는 정정과 전달 확정 근거, EVT12는 conflict_id/topic/scope와 repair_plan 실행·수용 근거를 갖춘 별도 단계다. 동일 action evidence의 재전송/재해석으로 이중 보상하지 않는다. | 설계 수용, 원장 및 회복 fixture 대기 |

승인 payload의 scope/participants/content_hash/version은 변경하지 않는다. 이름 누락만으로 고의 독점 EVT10을 생성하지 않는다. 본인 퇴장, 거절, 만료, 기술 중단에는 감정 벌점을 생성하지 않는다. 3라운드 각 3선택의 27경로는 검증할 계획이며 이번 27 성격 조합 테스트와 구별한다.

## 윤디자인 전달자료의 DEV-CHECK 6개 회신

| 항목 | 기술 회신 |
| --- | --- |
| 01 canonical | 위 김PO 최신 5개 값을 UI/API 기준으로 사용한다. 이전 문서 alias는 wire enum으로 노출하지 않는다. |
| 02 최초 생성/저장 | 최초 CreatePawn은 검증된 staging asset을 참조해 pawn·appearance version·trait profile의 메타데이터를 하나의 트랜잭션으로 확정하는 방식을 제안한다. 반쪽 활성 폰을 노출하지 않는다. 외형/성격 초안은 개별 보존, 재시도는 동일 command_id, 화면 이탈은 전송된 명령의 취소로 간주하지 않고 결과를 조회한다. 후속 SaveAppearance/SaveTraitProfile은 각각 expected_version과 중복 명령 처리를 둔다. 실제 서비스는 아직 미구현이다. |
| 03 성격 DTO | `fixtures/game1-trait-ui.json`에 기본 선택, dirty 저장 applied, 버전 conflict의 고정 예시 3개를 제공했다. applied의 profile_version/effective_from, conflict의 기존 초안, reason_key/allowed_actions를 포함한다. Preview는 own/sample 문맥 예시만 있고 타인 성격·확정 수치 예측은 없다. 이 파일은 응답 계약 예시이며 동작하는 API가 아니다. GetTraitOptions의 표시 문구·정렬 DTO는 다음 계약 작업에 포함한다. |
| 04 적용 시점 | traits.saved_future_only와 '저장 이후 새 행동·사건에 적용' 문구를 사용한다. 과거 변경 연출 금지. 비교는 동일 authority stream에서만 한다. 실제 동시 저장/사건 race 검증은 미완료다. |
| 05 원형/입력 | 편집기와 월드는 동일한 합성 규칙을 사용할 수 있다. base의 circle display clip과 균등 scale은 필수다. eyes/mouth는 원본 비파괴 input_clip=none, display_clip=circle을 제안하되 디자인 확정 전이다. hair/accessory는 바깥 표현 허용. Canvas2D의 별도 레이어 canvas, 역변환 좌표 입력, PNG 합성은 가능하나 메모리·용량·브러시 지연·실기기 검증이 필요하다. 표정 없는 파츠도 8모션과 감소 모션을 지원하도록 구현한다. 합성 실측은 아직 하지 않았다. |
| 06 공방/관계 | test_balance를 통화와 구별하고 알려진 비용/불확실성만 사전 표시한다. 승인/중단/인지/확정 결과는 별도 상태다. 허용된 자기 양방향, 비공개 반대 방향 scores=null, 근거 없는 power500의 DTO는 다음 fixture 납품 대상이며 아직 제작 완료가 아니다. |

이번 예시 reason_key는 traits.saved_future_only, traits.version_conflict, traits.example_not_guaranteed다. actions는 fixture의 traits.preview/pawn.create/traits.edit/traits.compare_latest/traits.reapply_draft다. 이는 UI 표시 식별자이며 권한 토큰이 아니다. 서버는 모든 명령의 소유권·승인·현재 상태를 다시 검증해야 한다. 전체 관계/공방 reason_key 목록은 DTO가 확정되는 단계에 추가한다.

## 디자이너에게 필요한 후속 납품

빈 원형 편집기·성격 3축 카드의 기본/저장 중/실패/충돌 시안, 자기 방향·비공개 방향·빈 기억 관계 시안, 공방 승인·기술 중단·확정 결과 시안을 요청한다. 투명 PNG 6슬롯(base/eyes_pair/mouth/back_hair/front_hair/frame_accessory), 합성 샘플, manifest를 함께 받으면 입력/출력 clip·피벗·8모션을 실제 검증할 수 있다. 48/64/96px 비교와 eyes/mouth display clip 결정도 필요하다. 512px 및 파일당 1MiB/버전당 8MiB는 실측 전 임시 기준이다.

검토 문서와 검증 결과는 수령자에게 전달할 수 있는 형태로 작성했으며 실제 외부 메시지는 보내지 않았다.
