## 파생축 계약

비율 입력은 importance_permille/contribution_permille/irreplaceability_permille/share_permille의 정수0~1000으로 고정했다. 문서의 0.8/0.75/0.9를 각각800/750/900으로 명시 변환하는 시험 입력이다. 복수 자원 기여 합은[0,1]에 clamp하고 최종 점수에서 half-away 반올림한다. 의존은540, 대체곤란400으로 바꾸면241이다. 역할 지분은 중요도 가중 평균이며 근거가 없으면500/no_active_basis다. 활성 수락 부담과 활성 갈등 severity는 각 최댓값, 없으면1이다. 입력 ID·중복·방향·값·active/accepted 타입을 검사한다.

과거 power520/550은 사용하지 않았다. 감사나 도움 완료 자체는 새 활성 부담을 만들지 않는다. 공방 H의 완료된 도움에 자동 장기 의무를 부과하지 않는다. R의 수락된 역할 예시에는 시험 burden700을 사용했으며 실제 계약 부담을 확정한 것이 아니다. 갈등은 원천별 direction/scope/topic을 보존하며 이번 계산기는 읽기만 한다. 실제 복구 상태 전이는 아직 미구현이다.

## 공방27경로와 실패 처리

받은27개 경로 ID·선택ID·명목 비용을 실행 결과와 일치시켰다. C는 정정+전달 근거 및 밤의 인지 이후 EVT09, H는 승인+도움 완료 및 모래의 인지 이후 EVT04를 시험 projection에 기록한다. D는 진행도만, V는 지식갱신만, A는 실제 대안확보가 확인되면 의존만 바뀐다. R/P/S는 필요한 별도 승인 없이는 확정하지 않는다. C를 EVT12로 자동 확대하거나 D를 EVT10으로 단정하지 않는다. P/S/E는 자동 친구/화해를 만들지 않는다.

실패8종: 고객전달 미확정, 도움 승인 거절, 학습 미완료, 새 책임 거절, 정산 거절 중 본인 퇴장, 고의 미입증 유예, 동일 command 재전송, 연결 단절을 검증했다. 불가 응답은 공개 가능한 reason_key와 재선택/중단/퇴장 행동을 제공한다. 동일 완료 command는 원 receipt를 반환하며 비용/효과를 다시 적용하지 않는다. commandID에 다른 선택을 넣으면 충돌이다. 연결 문제는 paused이며 감정 벌점0이다. 자기 퇴장은 연결·예산·상대 정산 승인과 무관하게 즉시 허용된다.

시험 비용 규칙: 성공한 단계를 확정할 때 fixture_points만 차감한다. 실패/대기는 차감0. E의 본인 퇴장은 무료이며, R3의 인계가 확인되고 시험 예산이 있을 때만 명목시간1을 차감한다. 인계 미확정은 settlement_pending이며 상대 부담은 변경하지 않는다. **이 비용 규칙은 로컬 시험 모델의 명시적 가정이다. 실제 차감/환불/정산 정책은 별도 확정이 필요하며 운영 경제로 승격하지 않는다.**

성격27조합과 경로27개는 별도 시험이다. 이번에는 기본성격27경로와 각축 low/high의 대표6사례를 실행했다. 친밀/위험회피의 정성적 후보 선호 가중치는 미정이므로 새 수치/확률을 만들지 않고 권한·비용·기초결과가 변하지 않는지만 검사했다. 전체729는 실행하지 않았다.

공방은 메모리 시험기로 실제 EventLedger/DB/outbox와 아직 연결되지 않았다. effects는 시험 projection이며 영구 원장 commit의 증거가 아니다. 동의 조건도 시험 입력 가정이며 실제 JWT·승인 payload·소유권 검증을 대신하지 않는다. 향후 어댑터는 검증된 서버 상태만 전달해야 한다.

## 관계 응답의 비공개 경계

observer 소유자가 아닌 요청에는 내부 데이터 조회 없이 항상 동일 restricted 응답을 반환한다. scores=null이며 사적 기억/태그/성격/차단/존재 이유를 넣지 않는다. 본인 방향은8축 allowlist, 인지된 기억의 id/사유인지/해결 상태만 제공하고 추가 내부 필드를 버린다. 둘 다 본인 소유일 때만 reverse 행동을 제공한다. 태그 필드는 아직 제공하지 않는다.

이 검증은 **순수 응답 함수의 누출 방지**다. requester/owner 정보는 장차 서버가 인증·DB로 확보해야 하며 클라이언트가 보낸 값으로 호출해서는 안 된다. 서버 API·알림·preview·대사·로그 전체 경로의 보안 검증은 아직 아니다. 공개 선언 scope에 따른 추가 공개도 이번에는 구현하지 않고 기본 비공개를 유지했다.

## 디자인 실제 파일 점검

PNG6개는512×512,8bit RGBA,CRC,압축 scanline/필터 디코드,해시,파일별 bytes,투명/가시 픽셀을 확인했다. 전체 압축파일86,894바이트, 디코드 RGBA 합6,291,456바이트(6MiB). 각각1MiB/합8MiB의 임시 파일 예산 이내다. 실제 앱은 canvas·undo·합성 버퍼를 추가로 사용하므로 이 값은 총 메모리 사용량이 아니다.

manifest의6슬롯 순서,중심pivot,단위scale,기본회전0을 검사했다. **브라우저 합성·좌표역변환·지우개·20undo/redo·8모션·DPR·48/64/96 실기기·입력지연·CreatePawn은 미실행**이다. display_clip 기본값은 미결로 보존하며 파일 검증이 원형 표시나 A/B 런타임 검증을 뜻하지 않는다. 생성 이미지의 문구/게이지는 구현 명세로 수입하지 않았다.
