# 김도현 → 김디자인: 디자인 결정안 v0.1 기술 답변

2026-10-13 / 상태: 개발 작업 기준 제안, 김PO 최종 승인 및 구현 검증 전. 사용자 메시지로 전달된 D-01~05를 검토했다.

## 1. 반영할 작업 기준

- 최초 시안1280×720, 완전 원형1:1 본체, 자유 그리기 우선, PNG+transform+manifest, 눈pair 우선/separate 확장 예약.
- 512×512 RGBA와 월드48/64/96px 비교, 파일1MiB/버전8MiB는 실측 전 제안값.
- 최소20단계undo/redo, 파츠별 독립 편집, 저장 후PNG 재편집, 과거 세션 획별 선택은A 필수 제외.
- idle/move/happy/sad/angry/hesitate/help/work의8상태. 본체 스쿼시·스트레치 금지, 표정 파츠 없이도 동작. 승인거절/단절/만료를 감정벌점으로 연출하지 않음.
- 방향 관계/독립8축/설명최대3개/기억3차원/반대방향비공개/권력근거없음/원인 표시 및 저장·충돌 초안 보존 계약 유지.
- 약한 사선 탑다운·부드러운 비픽셀 스타일, 최종 크기·모바일·엔진은PO/시제품 검토 전 확정하지 않는다. 세션 오류·복구 안내도 실제복구지원 정책과 구별한다.

## 2. 원형 베이스 마스크: 가능합니다

편집기와 월드가 동일한 AppearanceManifest와 합성 규칙을 사용하도록 설계합니다. 원본512 기준 중심(256,256), 반지름192(원지름384)는 기존 제안 규격이며 최종 치수는 디자인 시안과 함께 확정합니다. 마스크는 렌더러별로 따로 계산하지 않고 공통 합성기에서 적용한 결과를 월드가 사용합니다. 편집 미리보기와 저장 합성도 같은 합성기를 호출합니다.

마스크는 **원형 베이스에만** 적용합니다. 전체 캐릭터를 원형으로 자르면 머리카락·프레임·장식이 잘리므로 전체 합성에는 적용하지 않습니다. 눈/입을 원형 안으로 제한할지는 별도 슬롯 정책으로 기록합니다. 원본은 비파괴적으로 보존하며 표시에서만 clip합니다.

base의 비율과 윤곽은 고정합니다. 개별 파츠에는 비균등 scale 허용 여부를 검토할 수 있지만 최종 합성 폰의 scale은 x=y로 고정합니다. 모션은 회전·위치·타이밍으로 표현합니다. 사선 배경에서도 폰 원형을 원근 투영으로 찌그러뜨리지 않습니다.

실제 검증: 동일manifest→편집/월드합성 비교, 마스크 경계 투명도, 회전·mirror·극단변환,48/64/96px, 밝은/어두운 배경,8모션에서 원형비율 유지. 아직 수행된 테스트가 아닙니다.

## 3. Canvas2D 파츠 입력: 구현 가능, 처리할 제약이 있습니다

슬롯별 독립 오프스크린 캔버스와 불변원본/현재초안을 유지합니다. Pointer 좌표를 CSS크기·devicePixelRatio·카메라 및 레이어변환의 역변환으로 원본좌표에 매핑합니다. 지우개는 선택파츠에만 적용하고 최종합성에서 지우지 않습니다. 경계정책은 입력clip과표시clip을 구분합니다. 머리/장식은 원밖여백을 보존합니다.

Pointer capture, 선보간, pointercancel, 탭비활성화, 드래그와그리기모드 구분을 처리합니다. 화면 밖에서 입력이 종료돼도 한 획을 안전하게 완료/취소하고 undo단위를 한획/한변환으로 정의합니다. 최소20단계는 유지하되 매포인터이동마다 전체512RGBA 복사하지 않고 획종료/변환완료 시 기록하며 변경영역/메모리예산을 실험합니다.

PNG는 래스터여서 확대/반복축소로 선이 흐려질 수 있습니다. transform은 원본과 분리하고 원본에서 재합성합니다. 저장 후PNG에 덧그릴 수 있지만 과거세션의 개별획을 객체로 선택할 수는 없습니다. 브러시굵기의 단위는 원본px를 제안하며 화면크기와분리합니다.

외부이미지는1차입력에서제외합니다. 프리셋은 동일origin 또는허용CORS로 읽어야 캔버스 내보내기를 막는 taint를 피할 수 있습니다. 원본·프리뷰에 동일한 생성/합성 규칙을 적용하고 서버에서PNG실제디코딩/치수/크기/슬롯수를 검사합니다. Canvas출력만으로 서버검증을 대체하지 않습니다. SDK 토큰을초안/PNG/manifest에 넣지 않습니다.

이 목록은 모든 사용자에게 일괄 부여하는 권한이 아닙니다.

각 DTO에 현재실제로허용한 key만 보냅니다. relationship.view_reverse는 두폰모두본인소유일때만 제공하며 restricted에서는빈배열입니다. 편집권한없는방문자에게world.edit_layout을주지않습니다. 참가/책임/선택/동의는별도의미입니다. 실제명령때서버가권한·버전·차단·상태를다시검사합니다.

로컬편집도구의undo/redo/브러시버튼은 UI가능상태로 관리하며 서버allowed_actions의보안권한과혼동하지않습니다. action별target/option ID는 허용된선택 DTO로별도전달합니다. 단순allowed_actions에숨은조건/상대감정설명을끼워넣지않습니다. 요청실패/권한변경후화면/캐시를최신스냅샷으로갱신합니다.

## 6. 다음 인계

김디자인님은 원형베이스/머리·장식여백/눈pair 샘플1세트와 SCR-01/04/06/07의 기본·실패·충돌 사례를 먼저 제작할 수 있습니다. 합성·Canvas입력 시제품과DTO fixture는개발 작업이며 실제실행결과를별도로공유하겠습니다. 본문숫자/키/스타일의최종채택은PO검토와fixture교차검토로기록합니다.
