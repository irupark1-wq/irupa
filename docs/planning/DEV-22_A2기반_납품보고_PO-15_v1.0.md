## 1. 결론

- PO-15 의 A2 기반을 구현했습니다. 범위는 반복 효과의 Day 집계, 상한에 걸린 대화의 중립 기록, 미인지 사건의 자격 고정, 정정 뒤 태그 재구축, 관계 상세의 사실·해석·사유·해결 분리입니다.
- 수용 시험 A2-B01~10 은 **통과 9, 부분 1(B03)** 입니다. B03 은 메커니즘은 통과했습니다. 다만 "한쪽만 모르는 사건"을 실제로 만드는 사건 정의가 아직 없어, 제품 시나리오는 blocked 입니다.
- 전체 자동 시험은 140개 통과입니다(기존 126 + A2 11 + 대사·문구 3).
- 실행 주소: https://neinom.com (이 보고와 같은 커밋). 소스 버전은 문서대장의 DEV-22 행에 커밋 번호를 적습니다.

## 2. 현재 코드와의 차이 (구현 전 → 후)

| 항목 | 구현 전 | 구현 후 (PO-15) |
|---|---|---|
| 반복 제한 단위 | 폰 쌍(순서 없음)×종류, **누적 3회, 날이 바뀌어도 초기화 안 됨** | 방향별 bucket = Day × observer → target × 안정 scope(life-001) × family(light_social). Day 별 3회, 마지막 부여 tick 부터 60 tick 간격(Day 를 넘어 유지) |
| 판정 위치 | 시뮬레이션(life.js)이 쌍 단위로 | 저장 commit 안에서 방향별로(store.js `applyLifeCompletions`, 순수 판정은 repeat.js) |
| 인사·대화 vs 도움 | 같은 한도를 공유 | 인사·대화만 light_social. 도움은 기존 시험 한도 그대로 유지(minor_help 매핑 검수 전, PO-15 §2) |
| 상한에 걸린 완료 | 기록에서 사라짐("제한" 로그만) | `neutral_activity` 에 안정 참조로 남김(물리 action·방향·Day·이유·간격). 원장(EVT-01)·기억·태그에는 넣지 않음 |
| 미인지 완료 | 이 경로 없음 | 완료 시점에 방향별 자격을 동결(quota 소모). 지금 기여 0, 나중에 인지 정정되면 원래 자리에 투영. quota 를 다시 쓰거나 돌려주지 않음 |
| 같은 action 재전송 | tick 단위 중복만 막음 | action 참조로 막음. 기록·기회·기여 추가 0. 이틀 전 action 은 새 완료로 받지 않음(stale) |
| 정정 뒤 태그 | 긍정 여부만 뒤집음 | 원장 replay 로 각 행의 당시 점수 문맥과 긍정 여부를 다시 계산 |
| 관계 상세 | "사건 확인됨 · 사유 · 해결" 한 줄 | 사실 / 해석 / 사유 / 해결 독립 표시(관계창·상세 패널) |
| 생활 일지 | 반복 대화가 모두 따로 | 같은 쌍의 연속 중립 대화를 "오늘 N번"으로 묶음. 실패·하락처럼 보이지 않게 "둘은 잠깐 이야기를 나눴어요" |

## 3. 저장안 (기술안)

| 저장 위치 | 내용 | 크기 관리 |
|---|---|---|
| `life.repeat` | `{schema:1, rule_version, buckets:{"관찰>대상|scope|family": {day, count, last_grant_tick}}}` | 방향 수만큼(폰 3명 + 방문 1명이면 최대 12) |
| `events[].eligibility` | 자격을 받은 사건에 `{family, day, quota_index, since_last_grant, rule_version}` 동결 | 사건과 함께 |
| `life.neutral_activity` | 중립 완료 행 `{action_ref, source_ref, observer, target, tick, day, family, scope, reason, since_last_grant, rule_version}` | 오늘·어제만 행으로(최대 300), 그 이전은 `life.neutral_summary["Day|관찰>대상|family"]` 개수로 압축 |
| `tag_history` 행 | `qualifies:true` 추가(생활 완료로 자격을 얻은 행). positive·context 는 replay 로 다시 계산 | 기존과 같음 |
| `relation_baseline` | 시험 전용 관계 초기값(방향별). 없으면 기존 초기값 | 시험 fixture 에서만 사용 |

- **단일 commit:** tick·bucket·중립 기록·원장·기억·태그가 한 번의 저장으로 함께 반영됩니다. 저장이 실패하면 전부 원래대로입니다(B06).
- **이전 저장본 이전:** 옛 "쌍-talk" 누적 기록을 방향별 bucket 으로 옮깁니다. 마지막 부여 tick 은 유지하고, 그날 횟수는 min(누적, 3) 으로 보수적으로 잡습니다. 그래서 효과를 다시 주는 근거가 되지 않습니다. 옮긴 키는 지웁니다. 새 epoch 를 만들지 않으므로 관계와 기억이 초기화되지 않습니다.
- **되돌리기(rollback):** 이전 빌드로 되돌리면 옛 코드는 새 필드를 무시합니다. 대화 한도를 처음부터 다시 셀 수 있어서, 하루 최대 3회까지 효과가 다시 날 수 있습니다. 운영 전에는 업데이트 직전 "더보기 → 저장 파일 내보내기" 백업으로 되돌리는 절차를 씁니다. 온라인 단계(B-ACCOUNT)에서는 서버 버전으로 막습니다.

## 5. 남은 문제와 확인 필요

1. **사건 개수 상한(기존 제약):** 저장본 사건이 490개를 넘으면 새 완료가 원장에 들어가지 않습니다. 인사 상한으로 하루 최대 18건(6방향×3)과 도움이 쌓이면, 약 20~25 게임일 뒤에 도달합니다. checkpoint 압축안을 A3 또는 B-ACCOUNT 에서 제안합니다.
2. **태그 문맥의 구조 축:** 의존·의무 같은 구조 축은 재구축할 때 당시가 아니라 현재 구조값을 씁니다. 생활에서 구조가 바뀌는 것은 복구로 갈등이 닫히는 경우뿐이라 영향이 작습니다. 정확한 이력이 필요하면 구조 변경 이력을 저장해야 합니다.
3. **접근 재시도 35 tick 의 기준:** 상대가 반응한 tick(수락·거절 시점)입니다. 쌍 양방향에 같이 걸립니다. 효과 자격과는 별개입니다.
4. **도움 한도:** 기존 시험 규칙(쌍 누적 3회, 60 tick)을 그대로 둡니다. minor_help family 매핑 검수 뒤 바꿉니다.
5. **받지 못한 자료:** PO-DEC-002·003, PO-PLAN-001·002, 외주2.zip(김시스템 v1.1·REL-SYS JSON)을 받지 못했습니다. 이번 구현은 PO-15 본문 기준입니다. 보내 주시면 대조표를 만듭니다.
