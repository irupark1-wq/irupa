## 2. 사용자 실사용 보고 반영

### 2.1 일시정지 중에도 폰이 통통 튐 (수정)
- 원인: 폰 그림의 걷기·통통·숨쉬기 움직임은 화면 장식(CSS)이라 생활 정지와 연결돼 있지 않았음.
- 수정: 일시정지면 장면에 `life-paused` 표시를 붙여 폰 움직임을 모두 멈추고, 걷던 폰의 기울기도 0으로 둠. 재개하면 다시 움직임.
- 확인: 정지 전 waddle/bob → 정지 중 none → 재개 후 waddle/bob (브라우저 측정). 증거 `docs/evidence/rooms/room11-pc-paused-still.jpg`.

### 2.2 Google 계정에서 "비밀번호 정하기" 실패 (원인 조사 중)
- 화면에 일반 실패 문구만 나와 원인을 알 수 없었음.
- 보완: 일반 실패일 때 서버가 주는 **고정 오류 코드와 상태 번호만** 괄호로 함께 보여 줌(예: "(오류 코드: unexpected_failure · 500)"). 서버의 자유 문장·이메일·토큰은 보여 주지 않음.
- 로그인 세션이 끊긴 경우(session_not_found 등)는 "로그인이 끝났어요. 다시 로그인해 주세요"로 안내.
- 재시도 결과(사용자): `current_password_required · 400`. Supabase Auth 는 **이미 비밀번호가 있는 계정**이면 새 비밀번호를 정할 때 지금 비밀번호를 함께 요구한다(서버 설정 `UpdatePasswordRequireCurrentPassword`, 재설정 메일 세션은 면제). 이 Google 계정에는 이전 이메일 가입 등으로 비밀번호가 이미 있었던 것으로 보임.
- 수정: 서버가 이 코드를 주면 "지금 비밀번호" 칸을 보이고 버튼을 "비밀번호 바꾸기"로 바꿈. 지금 비밀번호와 함께 다시 보내면 바뀜. 틀리면 `current_password_mismatch` → "지금 비밀번호가 맞지 않아요" + 재설정 안내. 지금 비밀번호를 모르면 로그아웃 후 '비밀번호 재설정'(메일 링크 세션은 지금 비밀번호 면제).
- 재시험(사용자, neinom.com): 지금 비밀번호와 함께 **비밀번호 바꾸기 성공**. AUTH12 ②(이미 비밀번호가 있던 Google 로그인 계정의 비밀번호 바꾸기) 통과. ①③④는 미실행.

### 2.3 AUTH07 두 기기 충돌 (실기 통과)
- 사용자 실기: 다른 기기가 먼저 저장한 뒤 이 기기에서 저장 → "다른 기기에서 이 월드를 먼저 저장했어요. 계정 저장본은 그대로예요" + [계정 월드 불러오기] [이 월드를 새 월드로 저장] [취소]. 저장 위치 줄 "계정 저장 충돌 · 기존 저장본 유지". 증거 `docs/evidence/auth/auth07-conflict-real.webp`.
- 보완: 같은 충돌 문장이 위 안내와 아래 선택 칸에 두 번 나와, 아래 선택 칸에 한 번만 나오게 고침.
